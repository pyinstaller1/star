

(1) 기밀성 (Confidentiality)
비인가된 접근, 지능적인 차단으로부터 정보 보호
소유자 인가를 받은 자만 접근
정보 접근, 공개 관련 합법적 제한조건 준수
개인 프라이버시, 소유권에 대한 정보 보호 수단
군대 민감 정보, 산업체 경쟁자, 은행 고객 계좌
비인가 정보 공개 금지
기밀성 상실 시, 정보 부정 공개
조직은 기밀성 위협 대응(보관, 전송)
접근 통제, 암호화: 기밀성 보장




(2) 무결성 (Integrity)
정보, 정보처리 방법의 완전성, 정확성, 정밀성
수정 불허 (최초 내용 유지)
필요시, 인가된 사람, 권한, 절차, 방법으로만 수정

은행 고객 입출금 시, 계좌 금액 변경
전력차단과 같은 시스템 중단으로 변경
(항상 악의적 행동 아님)

무결성 상실 시, 무단 수정, 파괴
물리적 통제, 접근통제: 부적절한 정보 수정, 파괴 방지



(3) 가용성 (Availability)
인가된 자만 변하는 정보를 언제든지 사용 가능
합법적 사용자에게 지체 없이 동작, 적합한 서비스
시간성, 신뢰성
가용성 상실 시, 사용, 접근 불가
백업, 중복성 유지, 물리적 위험 요소로부터의 보호


 

(4) 인증성
정상적, 합법적 활동인지 보장
정보를 교환해서 실체 식별
접근 객체의 자격, 내용 검증
등록, 허가받은 네트워크 사용자인지 확인
성명, 패스워드를 목록과 대조 => 지정된 범위만 접속 허용
메시지 인증 코드, 전자서명: 전송된 메시지가 위조, 변조가 아닌지 확인




(5) 책임 추적성 (Accountability)
누가 언제 어떤 목적, 방법으로 사용했는지 추적
한 개체의 행동 추적
보안 책임이 있는 곳까지 추적(완벽 안전은 불가)
활동상황 기록, 포렌식 분석 =>침해 추적, 전송 분쟁 해결

(6) 신뢰성 (Reliability)
오류 없이 수행, 결과를 얻는 환경 유지 => 공급자 신뢰


보안 3대 목표: 기밀성, 무결성, 가용성

부인방지: 행위, 이벤트 증명 => 부인 방지
   대칭키: 제3신뢰기관의 보조 필요
   비대칭: 전자서명

포렌식: 휴대폰, PC, 서버의 데이터 수집 => 사법기관에 증거물 제출

데이터 기밀성: 부적합 사용자에게 노출 방지
프라이버시: 개인 정보 수집, 저장, 열람 대상 통제
데이터 무결성: 규정, 허가 정보만 변경
시스템 무결성: 시스템 기능 미손상, 모두 구현 상태로 수행


















강제적 접근 제어
① 장점
보안 중요 시스템 적합
모든 데이터에 보안 레이블, 보안 정책 확인 => 성능이 안좋고 구현이 어려움



임의적 접근 제어 (DAC)
주체 신원으로 객체 접근 제한
주체 ID만 근거: 하나의 주체 대 객체 단위로 권한 설정

접근 주체를 식별, 골라서 객체 접근 권한 제공 => '임의적'
소유자가 보안 관리자 개입 없이 자율적으로 접근권한 부여
소유주가 접근 주체와 객체 통제

사용자, 데이터 사이의 관계로 통제
주체, 객체 단위로 접근 제한
접근 권한 관리 편리 (DBMS, OS의 파일 시스템)
최초로 객체에 배포된 임의 접근 통제 관계는 복사된 객체로 전파 불가

중앙집중 관리가 힘들어서 엄격한 접근 제어가 어렵다.
권한 부여를 식별자에만 의존
데이터 의미 지식이 없음: 데이터에 의한 통제 불가

3) ACL (Access Control List)
데이터에 대한 사용자의 접근 권한이 리스트 형태(ACL)


(4) 역할기반 접근 제어(RBAC : Role-Based Access Control)
권한을 사람이 아닌 직책(역할)에 부여
사용자가 적절한 역할에 할당
비임의적 접근 제어

MAC처럼 객체의 비밀 등급 부여 가능

임의의 사용자에게 역할 부여하므로 임의적이지만,
조직 규칙으로 역할, 객체의 관계 정립(비임의적)

1사용자 여러 역할, 1역할 여러 사용자


역할(Role)
조직의 보안 정책, 비즈니스 규칙으로 만든 주체가 객체에 접근


역할기반 접근 제어(RBAC)
주체의 행위, 역할로 접근 권한 결정
조직의 업무 기능에 따라 역할과 권한을 생성
역할 권한의 최소한 접근
업무 변경, 책임에 따라 조직 변경 없이 역할 변경

Authorization Creep (권한 확산)
교원 변경 시, 새로운 권한을 부여받고 원래 권한 미삭제
=> 불필요한 권한을 많이 갖는 권한 확대





2) 역할기반 접근 제어의 장점

① 권한관리: 사용자의 권한 지정을 논리적, 독립적으로 할당·회수 가능, 보안 관리 단순
② 계층적인 역할 분배: 역할의 계층으로 상속 가능, 권한 관리 용이
③ 최소권한 정책 : 사용자에게 최소 권한만 부여, 권한 남용 방지, 해킹 방어
④ 임무의 분리 : 오류 발생 가능 권한의 사용자의 존재 방지
⑤ 객체 분류 : 수행 업무로 사용자 분류, 권한 제한





속성 기반 접근제어(ABAC)
1. 주체 속성
주체: 정보가 객체 사이를 이동, 시스템 상태를 변경하게 하는 능동적 존재
       (사용자, 응용 프로그램, 프로세스, 디바이스)
       주체 정의 속성과 연관 (신원, 이름, 조직, 직책)

2. 객체 속성
객체: 정보를 포함하거나 받는 수동적 자원(파일, 레코드, 테이블)
       메타데이터에서 객체 속성 추출

3. 환경 속성
날짜, 시간, 해킹 동향, 네트워크 한계
운영, 기술, 상황, 정보 접근이 발생하는 환경
주체, 자원과 연결짓지 않지만, 접근제어 적용에 관련


4. ABAC
주체, 객체의 속성, 공식 관계, 환경에서 주체-객체 속성 조합에 허가된 동작 규칙 평가




5. ABAC 시스템
DAC, RBAC, MAC 실행
접근제어 규칙을 만족하는 무제한의 조합 허가



래티스 기반 접근 제어
역할기반
주체가 접근 가능한 객체의 경계부터 하위 경계로 설정
주체가 객체에 접근 가능한 경계 지정





보안 모델
벨 라파둘라 모델
다중 사용자 OS를 설계하면서 개발 (벨, 라파둘라)
높은 등급 => 낮은 등급의 하향 흐름 방지
기밀성 O 무결성 X 가용성 X


2) 벨 라파둘라 모델의 규칙

높은 등급 읽을 수 없고, 낮은 등급 쓸 수 없다.

① Simple Security Property (ss-property : ss 속성)
ㄱ NRU(No Read-Up) : 높은 등급 읽을 수 없다.
ㄴ 접근 모드가 읽기, 쓰기
주체 s의 등급이 객체 o 보다 높으면
C(o) ≤ C(s)일 때만 주체 s는 객체 o 읽기 권한





ss-속성 만족
상향 읽기 금지(No Read Up)

 


② -property (-속성)

ㄱ NWD(No Write-Down) : 낮은 등급의 데이터에 쓸 수 없다.
ㄴ 접근 모드 a가 추가, 쓰기
     주체 s의 등급이 객체 o보다 높으면 -속성 만족
     객체 o의 읽기 권한이 있는 주체 s는
     C(o) ≤ C(s)일 때만 객체 o 쓰기 권한









임의적 보안 속성 (ds-property : ds-속성)
임의적 접근 제어
이름이 부여된 사용자의 식별이 부여된 객체에 접근권한을 통제

접근 허용을 소지한 주체는 다른 주체에게 접근허용 전달 가능

BLP 모델에서 접근 모드가
주체, 객체의 접근 통제 매트릭스에 포함되어 있으면 ds-속성 만족



(2) 비바(Biba) 모델

주체에 의한 객체 접근 항목으로 무결성
비인가자의 데이터 변경 방지
BLP 모델의 비밀 등급에 대응하는 무결성 등급


2) 비바 모델의 규칙
① 단순 무결성 속성 (Simple Integrity Property : si-속성)

① NRD(No Read Down) : 주체는 낮은 무결성 객체를 읽을 수 없다.
② 낮은 무결성 데이터를 읽으면 주체 오염


② -무결성 속성 (-Integrity Property : *i-속성)
① NWU (No Write Up, 상향 쓰기 금지) : 주체는 높은 무결성 객체에 쓸 수 없다.
② 낮은 무결성 주체가 높은 무결성 데이터 오염 방지


내부 일관성 유지
① 내부 일관성
시스템의 명령이 생성, 시스템 내부 상태의 속성들이 일관되어야 한다.

② 외부 일관성
현실에 대한 시스템 내부 상태의 관계 존중
시스템 외부의 수단(감사)로 검증


클라크-윌슨(Clark-Wilson) 모델
주체는 객체에 직접 접근 X, 중재 프로그램으로 접근
프로그램은 객체에 제한된 권한 보유, 주체의 능력 제한
중재 프로그램을 올바르게 작성 => 객체의 무결성 보장


중대한 기능을 둘 이상으로 분리, 서로 다른 주체가 각 부분을 수행
권한 있는 주체의 객체 무허가 수정 방지, 객체의 무결성 보장
감사로 객체 변경, 접근 검사
시스템 외부의 입력값 검증


만리장성 모델 (Brewer–Nash)
이해 충돌 회사 간의 정보흐름 방지 (비즈니스 정보보호)










③ 강한 무결성 속성

① No Read Down + No Write Up + 추가 제약
② 주체는 낮은 무결성 객체를 읽을 수 없고, 높은 무결성 객체에 쓸 수도 없으며
    동일 등급끼리만 읽기/쓰기 가능

(3) 클라크-윌슨 (Clark-Wilson) 모델
무결성
무결성 3목표: 비인가자의 데이터 변경 방지, 내외부 일관성, 합법 사람의 불법 수정 방지


2) 클라크-윌슨(Clark-Wilson) 모델의 구성 요소
① 잘 구성된 트랜잭션 : 모든 트랜잭션 구조화, 안전한 예측가능 방식으로 기록
② 직무 분리: 한 사람이 아닌 여러 사람이 나누어 부분별 관리 => 무결성 침해 방지
③ 주체의 응용 프로그램을 통한 데이터 접근 :
사용자의 직접 객체 접근 금지, 응용 프로그램 사용 강제


3) 클라크-윌슨(Clark-Wilson) 모델의 전제 조건
주체 식별, 인증 가능
객체는 제한된 프로그램으로만 조작
주체는 제한된 프로그램으로만 수행
감사 기록 유지
정확한 운영 보증























TCP/IP 계층별 주소

 링크 주소, 이더넷 네트워크 인터페이스 카드(NIC) 바이트(48비트) 주소

③ 포트 주소
인터넷 통신의 목적은 한 프로세스가 다른 프로세스와 통신

(1) OSI 7계층
1) 1계층 물리 계층

기계적, 전기적, 기능적, 절차적 특성 정의
비트 스트림을 물리적 매체로 전송


2) 2계층 데이터 링크 계층
물리 링크로 동기화, 에러제어, 흐름제어 => 프레임 전송
16진수 12자리의 MAC 주소로 객체 간 통신에 사용(MAC 주소는 고유)


3) 3계층 네트워크 계층
IP 주소 체계로 사용, 경로 설정, 패킷 전송

4) 4계층 전송 계층
① 종단 간의 신뢰성 있고, 투명한 데이터 전송
② 에러제어, 흐름제어, 다중화
포트: 응용 프로그램 간 통신




5) 5계층 세션 계층

① 통신 중 동기화 유지, 데이터 교환 관리
② 전송 계층의 종단 간 논리 연결에 추가 서비스 제공 => 효과적인 정보 교환


6) 6계층 표현 계층
데이터 구조를 통일된 형식으로 표현, 데이터 압축, 암호화

7) 7계층 응용 프로그램 계층
① 사용자나 응용 프로그램 간의 데이터 교환
② HTTP, FTP, 터미널 서비스, 메일 프로그램, 디렉터리 서비스












(2) TCP/IP 인터넷 계층 구조
1) 네트워크 접근 계층

① 운영체제의 네트워크 카드와 디바이스 드라이버 등과 같이 하드웨어적인 요소와 관련된 모든 것을 지원하는 계층이다.

② 송신측 단말기는 인터넷 계층으로부터 전달받은 패킷에 물리적 주소인 MAC 주소 정보를 갖는 헤더를 추가하여 프레임을 만들어 전달한다.

③ 대표 프로토콜로는 이더넷(Ethernet), IEEE 802.1X, MAC/LLC, SLIP, PPP 등이 있다.

2) 인터넷 계층

① IP는 네트워크의 주소 체계를 관리하며, 데이터그램을 정의하고 전송을 위한 경로 설정을 담당한다.

② 대표 프로토콜로는 IP, ARP, RARP, ICMP, IGMP 등이 있다.

3) 전송 계층

① 네트워크 양단의 송수신 호스트 사이의 신뢰성 있는 전송 기능을 제공한다.

② 시스템의 논리 주소와 포트를 가지므로 각 상위 계층의 프로세스를 연결한다.

③ 대표 프로토콜로는 TCP와 UDP가 사용된다.

4) 응용 계층

① 사용자에게 서비스를 제공해준다.

② 대표 프로토콜로는 FTP(File Transfer Protocol), SMTP(Simple Mail Transfer Protocol), SNMP(Simple Network Management Protocol) 등이 있다.






세션(Session)의 정의
두 대의 컴퓨터(또는 프로세스)가 서로 연결되어 데이터를 주고받는 하나의 시작부터 끝까지의 논리적인 통신 연결 단위
네트워크상에서 두 컴퓨터가 대화를 나누기 위해 연결을 맺고, 대화를 이어가고, 대화를 마칠 때까지의 전체적인 대화 기간(시간 참)을 의미한다.
활성화된 프로세스 간 연결이다.





(3) IP(Internet Protocol)
1번. 인터넷 계층에 해당하는 프로토콜이다.
2번. 송신측과 수신측 사이의 경로를 선택하여 전달을 해주는 라우팅(routing) 기능을 갖는다.
3번. 라우터(router)는 최단 거리를 찾는 알고리즘을 이용하여 전송 비용이 적은 최적의 경로를 찾는다.
4번. 네트워크 상의 전송 비용은 보통 전송 속도를 의미하는데, 경우에 따라 단순히 거쳐야 하는 라우터 개수(hop count)를 의미할 때도 있다.
5번. 인터넷을 연결하는 각각의 라우터들의 IP주소와 전송 비용 정보를 라우팅 테이블(routing table)에 저장하며 이 테이블은 라우터에 저장된다.

[공인 IP 주소(Public IP Address)]
IANA(Internet Assigned Numbers Authority)에 의해 할당받은 IP 주소
인터넷을 통해 외부에서도 바로 연결 시도가 가능한 주소이다.

[사설 IP 주소(Private IP Address)]
사내 네트워크 내에서만 사용될 수 있는 주소
클래스 A : 10.0.0.0 ~ 10.255.255.255
클래스 B : 172.16.0.0 ~ 172.31.255.255
클래스 C : 192.168.0.0 ~ 192.168.255.255






[IPv4 헤더 구성요소]
헤더길이 : 데이터그램 헤더의 전체 길이를 4바이트 단위로 나타낸다.
서비스 유형 : 라우터가 처리해야 하는 데이터그램에 대한 규정을 나타낸다.
전체길이 : IP헤더와 데이터그램의 길이를 바이트 단위로 나타낸다.
식별 : 각 데이터그램마다 고유하게 설정되는 데이터그램의 번호이다.
플래그 : 패킷의 분할을 제어한다.
단편 오프셋 : 단편화된 패킷을 재결합할 때 플래그 필드와 식별 필드와 결합되어 사용된다.
라이프 타임 : 패킷이 네트워크 상에 생존할 수 있는 시간을 의미하며 데이터그램이 통과하는 최대 라우터 수를 제어한다. 라우터를 통과할 때마다 1씩 감소한다.
프로토콜 : IP 계층의 서비스를 사용하는 상위 계층의 프로토콜의 종류를 정의한다.
헤더 검사합 : 전송 중 발생하는 헤더 부분의 에러를 검사한다.






URL (Uniform Resource Locator)

웹에서 페이지나 파일을 access할 때 사용되는 메서드로 일반적으로 http://를 사용한다.
ftp://, file:// 등의 다른 프로토콜을 사용할 수도 있다.

연결할 파일의 실제 이름이다.

(1) 정보보호 개념

정보(information)
① 정보는 데이터와 구별하여 어떤 목적에 필요한 도움을 주는 사실이나 지식을 말한다.
② 데이터는 단순한 관찰이나 측정을 통해서 수집된 사실이나 값을 말한다.
③ 데이터와 구별되어 '정보(information)'는 어떤 의사결정에 도움을 주기 위해 축적된 형태의 지식을 의미한다.

정보의 속성
효과성(Effectiveness): 비즈니스프로세스에 관련성 있고 타당하고 사용 가능한 정보여야 한다는 것
효율성(Efficiency): 최적의(가장 생산적이고 경제적인) 자원 활용을 통해서 정보를 제공하는 것
기밀성(Confidentiality): 민감한 정보를 불법적인 유출로부터 보호하는 것
무결성(Integrity): 정보의 정확성 및 무결성, 일관성
가용성(Availability): 필요한 때에(적시에) 정보가 사용 가능하다는 것
준거성(Compliance): 사업에 적용될 수 있는 법률, 규정, 계약사항 등과 같이 외부적으로 부과된 경영 기준, 그리고 내부 정책 등을 준수하는 것
신뢰성(Reliability): 경영진이 조직을 운영하고, 주주에 대한 책임(수탁책임)을 수행하기 위해 필요한 적절한 정보, 즉 타당하고 믿을 수 있는 정보를 제공하는 것

정보보호의 발전
50년대 후반~80년대 초반: 기술 중심 정보보호(TCSEC, ITSEC, CC)
80년대 중반~90년대 중반: 관리 중심 정보보호(체크리스트, 모범사례)
90년대 후반~: 정보보호 조직/체계 중심(BS7799, ISO2700, ISMS, PIMS, PIPEDA)






정보자산 분류표

정보 유형 - 설명

데이터 - 전산화된 정보로 문서파일, 데이터파일(개인정보, 산업기밀, 영업비밀 등)로 분류
소프트웨어 - 패키지 소프트웨어, 시스템 소프트웨어, 응용프로그램 등
서버 - 공용자원을 갖고 여러 사용자에게 서비스를 제공하는 시스템
시설 - 건물, 사무실, 데이터 센터 등의 물리적 시설
인력 - 소유자, 관리자, 사용자, 운영자, 개발자 등 정보시스템 관련 인력
무형 자산 - 기업이미지, 업무프로세스, 특허 및 지적재산권 등



정보보호의 정의
1번. 한국정보통신기술협회(TTA, Telecommunications Technology Association)의 정의
정보보호(information security)란 '정보의 수집/가공/저장/검색/송신/수신 중에 정보의 훼손/변조/유출 등을 방지하기 위한 관리적/기술적 수단, 또는 그러한 수단으로 이루어지는 행위'를 말한다.

2번. "정보통신망 이용 촉진 및 정보보호에 관한 법률"의 정의
정보보호는 '정보의 수집/가공/저장/검색/송신/수신 중에 정보의 훼손/변조/유출 등을 방지하기 위한 관리적/기술적 수단, 또는 그러한 수단으로 이루어지는 행위, 즉 우연히 혹은 의도적으로 허가 받지 않은 정보의 누출, 전송, 수정, 파괴 등으로부터 보호하는 것'으로 정의하고 있다.




정보보호의 핵심 원칙

정보보호
정보의 기밀성, 무결성, 가용성의 유지

기밀성: 접근을 허가받은 자만이 정보에 액세스할 수 있도록 확실히 할 것
무결성: 정보 및 처리방법이 정확하고 완전하도록 보호할 것
가용성: 허가된 이용자가 필요시에 정보 및 관련 자산에 액세스할 수 있도록 할 것

정보보호의 중요성 및 필요성
① 대국민 서비스의 IT 활용이 증가하면서 정보보호는 정부의 신뢰성·안전성을 보장하는 핵심요소이며, 사이버 공간이 제2의 생활공간으로 인식되면서 정보보호는 국민의 인권 및 자산을 보호하는 사회안전망 역할을 하게 되었다.
② 정보보호는 경제적 손익과 직결되는 문제로 IT기술을 기반으로 하는 국민의 삶에 있어서도 정보보호가 이루어지지 않은 경우 사회 혼란과 기업의 신뢰가치가 저하하고, 기업 신뢰도, 주가 하락 및 막대한 손해배상액으로 인한 기업의 존립자체를 위협하는 등 사회적인 손실이 발생하고 있다.
③ 웜·바이러스 등을 통한 정보통신망 침해행위는 개인정보 침해 뿐 아니라 인터넷을 기반으로 한 모든 사회·경제활동을 마비시키며, 공공·금융·상거래 등 국민 실생활과 직결된 대부분의 분야가 인터넷과 개인정보를 매개로 이루어지고 있어, 안전한 정보보호가 이루어지지 않을 경우 국가적 피해, 사회적 혼란 등 국가·기업·국민 모두의 손실로 이어진다.
④ 정보보호는 국가만의 문제가 아니라 기업, 개인 등 정보시스템을 소유 운영하는 기관과 기업, 개인은 물론 정보시스템을 이용하는 모든 사람이 함께 노력해야 할 문제이다.


(2) 정보보호 관리체계(ISMS, Information Security Management System) 개념

위험 관리
① 정보보호 관리체계(ISMS)는 경영과 IT영역의 중요한 위험 관리 활동의 하나이다.
② 위험은 일반적으로 나쁜 결과의 발생 가능성이라는 의미로 사용되지만 보다 확대 해석하여 좋은 결과와 나쁜 결과 쌍방의 발생 가능성을 포함한 '불확실성'으로 보기도 한다.

관리체계(Management System)
① 정보보호 관리체계란 Information Security Management System의 약칭으로, 정보보호에 관한 경영시스템이며 조직의 의사결정시스템, 내부통제시스템으로 위험 관리와 동일한 개념이다.
② 일반적으로 PDCA(Plan-Do-Check-Act) 사이클 기반으로 실행된다.

프로세스 접근방법
① 프로세스 접근방법에서는 입력을 출력으로 변환하기 위해 경영자원을 이용하여 운영·관리되는 모든 활동을 프로세스로 본다.
② 조직 내에서 프로세스를 명확히 하고 그 상호 관계를 파악하여 운영·관리하는 동시에 일련의 프로세스를 시스템으로서 적용하는 것은 '프로세스 접근방법'이라 한다. 이러한 순환적인 구조형태를 데밍의 품질관리 사이클(Deming's Quality Management Cycle) 또는 PDCA 사이클이라고도 한다.
③ Plan -> Do -> Check -> Act, 즉 계획, 실행, 점검, 개선 활동과 이러한 것들의 피드백(feedback)이라는 선순환구조를 이루어야 한다.

정보보호 관리체계
자신에 대한 보호를 체계적으로 수행하기 위해 자산을 식별한 후 이 자산이 어떠한 형태의 위협으로부터 어느 정도 위험에 치해있는지를 측정하여 위험수준을 적절한 수준으로 낮추기 위해 보안대책을 선정하는 활동이 필요하다.


정량적 위험분석
1번. 수학공식 접근법 : 위험 발생 빈도를 추정하는 계산식을 통해 위험을 계량하여 분석한다.
2번. 과거자료 분석법 : 과거 지표를 통해 위험 발생가능성을 예측한다.
3번. 확률분포법 : 위험에 대해 확률적 편차를 이용해 최저, 보통, 최고의 위험도를 분석한다.
4번. 예상손실
단일 예상손실(SLE) : 자산가치 × 노출계수
연간 예상손실(ALE) : 단일예상손실 × 연간발생률

정성적 위험분석
1번. 델파이법 : 전문가 집단으로 구성된 위험분석팀의 위험분석 및 평가를 통해 여러 가능성을 전제로 위협과 취약성에 대한 의견수렴을 통해 분석한다.
2번. 시나리오법 : 어떤 사건이 예상대로 발생하지 않는다는 사실에 근거하여 주어진 조건하에 발생 가능한 위험에 따른 결과를 예측한다.
3번. 순위결정법 : 비교우위 순위 결정표를 이용하여 위험 항목들의 순위를 결정한다.

위험관리 프로세스 절차
1번. 기업 내에 잠재돼 있는 위험을 파악
2번. 위험빈도, 크기에 따른 영향분석, 위험관리법 검토
3번. 최적의 위험관리기법 선택
4번. 위험관리기법 적용
5번. 적용 결과에 대한 모니터링

[보충학습] 위험분석과 위험관리의 비교

위험분석
보안관리를 수행하기 위한 필수적인 과정으로 시스템의 위험을 평가하고 비용 대비 효과면에서 조직에 가장 적합한 대응책을 제시하는 것이다. 위험분석의 핵심 요소에는 자산, 위협, 취약성, 보호대책, 위험 등이 포함된다.

위험관리
시스템의 위험을 평가하고 그 결과를 바탕으로 비용 및 효과와 비교하여 조직의 보안 방침과 목적에 일치하는 구현 전략과 시스템 보안 방침을 도출하는 일련의 과정이다. 위험관리는 조직의 환경과 능력에 맞추어 대응책을 운영하도록 지원한다.
