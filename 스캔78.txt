03 컴퓨터의 분류

1. 사용 데이터에 따른 분류

(1) 디지털 컴퓨터: 2진수로 부호화, 사칙, 논리연산
                             정확도가 아날로그보다 높다.

(2) 아날로그 컴퓨터: 아날로그 신호를 데이터로 이용(연속적인 물리량)
                      입력이 신속, 즉각적인 반응 => 제어용으로 사용

(3) 하이브리드 컴퓨터: 디지털과 아날로그 컴퓨터의 장점을 조합

2. 사용 목적에 따른 분류

(1) 범용 컴퓨터 : 광범위한 분야에 널리 사용
(2) 전용 컴퓨터 : 특수한 목적으로 사용

3. 처리 능력에 따른 분류

(1) 마이크로 컴퓨터
개인용 컴퓨터, 저렴하고 작다.
워드 길이로 구분(8비트, 16비트, 64비트)

(2) 미니 컴퓨터/메인프레임 컴퓨터
다수 사용자용 서버 (다중 작업)
중형 및 대형 컴퓨터

(3) 슈퍼 컴퓨터: 초대형, 초고속, 비싸다.
                강력한 병렬 처리 소프트웨어




진공관 (10⁻³ sec): 통계, 군사용, 많은 비용, 짧은 수명, 큰 부피, 많은 전력소모
트랜지스터 (10⁻⁶ sec): 생산관리, 신뢰성 증대, 전력 소모 감소, 기억용량 증대, OS
집적회로 (10⁻⁹ sec): MIS, 시분할 처리, 주변장치 고속화, 각 장치의 호환성
고밀도 집적회로(10⁻¹² sec): 경영 정보, 사무자동화, PC, DB, 마이크로프로세서
초고밀도 집적회로(10⁻¹⁵ sec): 인공지능 퍼지이론, 추론, 음성인식
                                  전문가 시스템, 고도능력의 단말기, 대규모 네트워크





04 정보처리 시스템의 분류

1. 일괄처리

① 입력 자료를 일정기간 또는 일정량을 모아서 한번에 처리
CPU 유휴시간이 많다. (CPU와 I/O장치의 속도차이)


CPU 1개 - 주기억장치 1개 - 프로그램 1개 - 사용자 1명

2. 다중프로그래밍 시스템
CPU 효율 극대화
1 CPU로 여러 사용자 프로그램이 동시에 실행되는 것처럼 처리
한 프로그램이 입출력 장치 사용,
다른 프로그램이 CPU 사용

CPU 1개 - 주기억장치 1개 - 프로그램 n개 - 사용자 1명

3. 실시간 시스템
자료가 발생할 때마다 즉시 처리

4. 시분할 시스템
다중프로그래밍의 논리적 확장
사용자들에게 CPU를 일정시간(Time Slice) 할당
주어진 시간동안 컴퓨터와 대화식으로 프로그램 수행
다수의 단말 사용자가 혼자 주컴퓨터를 사용하는 것 같이 처리


CPU 1개 - 주기억장치 1개 - 프로그램 n개 - 사용자 n명






5. 다중처리 시스템
여러 CPU, 기억장치 1개, 여러 프로그램
주기억장치 공유(강결합)

CPU n개 - 주기억장치 1개 - 프로그램 n개 - 사용자 n명





6. 분산처리 시스템
대형 컴퓨터의 기능을 여러 지역의 컴퓨터에 분산
=> 통신망으로 교환, 처리
각 CPU는 기억장치 보유(약결합)

CPU n개 - 주기억장치 n개 - 프로그램 n개 - 사용자 n명

컴퓨터 종류에 따라 2바이트, 4바이트, 8바이트
CPU가 램에서 1번에 읽는 단위

• Half Word : 2바이트
• Full Word : 4바이트
• Double Word : 8바이트

표준 BCD 코드
6비트(zone : 2bit, digit : 4bit)
2⁶(=64)개의 문자 표현
초기 컴퓨터에서 사용, (대문자, 소문자 구별 X)
10진수 입출력이 간편



아스키 코드
7비트(zone : 3bit, digit : 4bit)
2⁷(=128)개의 문자 표현
데이터 통신용, 마이크로컴퓨터



확장 BCD 코드(EBCDIC 코드)
8비트(zone : 4bit, digit : 4bit)
2⁸(=256)개의 문자 표현
범용 컴퓨터

유니코드(Uni-Code)
16비트, 2¹⁶(65,536)개, 모든 언어의 문자 표현
OS, 프로그램, 언어에 관계없이 문자마다 고유 코드값 제공




① 8421코드 : 4비트 BCD 코드, 10진수 한 자리를 4비트로 표현, 보수 변환이 어렵다.
② 3초과 코드: 8421코드에 3(0011)을 더한 코드, 자기보수, 비가중치 코드
③ Gray 코드 : 연산에는 부적당, A/D변환기나 입출력장치 코드, 기계 제어
                입력 코드로 사용하면 에러 감소 (1 비트만으로 새로운 코드 개발)



④ 패리티 비트 : 1 패리티 비트를 데이터에 추가, 1 에러만 검출

㉠ 짝수 패리티(우수 : even parity) : 1의 개수가 짝수
㉡ 홀수 패리티(기수 : odd parity) : 1의 개수가 홀수
㉢ CRC 패리티 방식 : 패리티 비트(수평 에러 검사), 패리티 워드(수직 에러 검사) => 에러 수정



⑤ 해밍코드 : 에러 검출, 수정  => 데이터 비트가 많아지면 패리티 비트도 증가


XOR: 입력이 다르면 1

고정소수점 연산

① 2진 정수 데이터 표현


② 표현 범위(Half Word, Full Word)는 작지만 빠르다.

③ 음수: 부호와 절대치, 1의 보수, 2의 보수 표현 방식

④ 양수: 부호와 절대치 방식만 사용, 보수 X






부동소수점 연산

(1) 특징

① 2진 실수 데이터 표현, 연산
② Full Word(32bit), Double Word(64bit)
③ 부호부, 지수부(소수점 위치), 가수부(유효숫자)
④ 부호: 최상위 비트로 양수는 0, 음수는 1
⑤ 소수점: 지수부와 가수부 사이로 간주
⑥ 정규화된 값 중 1은 저장 X (잠복비트)
⑦ 고정소수점보다 복잡하고 실행시간이 많이 걸리나 아주 큰 수, 작은 수 표현 가능
⑧ 정규화(Normalization) 필요: 지수부와 가수부로 분리
⑨ 음수 형태의 지수를 양수로 표현 => 지수에 바이어스(Bias)를 더한다.



01 논리 게이트

모든 정보를 0, 1로 표현
2진 정보를 게이트(논리회로)에서 처리
게이트의 동작은 부울 대수로 표현
게이트의 입력과 출력은 진리표로 표현


AND 게이트
① 논리곱 수행
② 모든 입력이 1인 경우에만 1 출력, 나머지는 0 출력


OR 게이트
① 논리합 수행
② 하나 이상의 입력이 1이면 출력 1


NOT 게이트

① 입력 1개, 출력 1개, 논리 부정
② 입력값의 반대를 출력


NAND 게이트
① AND 와 NOT 결합
② AND 결과를 반대로 출력


NOR 게이트
① OR 과 NOT 결합
② 하나 이상의 입력이 1이면 0 출력


XOR 게이트

① Exclusive OR, 배타적 OR
② 여러 입력 중 1의 개수가 홀수이면 1 출력
③ 2 입력 중 하나만 1이면 1 출력
   둘 다 1이거나 0이면 0 출력


XNOR 게이트

① Exclusive NOR, 배타적 NOR이라고 한다.
② 여러 입력 중 1의 개수가 짝수이면 1 출력
③ 2 입력 모두 1 또는 0으로 입력되면 1 출력, 두 입력이 다르면 0 출력


범용 논리 게이트

① NAND 게이트와 NOR 게이트는 모든 게이트를 구성 가능
② 유니버셜 게이트(universal gate)


조합논리회로
출력이 입력에 의해서 결정


(1) 반가산기(Half Adder)

① 2입력과 2출력 => 합(sum), 자리올림(carry)
② 합(sum): 두 입력의 XOR
③ 자리올림(carry): 두 입력의 AND


(2) 전가산기(Full Adder)

① 올라온 Carry 고려 => 3입력변수, 출력은 Sum과 Carry
② Sum = A'BC + A'BC' + AB'C' + ABC = A⊕B⊕C
③ Carry = A'BC + AB'C + ABC' + ABC = C(A⊕B) + AB
④ 2개의 반가산기와 1개의 OR회로




병렬 2진 가감산기

n비트를 더할 경우 n개의 전가산기 필요


가산기에 게이트를 추가해 부호 신호로 뺄셈 (별도의 감산기 X)


XOR 입력 부호값이 0이면 XOR 의 B에 변환이 없으므로 덧셈 수행
             부호값이 1이면 XOR 의 B의 보수 전달

다음 병렬가감산기는 M이 0일 때 A+B 수행, M이 1일 때 A-B 수행



(3) Decoder(해독기)

① n비트의 2진 코드를 최대 2ⁿ개의 정보로 바꿔주는 조합 논리회로
② 2ⁿ개의 출력 중 한 개만 1, 나머지는 0


(4) Encoder(부호기)

① 외부 입력 신호를 부호화된 신호로 변환, 컴퓨터 내부로 들어보낸다.
② 2ⁿ개의 입력신호로부터 n개의 출력 신호를 만든다.
③ 2ⁿ개의 비트 중 오직 한 비트만이 1을 갖고, 나머지 비트는 0이 되는 입력신호 생성
④ 활성화된 1이 몇 번째 비트인가를 파악 => 2진 정보 출력

(5) 멀티플렉서
① 여러 입력 중 하나만 출력에 전달해주는 조합 논리회로
② 여러 회로가 단일 회선을 공동 이용, 신호 전송



(6) 디멀티플렉서
여러 입력 신호 중 하나를 골라 출력




순서논리회로

① 플립플롭(2진 기억소자)와 논리게이트로 구성

② 출력: 외부입력과 플립플롭의 현재 상태로 결정
       출력의 일부가 입력으로 피드백되어 출력에 영향

③ 2진 자료(0, 1)를 기억 => 기억소자, 레지스터
④ 복잡하고 수리 어려움, 빠르다.

(1) RS 플립플롭

① 2 논리 값: Set, Reset
                출력은 Q(정상출력)와 Q'(보수출력)

② NOR 게이트를 이용한 RS 래치
　㉠ 래치: 수동적, 전자적으로 상태를 바꾸지 않는 한 상태 유지 (플립플롭으로 활용)
　㉡ 래치: 주어진 상태를 유지 (NAND 또는 NOR 로 회로 구성)



(2) JK 플립플롭
RS 플립플롭 개량
S, R이 동시에 1이 입력되더라도 반대 출력으로 바뀌어 안정
집적화되어 널리 사용




(3) D 플립플롭(Data, Delay)

① 동기 입력을 가진 RS-FF를 변경
   입력신호 D가 변하지 않고 그대로 출력
② R과 S에 같은 값 입력 차단


(4) T 플립플롭(Toggle)

① JK-FF를 변경

입력신호 T가 들어올 때마다 출력 상태 변경

② T가 0일 때는 변화가 없고, T가 1이면 보수 출력



01 중앙처리장치
산술 논리 연산장치와 레지스터 세트, 제어장치로 구성
CPU 버스로 연결

CPU 구성요소의 역할

① 제어장치: 명령 해독, 제어신호 발생, 제어 수행
② 연산장치: 각종 연산 실행
③ 레지스터: 데이터를 임시 저장
④ 버스: 데이터 전달


02 제어장치

1. 명령어

[연산 코드(Operation Code) | 오퍼랜드(Operand)]

연산 코드: 수행될 연산 지정, 비트 수가 증가하면 실행가능 연산 증가
오퍼랜드: 연산에 필요한 데이터, 주소, 레지스터 번호

③ 명령어의 길이: CPU가 한 번에 처리할 수 있는 데이터의 길이
   (CPU에 따라 단어 길이의 두 배 이상의 명령어 제공)

2. 오퍼랜드 수에 따른 명령어의 분류
(1) 0-주소 명령어

[OP-Code]

① 오퍼랜드 없이 연산자만으로 명령어 구성, 스택 컴퓨터에서 사용

② 명령어가 짧아서 빠르다.
③ 스택에 삽입하는 PUSH, 출력하는 POP 명령어
④ 수식은 역 폴리시(후위표기법)로 바꾸어야 한다.
⑤ 주소부가 없으나 무조건 스택을 사용하므로 묵시적 주소

(2) 1-주소 명령어

[OP-Code | Operand]

① 모든 데이터 처리가 내장되어 있는 누산기(AC)
② 누산기로 데이터를 전달하는 LOAD, 누산기의 데이터를 램에 저장하는 STORE






(3) 2-주소 명령어

[OP-Code | Operand1 | Operand2]

① 범용 레지스터
② Operand1이 기억장치에서 가져온 데이터와 Operand2가 가져온 데이터를 연산에 사용
     => Operand1에 기억
③ 계산 결과를 시험할 필요가 있을 때 CPU 내에서 직접 시험 가능 => 시간 절약

④ Move 명령어를 많이 사용


(4) 3-주소 명령어

[OP-Code | Operand1 | Operand2 | Operand3]

① 범용 레지스터 구조
② 프로그램을 짧게 하고, 연산 후 입력자료 보존
③ Operand2와 Operand3에 의해 주기억장치에서 가져온 데이터를 연산, Operand1이 가리키는 주기억장치에 저장

④ 1 명령을 수행하기 위해 최소 4번의 기억장치 접근, 오래 걸리고 특수목적용 외에는 미사용














연산코드(op-code)가 수행하는 연산에 따라 명령어의 특성 결정
(함수 연산, 전달 기능, 입출력, 제어)

① 함수 연산 : 산술연산, 논리연산
② 전달 : CPU와 주기억장치 사이 또는 CPU 내 레지스터 간의 정보 교환과 목적지에 저장
③ 입출력 : CPU와 외부장치 간의 데이터 이동
④ 제어 : 프로그램 흐름 제어









주소지정 방식

① 명령어 실행 과정에서 주소지정 방식에 따라 유효주소 EA 결정
     EA는 실제 데이터를 읽어오는 주소
② 주소지정 방식이 복잡해질수록 EA 결정 시간 증가

(1) 즉시 주소지정 방식

[OP-Code | 데이터]

① 오퍼랜드 필드의 내용이 연산에 사용할 실제 데이터
② 데이터의 인출을 위해 램 접근이 필요 없으므로 실행 사이클이 짧아진다.
③ 오퍼랜드 크기에 따라 사용 가능한 데이터의 범위 결정




(2) 직접 주소지정 방식
① 명령어 내 오퍼랜드 필드의 내용이 데이터의 유효주소
② 데이터 인출을 위해 한 번의 기억장치 접근만 필요
③ 오퍼랜드 필드의 비트 수에 의해 직접 접근할 수 있는 기억장치 주소 공간 제한


(3) 간접 주소지정 방식

① 명령어의 오퍼랜드 필드에 유효주소가 저장된 주소가 있고, 그 주소가 가리키는 기억 장소에 유효주소 저장

② 두 번의 기억장치 접근 필요
   첫 번째에서 주소를 읽어오고, 두 번째에서 실제 데이터 인출

③ 기억장치의 단어 길이가 n비트라면, 최대 2ⁿ개의 주소 공간

④ 여러 단계의 간접 지정도 가능
다단계(multi-level) 또는 연속적(cascade) 간접 주소지정 방식

(4) 레지스터 주소지정 방식

① 데이터가 레지스터에 저장
오퍼랜드가 지정한 유효주소는 레지스터 번호

② 오퍼랜드 필드의 비트 수에 의해 접근 가능한 레지스터의 개수가 정해진다.
③ 레지스터의 크기가 데이터의 범위 결정
④ 데이터 인출을 위해 기억장치 접근 X


(5) 레지스터 간접 주소지정 방식

① 오퍼랜드 필드가 가리키는 레지스터의 내용이 유효주소
② 주소가 지정될 수 있는 기억장치의 범위는 레지스터의 비트 수로 결정



(6) 변위 주소지정 방식

① 명령어는 변위를 나타내는 오퍼랜드와 레지스터 번호 R을 갖는다.
② 유효주소는 R이 가리키는 레지스터의 내용과 변위 A가 더해져 결정

③ 상대 주소지정 방식
　㉠ 다음 명령어의 주소를 기억하는 PC와 오퍼랜드에 저장된 변위를 더해 유효주소 결정
　㉡ PC 내용은 다음 명령어 주소, 변위는 그 명령어의 위치 기준 상대값








03 연산장치

1. 연산장치의 구성

① 연산장치: 제어장치의 지시에 따라 사칙연산
                수식의 합, 곱셈을 판단하는 논리 연산

산술 및 논리 연산기, 상태 레지스터, 쉬프터(shifter), 보수기(complementer)로 구성
　㉠ 산술 및 논리 연산기 : 산술, 논리 연산 수행
　㉡ 쉬프터 : 데이터 비트를 좌우로 이동
                 산술적 왼쪽 이동은 기존 값*2
                 산술적 오른쪽 동은 기존 값/2
　㉢ 보수기 : ALU 내 데이터의 보수 연산


③ 상태 레지스터의 상태 비트: 플래그나 조건코드
　㉠ 자리올림(C:Carry) : 자리 올림수가 발생하면 1
　㉡ 부호(S:Sign) : 음수면 1
　㉢ 제로(Z:Zero) : 연산 결과가 0이면 1
　㉣ 오버플로(O:Overflow) : 오버플로가 발생하면 1

2. 연산의 종류

① 비수치적 연산(논리적 연산)
MOVE, AND, OR, XOR, COMPLEMENT, 논리적 SHIFT, ROTATE

② 수치적 연산
사칙연산(ADD, SUBTRACT, MULTIPLY, DIVIDE), 산술적 SHIFT 등

③ Unary 연산(단항 연산)
SHIFT, ROTATE, COMPLEMENT, MOVE 등

④ Binary 연산(이항 연산)
사칙연산, AND, OR, XOR 등


인터럽트

① 중앙처리장치가 실행 중인 프로그램을 강제 중단, 특정 주소의 프로그램 수행
② 새로운 프로그램 루틴: 인터럽트 서비스 루틴(ISR : Interrupt Service Routine)

인터럽트 동작 순서

① 인터럽트 발생장치가 요청
② 수행중인 프로그램 상태를 기억장소에 저장
③ 인터럽트 장치와 원인을 분석, 인터럽트 서비스 루틴 수행
④ 끝나면, 보존된 프로그램 상태를 복구, 중단된 곳부터 수행

인터럽트의 종류

(1) 외부 인터럽트

① 정전, 기계 결함 같은 외부 원인
② 입출력장치 같은 하드웨어로 발생되므로 하드웨어 인터럽트
③ CPU와 비동기적으로 발생
• 정전, 기계 오류
• 의도적 조작, 타이머
• 조작원이나 다른 프로세서가 재시작 명령
• 입출력 장치의 요청(키보드, 하드디스크)


(2) 내부 인터럽트


② CPU와 동기적
• 프로그램 오류(0으로 나누기, 보호 영역 메모리 접근, 미정의 명령어)
• 슈퍼바이저 호출 인터럽트: 명시적으로 예외 조건을 생성하는 명령
   발생 시점이 일정하고 동기적
   특별한 서비스가 필요할 때 고의적으로 OS 호출

   사용자 모드 => 슈퍼바이저 모드로 진입

   인터럽트 요청장치 판별방법






소프트웨어에 의한 방식 : 폴링(Polling)방식

① 하나의 인터럽트 처리 루틴을 통해서 인터럽트 발생 시 이를 처리하는 방식

모든 장치의 인터페이스에 여러 플래그를 두어 그 중 인터페이스가 인터럽트를 요청 하였는지를 나타내는 DONE 플래그에 의해서 감지하여 처리


② 인터럽트가 많을 때 많은 시간 소요
③ 저속이지만 우선순위 변경이 간단


하드웨어에 의한 방식 : 벡터 인터럽트(vector interrupt)

① CPU와 Interrupt를 요청할 수 있는 장치 사이에 장치 번호 버스(Device Code Bus)를 설치
이 버스를 통하여 요청장치의 번호를 CPU에 알리는 방식

② 중앙처리장치와 인터럽트를 발생할 수 있는 모든 장치 간에 장치번호 버스를 연결

버스에서 신호가 발생 시 감지하여 인터럽트를 처리

인터럽트 처리 루틴으로 분기하는 명령들이 있어 감지된 장치, 인터럽트 종류에 따라 해당루틴으로 분기



데이지 체인(daisy chain) 방식

① 모든 입출력 모듈이 하나의 인터럽트 요구선 공유
② 입출력 모듈의 인터럽트 확인 신호 선은 데이지 형태로 연결
   중앙처리장치와 가까운 입출력 모듈의 우선순위가 높다.







05 명령실행과 제어

주기억장치에 기억된 프로그램의 명령을 꺼내어 해독
각 장치에 제어 신호 제공 => 장치 동작

1. 명령어 실행에 필요한 CPU 레지스터

(1) 프로그램 카운터(PC)

① 다음 명령어 주소

② 명령어 인출 후 자동적으로 1 또는 명령어 길이(바이트 수)만큼 증가
③ 분기(branch) 명령어 실행 시 그 목적지 주소로 바뀐다.

(2) 명령어 레지스터(Instruction Register : IR)

최근 인출 명령어 저장


(3) 누산기(Accumulator : AC)

① 데이터를 일시적으로 저장
② CPU가 한 번에 처리할 수 있는 비트 수(Word) 같다.

(4) 기억장치 주소 레지스터(Memory Address Register : MAR)

PC 주소가 주 버스로 출력되기 전에 일시적으로 저장

(5) 기억장치 버퍼 레지스터(Memory Buffer Register : MBR)

기억장치에 쓰여질, 읽혀진 데이터를 일시적으로 저장




레지스터의 크기

PC와 MAR의 크기는 같다.
MBR과 주기억장치 1워드의 크기는 같다.

각 명령어 사이의 역할
① 인출 사이클 : 명령어 인출 후 해독
② 간접 사이클 : 데이터의 유효주소 계산
③ 실행 사이클 : 데이터(OPERAND) 인출 후 실행
④ 인터럽트 사이클 : 인터럽트 처리를 위한 프로그램 상태정보 저장





06 마이크로 오퍼레이션

① 각 명령은 명령 사이클에 의해 수행
② 명령 사이클은 명령어 인출 사이클과 실행 사이클로 구성
③ 마이크로 오퍼레이션은 각 사이클에서 실제 수행
   프로그램 수행의 기본 단위



프로그램 실행의 계층 구조
① 프로그램은 여러 명령어 사이클(instruction cycle)을 수행
② 명령어 사이클은 인출 사이클(fetch cycle), 간접 사이클(indirect cycle), 실행 사이클(execute cycle), 인터럽트 사이클(interrupt cycle)로 구성
③ 각 사이클들은 마이크로 오퍼레이션으로 구성


1. 인출 사이클(fetch cycle)

기억장치의 지정된 위치에서 명령어 읽어오기



t₀
MAR ← PC
PC 내용을 MAR로 보낸다. (CPU 내부 버스)

t₁
MBR ← M[MAR], PC ← PC + 1
주소가 지정하는 명령어가 MBR에 적재 (데이터 버스)
PC의 내용에 1을 더하여 다음 명령어 주소를 가리킨다.

t₂
IR ← MBR
MBR의 명령어가 IR로 이동


2. 실행 사이클(execute cycle)

명령어를 실행

① 데이터 이동 : CPU와 기억장치 또는 CPU와 I/O 장치 사이에 데이터 이동 (LOAD)

t₀
MAR ← IR(addr)
IR의 오퍼랜드(주소)를 MAR로 보낸다.

t₁
MBR ← M[MAR]
주소의 데이터 인출, MBR로 보낸다.

t₂
AC ← MBR
MBR의 데이터를 AC에 적재






② 데이터 처리 : 데이터에 대해 산술 또는 논리연산 수행 (ADD)

t₀
MAR ← IR(addr)
IR의 오퍼랜드(주소)를 MAR로 보낸다.

t₁
MBR ← M[MAR]
주소의 데이터를 인출, MBR로 보낸다.

t₂
AC ← AC + MBR
데이터와 AC의 내용을 더하고 결과를 다시 AC에 저장

③ 데이터 저장 : 연산 결과 데이터 혹은 읽은 데이터를 기억장치에 저장 (STORE)

t₀
MAR ← IR(addr)
데이터를 저장할 기억장치 주소를 MAR로 보낸다.

t₁
MBR ← AC
저장할 데이터를 MBR로 보낸다.

t₂
M[MAR] ← MBR
MBR의 내용을 MAR이 지정하는 기억 장소에 저장

④ 제어 : 프로그램의 실행 순서 결정

t₀
PC ← IR(addr)
분기할 목적지의 주소가 PC로 적재

3. 간접 사이클(indirect cycle)

① 간접 주소 사용 시, 실행 사이클이 시작되기 전에 그 유효주소를 기억장치로부터 읽어와 IR의 오퍼랜드에 적재

② 인출 사이클과 실행 사이클 사이에 위치

t₀
MAR ← IR(addr)
명령어의 오퍼랜드를 MAR로 보낸다.

t₁
MBR ← M[MAR]
MAR이 가리키는 기억장치의 내용(데이터의 실제 주소)을 MBR로 보낸다.

t₂
IR(addr) ← MBR
데이터의 실제 주소를 명령어의 오퍼랜드에 넣는다.



인터럽트 사이클(interrupt cycle)

① CPU는 한 명령어의 실행 사이클 종료
다음 명령어를 위한 인출 사이클 시작 전에 인터럽트 요구 신호가 있는지 검사
② 요구가 있으면 현재 명령어 실행을 끝내고, 다음 명령어의 주소(PC)를 스택에 저장
③ 인터럽트 서비스 루틴을 호출하기 위해 루틴의 시작주소를 PC에 적재
   시작주소는 인터럽트 요구 장치로부터 전송되거나 미리 정해진 값으로 결정


인터럽트 사이클

t₀
MBR ← PC
주프로그램에서 수행될 다음 명령어의 주소를 MBR로 전송

t₁
MAR ← SP, PC ← ISR(인터럽트 서비스루틴)의 시작 주소
SP(stack pointer)의 내용을 MAR로 전송
PC의 내용은 인터럽트 서비스루틴의 시작주소로 변경

t₂
M[MAR] ← MBR
MBR에 저장되어 있던 원래 PC의 값(복귀주소)을 스택에 저장

인터럽트 사이클

① MBR ← PC : 리턴 번지를 MBR에 저장
② PC ← 0 : PC를 0으로 설정
③ MAR ← PC : MAR을 0으로 설정
④ PC ← M : ISR(인터럽트 서비스 루틴)이 있는 주소로 설정
⑤ M[MAR] ← MBR : 리턴 번지를 스택에 저장
⑥ IEN ← 0 : IEN(interrupt enable)을 0으로 설정
⑦ R ← 0 또는 F ← 0 : FETCH 사이클로 진행


마이크로 오퍼레이션 사이클 타임

CPU 클록: 모든 플립플롭(레지스터 포함)들이 클록 펄스에 동기화되어 동작
        마이크로오퍼레이션은 이 주기 이내에 수행

(1) 동기 고정식

① 마이크로 오퍼레이션 사이클 타임 중에서 수행시간이 가장 긴 것
    CPU의 Clock 주기를 정하는 방식
② 마이크로 오퍼레이션 사이클 타임이 모두 같으므로 제어기를 구현하기 쉽다.
③ 마이크로 오퍼레이션 사이클 타임이 현저한 차이가 날 때 시간 낭비


(2) 동기 가변식

① 사이클 타임이 현저한 차이가 날 때 수행시간이 유사한 군 별로 다른 사이클 타임 (서로 정수배)

② 차이가 날 때 동기 고정식보다 시간 낭비를 줄인다.
③ 제어기 복잡



(3) 비동기식
① 원하는 만큼의 cycle time을 각각 할당
② CPU 시간 낭비는 없으나 복잡해서 미사용







07 시스템 버스

① 중앙처리장치와 시스템 내의 다른 요소들 사이에 정보 교환

② CPU 내부 버스는 제어장치, 연산장치, 레지스터를 연결하는 배선(wire)의 집합
데이터 신호, 주소 신호, 제어 신호 전송



데이터 버스 대역폭
① 클록 주파수 : 20MHz
　1초에 20M개의 클록 전송

② 버스 클록 주기 : 50nsec
　클록 1개의 시간은 클록 주파수의 역수

③ 데이터 버스 폭 : 64비트일 경우
　클록 1개는 64bit(8Byte)를 전송

④ 버스 대역폭은 Byte × 20M/1sec로 계산되어 160(Mbyte/sec)

1. 데이터 버스

① 장치들 사이에 데이터를 전송
② 양방향 전송
③ 폭은 중앙처리장치와 주기억장치 사이에 한 번에 전송되는 비트 수


2. 주소 버스

① 데이터의 쓰기, 읽기를 할 때, 해당 주기억장치 장소를 주소로 전송
② 단방향 전송
③ 비트 수는 중앙처리장치가 접근할 수 있는 기억장치의 주소 수 결정
   기억장소의 수 결정

3. 제어 버스

① 중앙처리장치와 주기억장치 및 입출력장치 사이에 제어신호를 전송하는 선들의 집합
② 제어 버스의 비트 수는 CPU 또는 시스템 구성에 따라 달라진다.
③ 기억장치 읽기/쓰기 신호와 I/O 읽기/쓰기 신호가 있다.





08 마이크로프로세서의 분류

CISC: 복잡한 명령어 집합 사용
RISC: 간단한 명령어 집합 사용


1. CISC(Complexed Instruction Set Computer)
① Load, Store, Register와 다양한 메모리 명령 제공
② 주기억장치 참조 방식에 따라 다양한 명령어
③ 명령어 길이는 가변
④ 마이크로 프로그래밍 제어방식 사용
⑤ 명령어가 복잡해서 속도 향상에 한계
⑥ 전력 소모가 많다.

2. RISC(Reduced Instruction Set Computer)

① 필수적인 명령어만 제공
② 한정된 주소지정 방식 사용
③ 모든 명령은 1클록으로 실행
④ 모든 명령은 1워드 길이로 명령어의 길이는 고정
⑤ 연산은 레지스터 사이에서만 수행, 메모리 참조는 Load/Store 명령만 사용
⑥ Hard-Wired Control 방식 사용
⑦ 레지스터를 많이 사용, 처리속도가 빠르고 처리율이 높다.
⑧ 자주 사용되지 않는 명령들이 사용될 경우 느리다.
⑨ 프로세서 기능이 단순 => 전력 소모가 적다.
⑩ 파이프라이닝에 효율적


기억장치 속도 순서

레지스터 > L1캐시 > L2캐시 > 주기억장치 > 보조기억장치

접근 방법에 따른 기억장치 유형
1. 순차적 접근

데이터 저장 순서에 따라 기억장치에 순차적으로 접근
접근 시간은 원하는 데이터가 저장된 위치에 따라 결정
(자기 테이프)

2. 직접 접근
어떻게 분류되고 어느 위치에 있는지에 상관없이 언제든지 호출
호출할 때 데이터 저장 위치나 접근 시간에 구애받지 않는다.

임의 접근과 비슷하나 임의 접근은 주기억 장치, 직접 접근은 보조 기억 장치


3. 임의 접근
접근 시간이 이전의 접근 순서와 무관하게 항상 일정
(RAM, ROM)

01 주기억장치

입력장치에서 온 초기정보, 처리과정의 중간정보, 처리 후의 최종정보를 기억

컴퓨터의 명령에 따라 유효하게 사용될 수 있도록 배열
용량에 따른 번지수

1. 기억장치 계층 구조

① 상위로 갈수록 용량은 작아지고 속도, 가격은 높아진다.


임의 접근 기억장치(Random Access Memory : RAM)

전원 공급이 중단되면 모든 데이터가 지워지는 휘발성


(1) 동적 RAM(DRAM)

① 충전기 캐패시터에 전하 저장(2진 데이터)
② 캐패시터의 전하는 방전되므로 재충전 제어회로 탑재
③ 저렴해서 메모리로 사용
④ 전력 소모가 적고 가격이 낮다.

(2) 정적 RAM(SRAM)
① 플립플롭 기억소자의 임의 접근 기억장치, 전원 공급이 있는 한 기억
② 재충전 제어회로 불필요
③ 집적도가 낮고 가격이 높다.
④ 빨라서 캐시 메모리

읽기 전용 기억장치(Read Only Memory : ROM)
① 명령, 데이터를 읽기만 가능
② 전원 공급이 중단되도 저장
③ 쓰기가 없어서 RAM보다 간단한 구조
④ 플립플롭 대신 OR 연결로 기억장치 배열 형성


ROM에 저장되는 내용

시스템 초기화 프로그램 및 진단 프로그램
그림(BIOS-POST)
자주 사용되는 함수들을 위한 서브루틴
제어 장치의 마이크로프로그램



(2) 종류

1) mask ROM

ROM 제작 시, 저장 데이터에 맞게 회로를 구성해 내용 변경 불가능

2) PROM(Programmable ROM)
① 사용자가 PROM writer로 기록 가능(1회만)
② 1회 변경 후, 변경, 삭제 X

3) EPROM(Erasable PROM)

① 여러 번 변경, 삭제
② UVEPROM(Ultra Violet Erasable PROM)과 EEPROM(Electrically Erasable PROM)
③ EEPROM: 비휘발성, 읽기와 쓰기 모두 가능
④ EEPROM: 데이터를 갱신 횟수 제한
.

4) 플래시 메모리(flash memory)

① 데이터를 보존하는 롬과 입출력이 자유로운 램의 장점 보유
② EEPROM처럼 전기적으로 삭제
③ EEPROM처럼 갱신 횟수 제한
④ 소비전력이 작고, 전원이 꺼져도 비휘발성, 하드디스크 대용
⑤ 저장용량이 큰 NAND형과 빠른 NOR형



SSD(Solid State Drive)

HDD와 달리 자기디스크가 아닌 반도체 메모리 내장
기계 구동장치가 필요없어 열, 소음 X
외부 충격에 강하다.


낸드플래시 메모리에 자료를 읽고 쓰는 방식
HDD보다 빠르다. 대용량 SSD 개발로 HDD 대체


SLC : 한 개의 셀/한 개의 비트저장
MLC : 한 개의 셀/두 개의 비트저장
TLC : 한 개의 셀/세 개의 비트저장



주기억장치 용량과 레지스터 간의 크기 관계

① 주기억장치의 용량은 주소의 개수와 주소 1개의 크기를 곱해 구한다.
② 주소의 개수는 MAR(memory address register)의 크기 관련
③ 주기억장치 주소 1개의 크기인 워드 길이는 MBR(memory buffer register) 크기



자기디스크
① 디스크팩 : 디스크에 자화 물질을 입혀서 만든 다수의 여러 장
② 액세스암 : Read/Write Header가 붙어있는 암
③ R/W 헤드 : 읽고 쓰는 자기 헤드
④ 트랙 : 디스크의 중심원으로 나눈 것
⑤ 섹터 : 트랙을 구역으로 나눈 것
⑥ 실린더 : 액세스암이 한번 이동되어 만날 수 있는 트랙의 집합
⑦ 사용면수 : 디스크 장수 × 2 - 2
　(맨 위, 맨 아래면)

2. 접근 시간

Access Time = Seek Time + Search Time + Transmission Time

① Seek Time : 헤드가 해당 트랙을 찾는데 걸리는 시간
② Search Time : 해당 트랙 내에서 해당 섹터를 찾는데 걸리는 시간
③ Transmission Time : 찾은 데이터를 이동시키는 데 걸리는 시간

주기억장치 용량과 레지스터와의 관계

① 주기억장치의 주소는 512개 이상 => 직접 주소방식에서 주소 관련 PC와 MAR은 10비트 이상

② 주기억장치의 한 주소내의 크기가 16비트 => 워드는 16비트, MBR과 AC(누산기)의 크기도 16비트

DRAM 확장

소용량 DRAM 칩으로 대용량 DRAM 칩 구성: 워드 길이, 개수 확장

1. 워드 길이 확장(병렬)

① 주소버스, 제어버스에 공통 신호 사용, 여러 워드를 순차적으로 연결 => 워드 길이 확장(워드용량 유지)

② 4개의 1K×8비트 RAM 칩들을 병렬로 연결하면 워드의 길이가 4배 확장
    => 1K×32비트의 기억장치 모듈을 설계 가능


워드 개수의 확장(직렬)

① 기억장치 칩들의 선택 신호를 제어버스로 공통으로 연결
   => 각 기억장치 칩의 선택을 통해 주소 확장
   사용할 수 있는 워드의 개수 확장



② 4개의 1K×8비트 RAM 칩들을 직렬 연결
   => 주소가 4배 확장되어 4K×8비트의 기억장치 모듈 설계 가능


③ 4K×8비트 기억장치 모듈에서 각 RAM에 지정되는 주소 영역을 나타낸 것

④ 2×4 디코더의 입력 비트 값이 주소 비트의 상위 두 비트




02 캐시 메모리

① CPU와 주기억장치의 속도 차이 보완
CPU 칩과 인접한 곳이나 칩 내부
고속의 반도체 기억장치 칩들 사용 => 주기억장치 접근 시간보다 매우 짧다.
주기억장치 용량보다 매우 적다.

캐시 사용 방식의 속도
연관 사상 > 집합 연관 사상 > 직접 사상

2. 캐시 기억장치의 동작 원리

① CPU가 기억장치 참조 시, 주기억장치대신 캐시 먼저 조사


② 캐시에서 찾으면 적중(hit), 못 찾으면 실패(miss)

③ 실패인 경우, 주기억장치에서 인출해야 하므로 CPU의 처리 시간이 길어진다.
④ CPU가 한 번 이상 접근했던 부분들이 캐시에 복사되어 있는 상태
⑤ 캐시는 중앙처리장치 명령어와 필요한 정보 저장, 즉시 제공

처리 시간 감소 (참조 지역성)


3. 주기억장치와 캐시 기억장치 사이에서의 평균 기억장치 접근 시간

T_average = H_hit ratio × T_cache + (1-H_hit ratio) × (T_main + T_cache)

보충학습 — 평균 기억장치 접근 시간 구하기

T_cache = 50ns, T_main = 500ns, 적중률 90%





보충학습
평균 기억장치 접근 시간 구하기

T_cache = 50ns, T_main = 500ns, 적중률 90%

1. 캐시 실패 시 캐시 기억장치 접근시간을 포함하는 경우
= 0.9 × 50ns + 0.1 × (500ns + 50ns) = 100ns

2. 캐시 실패 시 캐시 기억장치 접근시간을 포함하지 않는 경우
= 0.9 × 50ns + 0.1 × 500ns = 95ns


주기억장치에서 캐시로 데이터를 복사하는 방법

1. 직접 사상(direct mapping)

① 용량이 작은 RAM을 캐시 기억장치로 사용 (가장 간단)
② 주기억장치의 블록이 특정 라인에만 적재
   => 캐시 적중 여부는 그 블록이 적재될 수 있는 라인만 검사
③ 사상 방식이 간단, 저렴
④ 주기억장치 블록이 적재될 수 있는 라인이 하나
   => 프로그램이 동일 라인에 적재되는 두 블록들을 반복적으로 액세스하면 캐시 실패율 증가




직접 사상

캐시 블록번호 = 메모리 블록 번호 mod 캐시 블록개수
캐시 블록이 8개인 경우, 캐시 블록번호는 메모리 블록번호를 8로 나눈 나머지 값

메모리의 블록 주소 5비트 중에서 하위 3비트를 추출하는 것
상위 2비트는 몫에 해당하므로 캐시 블록 번호와 무관

직접 사상은 모듈로 연산의 결과인 하위 3비트를 사용하여 메모리 블록을 캐시 블록으로 사상

캐시 블록의 위치는 메모리 블록 번호의 마지막 3비트 정보만 내포

① 직접 사상(direct mapping) : 메모리 블록을 정해진 하나의 캐시 블록에만 사상

② 완전 연관 사상(fully-associative mapping) : 메모리 블록을 어떤 캐시 블록에도 사상

③ 집합 연관 사상(set-associative mapping) : 직접 사상과 완전 연관 사상을 절충, 메모리 블록을 정해진 블록의 집합 내 어디에도 사상





2. 완전-연관 사상(fully-associative mapping)

① 주기억장치 블록이 캐시의 어느 라인에도 적재 가능 => 직접 사상의 단점 보완
② 적중 검사가 모든 라인에 대해서 이루어져야 하므로 검사 시간이 길어진다.
③ 캐시 슬롯의 태그를 병렬 검색: 복잡하고 비용이 높은 회로 필요


보충학습

완전 연관 사상

메모리 블록이 어느 캐시 블록에도 사상될 수 있는 방식으로, 캐시 블록을 정할 수 있는 인덱스 필드가 없다. 메모리 블록 번호가 0100, 0100, 1000, 1100이 캐시 메모리의 어느 블록에도 사상될 수 있음을 보여준다.

캐시 블록 번호는 태그로부터 전혀 무관하며, 메모리 블록의 어떤 정보도 포함하지 않는다.

완전 연관 사상은 캐시 블록이 어느 메모리 블록에 대응하는지 식별하기 위해 메모리 블록 번호 5비트를 모두 캐시 태그로 사용한다.

만약 메모리 블록 번호가 1000번이었고 캐시 블록 번호가 100에 적재되었다면 캐시 블록 번호 100에 대응하는 태그는 01100이다.

연관 사상에서의 캐시 교체방식

① 최소 최근 사용(LRU: least recently used) 방식
: 적중률이 매우 높은 방식으로, 모든 블록에 대해 최근에 참조된 정보를 포함해야 하므로 구현 비용이 높다.

② 무작위(random) 방식
: 임의의 캐시 블록을 선택하여 교체함으로써 캐시 메모리 공간을 검사하는 방식이다. 효율성은 보장하기 어렵지만 구현 비용이 저렴하고 간단하다.

③ 선입 선출(FIFO first-in-first-out) 방식
: 캐시 메모리에 먼저 저장된 블록을 먼저 삭제하고 새로운 블록이 메모리 공간을 준비하는 방식이다. 무작위 방식보다 효율성은 보장하기 어렵지만 구현 비용이 저렴하다.


3. 집합-연관 사상(set-associative mapping)

① 직접 사상과 연관 사상 방식을 조합한 방식이다.
② 캐시는 n개의 집합으로 나누어지고, 각 집합은 k개의 슬롯으로 구성된다.
③ 주기억장치 블록은 정해진 집합에 적재되고 그 집합 내에서는 연관 사상방식으로 집합 내 어느 슬롯에도 적재될 수 있다.

보충학습

집합-연관 사상

캐시 집합 번호 = 메모리 블록 번호 mod 캐시 집합의 개수

컴퓨터의 캐시 블록은 8개이다. 2-방향 집합 연관 사상이라면 집합의 크기가 2개 블록이므로 캐시 집합의 개수는 4개이다.

메모리 블록을 캐시 집합에 사상하려면 메모리 블록 번호를 4로 나눈 나머지 값을 사용하면 된다. 이는 메모리 블록 번호의 하위 2비트를 인덱스 필드로 사용하는 방식이다.

집합 연관 사상의 인덱스 필드는 하나의 집합을 색인하기 때문에 집합 번호(set number)라고도 한다.

캐시 블록 번호의 5비트 중 상위 3비트는 캐시 블록에 적재된 데이터가 어느 메모리 블록인지 식별하기 위한 태그로 사용된다.



4. 캐시 기억장치 쓰기 정책

CPU가 프로그램을 수행하는 동안 결과를 캐시 기억장치에 쓰는 경우가 있다. 이때
캐시 기억장치와 주기억장치에 기록하는 시점에 따라 즉시 쓰기(write through) 방식과
나중 쓰기(write back) 방식이 있다.

(1) 즉시 쓰기 방식(Write-Through)

① 모든 쓰기 동작이 캐시뿐만 아니라 주기억장치에서도 동시에 발생한다.
② 주기억장치와 캐시 기억장치의 데이터 일관성을 유지한다.
③ 주기억장치 접근이 빈번하게 일어나고 쓰기 시간이 길어진다.

(2) 나중 쓰기 방식(Write-Back)

① 새로운 데이터가 캐시에서 갱신된다.
② 다른 데이터로 교체될 경우 주기억장치에 새로운 데이터를 적용하고 교체된다.
③ 주기억장치에 접근하는 동작을 최소화함으로써 성능은 증진하지만, 캐시 기억장치와
   주기억장치 간 데이터 일관성이 유지되지 않을 수 있다.

5. 캐시 기억장치의 종류

① 집적회로의 기술 발달로 인해 캐시 기억장치를 CPU의 내부에 포함시키는 것이
   가능해지고 있는데 이것을 온 칩(on-chip) 캐시 기억장치라고 한다.
② 캐시 기억장치가 CPU 외부에 위치하면 오프 칩(off-chip) 캐시 기억장치 또는
   외부 캐시 기억장치라고 한다.
③ 계층적 캐시(hierarchical cache)는 온 칩 캐시를 1차 캐시(L1)로 사용하고 칩 외부에
   더 큰 용량의 오프 칩 캐시를 2차 캐시(L2)로 설치하는 방식이다.

보충학습

연관 기억장치(Associative Memory)

① 변위에 의해 혹은 올바른 값이 아니라 기억된 정보의 일부만을 내용 이용하여 원하는
   정보의 위치를 알아낸 후, 그 위치에서 다시 직접적인 접근할 수 있는 특수한
   기억장치이다.

② CAM(Content Addressable Memory)
   : 내용 주소화 메모리라고 한다.

③ 데이터 내용을 기준으로 동시에 병렬로 접근할 수 있고 또한 한 번에 저장장치의
   내용을 검색하여 원하는 결과의 위치를 찾을 수 있다.

④ 각 셀(cell)이 저장장소뿐 아니라 외부인수와 자신의 내용을 비교하는 논리기능을
   가지고 있다.

⑤ 검색은 빠르지만 가격이 비싸다.



다중 프로세서에서의 캐시 일관성 문제 해결

1. 스누핑 프로토콜

① 주소 버스를 항상 감시하여 캐시 상의 메모리에 대한 접근이 있는지를 감시하는 구조이다.
② 다른 캐시에서 쓰기가 발생하면 캐시 컨트롤러에 의해서 자신의 캐시 위에 있는 복사본을 같이 갱신 또는 무효화시킨다.
③ 메모리 요청(Request)에 대해 다른 모든 노드에 브로드캐스트 해야 하며 노드의 수가 증가하면 더 많은 브로드캐스트가 발생하게 된다.

2. 디렉터리 기반 프로토콜

① 디렉터리 기반 일관성 구조는 캐시 블록의 공유 상태, 노드 등을 기록하는 저장 공간인 디렉터리를 이용하여 관리하는 구조이다.
② 어떤 노드에서 해당 캐시 블록의 복사본을 가지고 있는지를 알고 있기 때문에 특정 노드에만 요청을 하게 된다.
③ 브로드캐스트가 불필요하게 되어 대역폭이 상대적으로 작아도 된다.

3. MESI 프로토콜

① MESI 프로토콜은 메모리가 가질 수 있는 네 가지의 캐시 상태를 정의한다.

② MESI에서 메모리 블록이 가지는 상태는 다음과 같다.

㉠ Modified : 블록이 캐시에서 수정된 상태이다. 메모리는 수정되지 않았으며 캐시만 수정되었기 때문에 캐시와 메모리는 다른 데이터를 가지고 있다. 이러한 캐시 블록을 캐시에서 내보낼 때 메모리에 그 변경된 내용을 반영해야 한다.

㉡ Exclusive : main memory와 데이터가 일치한 상태이고, 다른 캐시에 복사본이 존재하지 않는다. 만약 이 캐시의 내용이 CPU에 의해 변경되면 exclusive 상태에서 modified된 상태로 변화된다.

㉢ Shared : 블록이 캐시로 공유된 상태이다. 캐시와 메모리의 상태가 동일하기 때문에 해당 블록을 캐시에서 내보낼 때 메모리에 쓰기 작업을 할 필요가 없다.

㉣ Invalid : 블록이 유효하지 않은 상태이다. 해당 블록의 내용을 캐시로 올리기 위해서는 메모리나 다른 캐시에서 갱신된 내용을 확인할 필요가 있다.

③ 프로그램이 M 상태나 S 상태에 있는 블록을 읽으려고 하는 경우에는 별다른 조치 없이 캐시에서 읽을 수 있다. 만약 I 상태의 메모리 블록을 읽으려고 하는 경우에는 다른 캐시에서 그 메모리를 M 상태로 가지고 있는지를 확인하며, 그에 따른 갱신 작업이 추가적으로 이루어진다.


메모리 인터리빙(Memory Interleaving)

① 하나의 시스템 타이밍에 복수개의 워드를 식별하고 판단할 수 있도록 하여 기억장치에 접근 효율을 높이기 위한 방법이다.
② 기억장치 모듈을 여러 개 가진 기억장치이다.
③ 각 기억장치 모듈을 독립적으로 액세스할 수 있게 되므로 기억장치 주소 상에서 연속적으로 배치된 여러 개의 바이트들을 한 번의 액세스로 주기억장치에서 꺼낼 수 있다.
④ bus를 구성하는 회선의 수가 많을 때는 모든 모듈도 동시에 병렬 접근할 수 있다.


03 RAID(Redundant Array of Independent Disks)

1. RAID 개요

① 여러 개의 디스크를 배열(array) 구조로 연결하여 하나의 논리적 디스크 단위로 패키지화한 시스템이다.
② 여러 개의 독립된 디스크가 일부 중복된 데이터를 나눠서 저장하고 성능을 향상시키는 기술을 말한다.
③ 레벨에 따라 저장장치의 신뢰성을 높이거나 전체적인 성능을 향상시키는 목적을 만족시킨다.
④ 대규모 저장 용량을 필요로 하는 중대형 컴퓨터 시스템에서 널리 사용되고 있다.

2. RAID 시스템 레벨

(1) RAID 0 : 스트라이핑(Striping) 모드

① 패리티나 미러링 없이 스트라이핑만으로 구성된다.
② 스트립(strip)은 일정한 크기로 분할한 하나의 파일 조각을 의미하고, 스트라이프(stripe)는 다수의 논리적 하드디스크에 분산되어 있는 연속적인 여러 조각의 스트립을 의미한다.
③ 오류 검증 기능이 없으므로 드라이브에서 장애가 발생하면 데이터는 모두 손실된다.
④ 다수의 하드디스크에 대해 병렬로 읽기 및 쓰기 작업을 수행할 수 있어 성능이 개선된다.
⑤ RAID 0은 데이터의 안정성은 중요하지 않지만 빠른 데이터 접근을 요구하는 애플리케이션에 적합하다.


(2) RAID 1 : 미러링(mirroring) 모드

① 동일한 내용을 갖는 RAID 볼륨을 추가적으로 구성한다.
② 모든 데이터를 반사 디스크에 복사하고 비교하여 오류를 검사하고 수정할 수 있다.
③ 다른 레벨에 비해 실시간으로 데이터에 대한 복사 기능이 가능하므로 신뢰성이 높다.
④ 읽기 요청에 대해 데이터 디스크와 반사 디스크 중 탐색시간이 짧은 디스크를 사용할 수 있다.
⑤ 쓰기 작업에 대해 모든 디스크를 갱신해야 하므로 성능이 좋지 않다.
⑥ 저장 비용이 많이 들지만, 높은 신뢰성을 요구하는 애플리케이션에 적합하다.

(3) RAID 2 : bit-interleaved with ECC 모드

① 비트 수준으로 분산 저장한 데이터 디스크와 해밍 코드(Hamming code)를 저장하는 검사 디스크로 구성된다.
② 1비트의 오류가 발생하면 검출과 수정이 가능하지만, 2비트 오류가 발생할 때는 검출만 가능하다.
③ 데이터 디스크가 늘어나면 오류 수정을 위한 검사 디스크도 늘어나며, 비용이 높아 거의 사용하지 않는다.



(4) RAID 3 : bit-interleaved striping with parity 모드

① 비트 단위로 분산 저장된 데이터 디스크와 하나의 패리티 디스크로 구성된다.
② RAID 4와 유사하나 분산 저장을 경제적으로 수행하기 위해 하드웨어적인 지원이 요구되며 효율적인 동작을 위해 동기 가능한(synchronized-spindle) 드라이브를 사용한다.

(5) RAID 4 : block-interleaved striping with parity 모드

① 블록 단위로 분산 저장된 데이터 디스크와 하나의 패리티 디스크로 구성된다.
② 데이터를 읽을 때는 RAID 0에 필적하는 우수한 성능을 보이나, 저장할 때는 매번 패리티 정보를 갱신하기 때문에 추가적인 시간이 필요하다.
③ 패리티 디스크에 병목 현상이 발생하면 전체 스트라이핑의 성능 저하가 발생한다.


(6) RAID 5 : block-interleaved striping with distributed parity 모드

① 모든 패리티 비트를 볼륨에 라운드 로빈 방식으로 분산 저장함으로써 패리티 볼륨에 대한 병목 현상을 방지한다.
② 데이터 디스크와 패리티 디스크의 구분이 없다.
③ 용량과 비용을 중요시 하는 응용 환경에 적합하다.
④ 현재 가장 많이 사용되는 RAID 방식이다.

(7) RAID 6 : block-interleaved striping with double distributed parity 모드

① 블록 단위의 데이터와 패리티를 분산하여 저장하지만 신뢰성을 향상하기 위해 두 가지 패리티 정보를 사용하는 RAID이다.
② 블록 인터리브된 이중 분산 패리티 방식이라고도 한다.


01 입출력장치

① 컴퓨터의 중앙처리장치(CPU)가 외부에서 정보를 받아들이는 과정을 입력이라고 하며, 외부 정보를 받아들이는 장치를 입력장치라 한다.

② 컴퓨터의 중앙처리장치가 외부로 정보를 내보내는 과정을 출력이라고 하며, 정보를 내보내는 장치를 출력장치라 한다.


2. 입출력장치의 동작

① 중앙처리장치 또는 주기억장치와 외부의 입출력 매체 사이에 정보를 전송한다.
② 중앙처리장치 또는 주기억장치에 비해 동작 속도가 매우 느리다.
③ 중앙처리장치 또는 주기억장치에 정보를 처리하는 단위가 다르다.
④ 에러가 발생할 확률이 매우 높다.
⑤ 각각의 동작에 대해 자율성을 보장할 수 있다.



1. 입출력 모듈

① 입출력 장치는 종류가 다양하므로 전송 데이터 길이, 전송 데이터 형식, 전송 속도 등이 서로 다르다. 입출력 모듈(I/O module)은 이들을 제어하는 장치이다.
② 주변장치들은 컴퓨터 내부의 중앙처리장치, 주기억장치에 비해 속도가 매우 느리기 때문에 이들과 직접적인 통신이 불가능하다. 이 경우 입출력 모듈이 중간 위치에서 제어하여 적절한 처리 속도로 통신을 가능하게 해준다.


2. 입출력장치의 주소 지정

입출력 모듈에는 여러 개의 입출력 장치가 연결되어 있으므로, 각 장치들을 구분할 수 있도록 고유의 번호 또는 주소가 지정되어 있다.

(1) 기억장치-사상 방식(memory-mapped)

① 입출력장치와 주기억장치는 하나의 주소 공간을 공유한다.
② 기억장치 주소 영역의 일부분을 입출력장치의 주소 영역으로 할당하는 방식이다.
③ 기억장치의 읽기와 쓰기 신호를 입출력장치의 읽기와 쓰기 신호로 사용할 수 있다.
④ 동일한 신호와 명령어를 기억장치와 입출력장치에 사용하므로 프로그래밍하기 쉽다.
⑤ 입출력장치가 기억장치 주소 영역을 사용하므로 기억장치만을 위한 주소 공간이 감소한다.


(2) 분리형 입출력 방식(isolated I/O mapped)

① 입출력장치의 주소 공간을 기억장치 주소 공간과 별도의 기억장치에 할당하는 방식이다.
② 입출력 제어를 위한 별도의 입출력 명령어를 사용한다.
③ 별도의 입출력장치에 대한 읽기 쓰기 신호가 필요하다.
④ 입출력 제어를 위해 입출력장치 명령어들만 사용가능하므로 프로그래밍이 복잡해진다.


입출력 데이터 전송

저속으로 동작하는 입출력장치와 출력장치는 고속으로 동작하는 중앙처리장치와 속도 차이가 때문에 중앙처리장치는 동기화하지 않고, 자체적인 시간 펄스를 이용하여 독립적으로 동작한다.

1. 스트로브 신호(strobe)

① 송신 측에서 데이터를 전송하는 경우 전송되는 것을 수신 측에 알려주기 위해 별도의 신호를 사용한다.
② 송신 측에서 데이터를 데이터 버스에 실어 데이터 펄스 신호를 안정적으로 활성화한 후, 그 신호를 수신 측에 해당하는 출력장치에 보낸다. 출력장치는 스트로브 신호와 데이터 버스에 데이터를 수신한다.
③ 수신 측에서 스트로브 신호를 송신 측에 전달하여 데이터에 대한 전송을 요청한다. 송신 측에서는 데이터 버스에 전송할 데이터를 보내고 수신 측에서는 데이터의 전송을 수신한다.
④ 송신측은 수신측의 수신 여부를 알 수 없다.


2. 핸드셰이킹(handshaking)

① 송신 측과 수신 측 양쪽에서 상대방에게 제어신호를 보내서 데이터의 전송을 알려주는 방법으로 데이터 버스 외에 양쪽에 제어신호를 보내는 별도의 신호선 2개를 가지고 있어야 한다.
② 송신 측과 수신 측이 동시에 동작하는 방식으로, 어느 한 쪽의 장치가 잘못되면 데이터의 전송이 이루어지지 않으므로 높은 신뢰성을 갖는다.
