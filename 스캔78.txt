03 컴퓨터의 분류

1. 사용 데이터에 따른 분류

(1) 디지털 컴퓨터: 2진수로 부호화, 사칙, 논리연산
                             정확도가 아날로그보다 높다.

(2) 아날로그 컴퓨터: 아날로그 신호를 데이터로 이용(연속적인 물리량)
                      입력이 신속, 즉각적인 반응 => 제어용으로 사용

(3) 하이브리드 컴퓨터: 디지털과 아날로그 컴퓨터의 장점을 조합

2. 사용 목적에 따른 분류

(1) 범용 컴퓨터 : 광범위한 분야에 널리 사용
(2) 전용 컴퓨터 : 특수한 목적으로 사용

3. 처리 능력에 따른 분류

(1) 마이크로 컴퓨터
개인용 컴퓨터, 저렴하고 작다.
워드 길이로 구분(8비트, 16비트, 64비트)

(2) 미니 컴퓨터/메인프레임 컴퓨터
다수 사용자용 서버 (다중 작업)
중형 및 대형 컴퓨터

(3) 슈퍼 컴퓨터: 초대형, 초고속, 비싸다.
                강력한 병렬 처리 소프트웨어




진공관 (10⁻³ sec): 통계, 군사용, 많은 비용, 짧은 수명, 큰 부피, 많은 전력소모
트랜지스터 (10⁻⁶ sec): 생산관리, 신뢰성 증대, 전력 소모 감소, 기억용량 증대, OS
집적회로 (10⁻⁹ sec): MIS, 시분할 처리, 주변장치 고속화, 각 장치의 호환성
고밀도 집적회로(10⁻¹² sec): 경영 정보, 사무자동화, PC, DB, 마이크로프로세서
초고밀도 집적회로(10⁻¹⁵ sec): 인공지능 퍼지이론, 추론, 음성인식
                                  전문가 시스템, 고도능력의 단말기, 대규모 네트워크





04 정보처리 시스템의 분류

1. 일괄처리

① 입력 자료를 일정기간 또는 일정량을 모아서 한번에 처리
CPU 유휴시간이 많다. (CPU와 I/O장치의 속도차이)


CPU 1개 - 주기억장치 1개 - 프로그램 1개 - 사용자 1명

2. 다중프로그래밍 시스템
CPU 효율 극대화
1 CPU로 여러 사용자 프로그램이 동시에 실행되는 것처럼 처리
한 프로그램이 입출력 장치 사용,
다른 프로그램이 CPU 사용

CPU 1개 - 주기억장치 1개 - 프로그램 n개 - 사용자 1명

3. 실시간 시스템
자료가 발생할 때마다 즉시 처리

4. 시분할 시스템
다중프로그래밍의 논리적 확장
사용자들에게 CPU를 일정시간(Time Slice) 할당
주어진 시간동안 컴퓨터와 대화식으로 프로그램 수행
다수의 단말 사용자가 혼자 주컴퓨터를 사용하는 것 같이 처리


CPU 1개 - 주기억장치 1개 - 프로그램 n개 - 사용자 n명






5. 다중처리 시스템
여러 CPU, 기억장치 1개, 여러 프로그램
주기억장치 공유(강결합)

CPU n개 - 주기억장치 1개 - 프로그램 n개 - 사용자 n명





6. 분산처리 시스템
대형 컴퓨터의 기능을 여러 지역의 컴퓨터에 분산
=> 통신망으로 교환, 처리
각 CPU는 기억장치 보유(약결합)

CPU n개 - 주기억장치 n개 - 프로그램 n개 - 사용자 n명

컴퓨터 종류에 따라 2바이트, 4바이트, 8바이트
CPU가 램에서 1번에 읽는 단위

• Half Word : 2바이트
• Full Word : 4바이트
• Double Word : 8바이트

표준 BCD 코드
6비트(zone : 2bit, digit : 4bit)
2⁶(=64)개의 문자 표현
초기 컴퓨터에서 사용, (대문자, 소문자 구별 X)
10진수 입출력이 간편



아스키 코드
7비트(zone : 3bit, digit : 4bit)
2⁷(=128)개의 문자 표현
데이터 통신용, 마이크로컴퓨터



확장 BCD 코드(EBCDIC 코드)
8비트(zone : 4bit, digit : 4bit)
2⁸(=256)개의 문자 표현
범용 컴퓨터

유니코드(Uni-Code)
16비트, 2¹⁶(65,536)개, 모든 언어의 문자 표현
OS, 프로그램, 언어에 관계없이 문자마다 고유 코드값 제공




① 8421코드 : 4비트 BCD 코드, 10진수 한 자리를 4비트로 표현, 보수 변환이 어렵다.
② 3초과 코드: 8421코드에 3(0011)을 더한 코드, 자기보수, 비가중치 코드
③ Gray 코드 : 연산에는 부적당, A/D변환기나 입출력장치 코드, 기계 제어
                입력 코드로 사용하면 에러 감소 (1 비트만으로 새로운 코드 개발)



④ 패리티 비트 : 1 패리티 비트를 데이터에 추가, 1 에러만 검출

㉠ 짝수 패리티(우수 : even parity) : 1의 개수가 짝수
㉡ 홀수 패리티(기수 : odd parity) : 1의 개수가 홀수
㉢ CRC 패리티 방식 : 패리티 비트(수평 에러 검사), 패리티 워드(수직 에러 검사) => 에러 수정



⑤ 해밍코드 : 에러 검출, 수정  => 데이터 비트가 많아지면 패리티 비트도 증가


XOR: 입력이 다르면 1

고정소수점 연산

① 2진 정수 데이터 표현


② 표현 범위(Half Word, Full Word)는 작지만 빠르다.

③ 음수: 부호와 절대치, 1의 보수, 2의 보수 표현 방식

④ 양수: 부호와 절대치 방식만 사용, 보수 X






부동소수점 연산

(1) 특징

① 2진 실수 데이터 표현, 연산
② Full Word(32bit), Double Word(64bit)
③ 부호부, 지수부(소수점 위치), 가수부(유효숫자)
④ 부호: 최상위 비트로 양수는 0, 음수는 1
⑤ 소수점: 지수부와 가수부 사이로 간주
⑥ 정규화된 값 중 1은 저장 X (잠복비트)
⑦ 고정소수점보다 복잡하고 실행시간이 많이 걸리나 아주 큰 수, 작은 수 표현 가능
⑧ 정규화(Normalization) 필요: 지수부와 가수부로 분리
⑨ 음수 형태의 지수를 양수로 표현 => 지수에 바이어스(Bias)를 더한다.



01 논리 게이트

모든 정보를 0, 1로 표현
2진 정보를 게이트(논리회로)에서 처리
게이트의 동작은 부울 대수로 표현
게이트의 입력과 출력은 진리표로 표현


AND 게이트
① 논리곱 수행
② 모든 입력이 1인 경우에만 1 출력, 나머지는 0 출력


OR 게이트
① 논리합 수행
② 하나 이상의 입력이 1이면 출력 1


NOT 게이트

① 입력 1개, 출력 1개, 논리 부정
② 입력값의 반대를 출력


NAND 게이트
① AND 와 NOT 결합
② AND 결과를 반대로 출력


NOR 게이트
① OR 과 NOT 결합
② 하나 이상의 입력이 1이면 0 출력


XOR 게이트

① Exclusive OR, 배타적 OR
② 여러 입력 중 1의 개수가 홀수이면 1 출력
③ 2 입력 중 하나만 1이면 1 출력
   둘 다 1이거나 0이면 0 출력


XNOR 게이트

① Exclusive NOR, 배타적 NOR이라고 한다.
② 여러 입력 중 1의 개수가 짝수이면 1 출력
③ 2 입력 모두 1 또는 0으로 입력되면 1 출력, 두 입력이 다르면 0 출력


범용 논리 게이트

① NAND 게이트와 NOR 게이트는 모든 게이트를 구성 가능
② 유니버셜 게이트(universal gate)


조합논리회로
출력이 입력에 의해서 결정


(1) 반가산기(Half Adder)

① 2입력과 2출력 => 합(sum), 자리올림(carry)
② 합(sum): 두 입력의 XOR
③ 자리올림(carry): 두 입력의 AND


(2) 전가산기(Full Adder)

① 올라온 Carry 고려 => 3입력변수, 출력은 Sum과 Carry
② Sum = A'BC + A'BC' + AB'C' + ABC = A⊕B⊕C
③ Carry = A'BC + AB'C + ABC' + ABC = C(A⊕B) + AB
④ 2개의 반가산기와 1개의 OR회로




병렬 2진 가감산기

n비트를 더할 경우 n개의 전가산기 필요


가산기에 게이트를 추가해 부호 신호로 뺄셈 (별도의 감산기 X)


XOR 입력 부호값이 0이면 XOR 의 B에 변환이 없으므로 덧셈 수행
             부호값이 1이면 XOR 의 B의 보수 전달

다음 병렬가감산기는 M이 0일 때 A+B 수행, M이 1일 때 A-B 수행



(3) Decoder(해독기)

① n비트의 2진 코드를 최대 2ⁿ개의 정보로 바꿔주는 조합 논리회로
② 2ⁿ개의 출력 중 한 개만 1, 나머지는 0


(4) Encoder(부호기)

① 외부 입력 신호를 부호화된 신호로 변환, 컴퓨터 내부로 들어보낸다.
② 2ⁿ개의 입력신호로부터 n개의 출력 신호를 만든다.
③ 2ⁿ개의 비트 중 오직 한 비트만이 1을 갖고, 나머지 비트는 0이 되는 입력신호 생성
④ 활성화된 1이 몇 번째 비트인가를 파악 => 2진 정보 출력

(5) 멀티플렉서
① 여러 입력 중 하나만 출력에 전달해주는 조합 논리회로
② 여러 회로가 단일 회선을 공동 이용, 신호 전송



(6) 디멀티플렉서
여러 입력 신호 중 하나를 골라 출력




순서논리회로

① 플립플롭(2진 기억소자)와 논리게이트로 구성

② 출력: 외부입력과 플립플롭의 현재 상태로 결정
       출력의 일부가 입력으로 피드백되어 출력에 영향

③ 2진 자료(0, 1)를 기억 => 기억소자, 레지스터
④ 복잡하고 수리 어려움, 빠르다.

(1) RS 플립플롭

① 2 논리 값: Set, Reset
                출력은 Q(정상출력)와 Q'(보수출력)

② NOR 게이트를 이용한 RS 래치
　㉠ 래치: 수동적, 전자적으로 상태를 바꾸지 않는 한 상태 유지 (플립플롭으로 활용)
　㉡ 래치: 주어진 상태를 유지 (NAND 또는 NOR 로 회로 구성)



(2) JK 플립플롭
RS 플립플롭 개량
S, R이 동시에 1이 입력되더라도 반대 출력으로 바뀌어 안정
집적화되어 널리 사용




(3) D 플립플롭(Data, Delay)

① 동기 입력을 가진 RS-FF를 변경
   입력신호 D가 변하지 않고 그대로 출력
② R과 S에 같은 값 입력 차단


(4) T 플립플롭(Toggle)

① JK-FF를 변경

입력신호 T가 들어올 때마다 출력 상태 변경

② T가 0일 때는 변화가 없고, T가 1이면 보수 출력



01 중앙처리장치
산술 논리 연산장치와 레지스터 세트, 제어장치로 구성
CPU 버스로 연결

CPU 구성요소의 역할

① 제어장치: 명령 해독, 제어신호 발생, 제어 수행
② 연산장치: 각종 연산 실행
③ 레지스터: 데이터를 임시 저장
④ 버스: 데이터 전달


02 제어장치

1. 명령어

[연산 코드(Operation Code) | 오퍼랜드(Operand)]

연산 코드: 수행될 연산 지정, 비트 수가 증가하면 실행가능 연산 증가
오퍼랜드: 연산에 필요한 데이터, 주소, 레지스터 번호

③ 명령어의 길이: CPU가 한 번에 처리할 수 있는 데이터의 길이
   (CPU에 따라 단어 길이의 두 배 이상의 명령어 제공)

2. 오퍼랜드 수에 따른 명령어의 분류
(1) 0-주소 명령어

[OP-Code]

① 오퍼랜드 없이 연산자만으로 명령어 구성, 스택 컴퓨터에서 사용

② 명령어가 짧아서 빠르다.
③ 스택에 삽입하는 PUSH, 출력하는 POP 명령어
④ 수식은 역 폴리시(후위표기법)로 바꾸어야 한다.
⑤ 주소부가 없으나 무조건 스택을 사용하므로 묵시적 주소

(2) 1-주소 명령어

[OP-Code | Operand]

① 모든 데이터 처리가 내장되어 있는 누산기(AC)
② 누산기로 데이터를 전달하는 LOAD, 누산기의 데이터를 램에 저장하는 STORE






(3) 2-주소 명령어

[OP-Code | Operand1 | Operand2]

① 범용 레지스터
② Operand1이 기억장치에서 가져온 데이터와 Operand2가 가져온 데이터를 연산에 사용
     => Operand1에 기억
③ 계산 결과를 시험할 필요가 있을 때 CPU 내에서 직접 시험 가능 => 시간 절약

④ Move 명령어를 많이 사용


(4) 3-주소 명령어

[OP-Code | Operand1 | Operand2 | Operand3]

① 범용 레지스터 구조
② 프로그램을 짧게 하고, 연산 후 입력자료 보존
③ Operand2와 Operand3에 의해 주기억장치에서 가져온 데이터를 연산, Operand1이 가리키는 주기억장치에 저장

④ 1 명령을 수행하기 위해 최소 4번의 기억장치 접근, 오래 걸리고 특수목적용 외에는 미사용














연산코드(op-code)가 수행하는 연산에 따라 명령어의 특성 결정
(함수 연산, 전달 기능, 입출력, 제어)

① 함수 연산 : 산술연산, 논리연산
② 전달 : CPU와 주기억장치 사이 또는 CPU 내 레지스터 간의 정보 교환과 목적지에 저장
③ 입출력 : CPU와 외부장치 간의 데이터 이동
④ 제어 : 프로그램 흐름 제어









주소지정 방식

① 명령어 실행 과정에서 주소지정 방식에 따라 유효주소 EA 결정
     EA는 실제 데이터를 읽어오는 주소
② 주소지정 방식이 복잡해질수록 EA 결정 시간 증가

(1) 즉시 주소지정 방식

[OP-Code | 데이터]

① 오퍼랜드 필드의 내용이 연산에 사용할 실제 데이터
② 데이터의 인출을 위해 램 접근이 필요 없으므로 실행 사이클이 짧아진다.
③ 오퍼랜드 크기에 따라 사용 가능한 데이터의 범위 결정




(2) 직접 주소지정 방식
① 명령어 내 오퍼랜드 필드의 내용이 데이터의 유효주소
② 데이터 인출을 위해 한 번의 기억장치 접근만 필요
③ 오퍼랜드 필드의 비트 수에 의해 직접 접근할 수 있는 기억장치 주소 공간 제한


(3) 간접 주소지정 방식

① 명령어의 오퍼랜드 필드에 유효주소가 저장된 주소가 있고, 그 주소가 가리키는 기억 장소에 유효주소 저장

② 두 번의 기억장치 접근 필요
   첫 번째에서 주소를 읽어오고, 두 번째에서 실제 데이터 인출

③ 기억장치의 단어 길이가 n비트라면, 최대 2ⁿ개의 주소 공간

④ 여러 단계의 간접 지정도 가능
다단계(multi-level) 또는 연속적(cascade) 간접 주소지정 방식

(4) 레지스터 주소지정 방식

① 데이터가 레지스터에 저장
오퍼랜드가 지정한 유효주소는 레지스터 번호

② 오퍼랜드 필드의 비트 수에 의해 접근 가능한 레지스터의 개수가 정해진다.
③ 레지스터의 크기가 데이터의 범위 결정
④ 데이터 인출을 위해 기억장치 접근 X


(5) 레지스터 간접 주소지정 방식

① 오퍼랜드 필드가 가리키는 레지스터의 내용이 유효주소
② 주소가 지정될 수 있는 기억장치의 범위는 레지스터의 비트 수로 결정



(6) 변위 주소지정 방식

① 명령어는 변위를 나타내는 오퍼랜드와 레지스터 번호 R을 갖는다.
② 유효주소는 R이 가리키는 레지스터의 내용과 변위 A가 더해져 결정

③ 상대 주소지정 방식
　㉠ 다음 명령어의 주소를 기억하는 PC와 오퍼랜드에 저장된 변위를 더해 유효주소 결정
　㉡ PC 내용은 다음 명령어 주소, 변위는 그 명령어의 위치 기준 상대값








03 연산장치

1. 연산장치의 구성

① 연산장치: 제어장치의 지시에 따라 사칙연산
                수식의 합, 곱셈을 판단하는 논리 연산

산술 및 논리 연산기, 상태 레지스터, 쉬프터(shifter), 보수기(complementer)로 구성
　㉠ 산술 및 논리 연산기 : 산술, 논리 연산 수행
　㉡ 쉬프터 : 데이터 비트를 좌우로 이동
                 산술적 왼쪽 이동은 기존 값*2
                 산술적 오른쪽 동은 기존 값/2
　㉢ 보수기 : ALU 내 데이터의 보수 연산


③ 상태 레지스터의 상태 비트: 플래그나 조건코드
　㉠ 자리올림(C:Carry) : 자리 올림수가 발생하면 1
　㉡ 부호(S:Sign) : 음수면 1
　㉢ 제로(Z:Zero) : 연산 결과가 0이면 1
　㉣ 오버플로(O:Overflow) : 오버플로가 발생하면 1

2. 연산의 종류

① 비수치적 연산(논리적 연산)
MOVE, AND, OR, XOR, COMPLEMENT, 논리적 SHIFT, ROTATE

② 수치적 연산
사칙연산(ADD, SUBTRACT, MULTIPLY, DIVIDE), 산술적 SHIFT 등

③ Unary 연산(단항 연산)
SHIFT, ROTATE, COMPLEMENT, MOVE 등

④ Binary 연산(이항 연산)
사칙연산, AND, OR, XOR 등


인터럽트

① 중앙처리장치가 실행 중인 프로그램을 강제 중단, 특정 주소의 프로그램 수행
② 새로운 프로그램 루틴: 인터럽트 서비스 루틴(ISR : Interrupt Service Routine)

인터럽트 동작 순서

① 인터럽트 발생장치가 요청
② 수행중인 프로그램 상태를 기억장소에 저장
③ 인터럽트 장치와 원인을 분석, 인터럽트 서비스 루틴 수행
④ 끝나면, 보존된 프로그램 상태를 복구, 중단된 곳부터 수행

인터럽트의 종류

(1) 외부 인터럽트

① 정전, 기계 결함 같은 외부 원인
② 입출력장치 같은 하드웨어로 발생되므로 하드웨어 인터럽트
③ CPU와 비동기적으로 발생
• 정전, 기계 오류
• 의도적 조작, 타이머
• 조작원이나 다른 프로세서가 재시작 명령
• 입출력 장치의 요청(키보드, 하드디스크)


(2) 내부 인터럽트


② CPU와 동기적
• 프로그램 오류(0으로 나누기, 보호 영역 메모리 접근, 미정의 명령어)
• 슈퍼바이저 호출 인터럽트: 명시적으로 예외 조건을 생성하는 명령
   발생 시점이 일정하고 동기적
   특별한 서비스가 필요할 때 고의적으로 OS 호출

   사용자 모드 => 슈퍼바이저 모드로 진입

   인터럽트 요청장치 판별방법






소프트웨어에 의한 방식 : 폴링(Polling)방식

① 하나의 인터럽트 처리 루틴을 통해서 인터럽트 발생 시 이를 처리하는 방식

모든 장치의 인터페이스에 여러 플래그를 두어 그 중 인터페이스가 인터럽트를 요청 하였는지를 나타내는 DONE 플래그에 의해서 감지하여 처리


② 인터럽트가 많을 때 많은 시간 소요
③ 저속이지만 우선순위 변경이 간단


하드웨어에 의한 방식 : 벡터 인터럽트(vector interrupt)

① CPU와 Interrupt를 요청할 수 있는 장치 사이에 장치 번호 버스(Device Code Bus)를 설치
이 버스를 통하여 요청장치의 번호를 CPU에 알리는 방식

② 중앙처리장치와 인터럽트를 발생할 수 있는 모든 장치 간에 장치번호 버스를 연결

버스에서 신호가 발생 시 감지하여 인터럽트를 처리

인터럽트 처리 루틴으로 분기하는 명령들이 있어 감지된 장치, 인터럽트 종류에 따라 해당루틴으로 분기



데이지 체인(daisy chain) 방식

① 모든 입출력 모듈이 하나의 인터럽트 요구선 공유
② 입출력 모듈의 인터럽트 확인 신호 선은 데이지 형태로 연결
   중앙처리장치와 가까운 입출력 모듈의 우선순위가 높다.







05 명령실행과 제어

주기억장치에 기억된 프로그램의 명령을 꺼내어 해독
각 장치에 제어 신호 제공 => 장치 동작

1. 명령어 실행에 필요한 CPU 레지스터

(1) 프로그램 카운터(PC)

① 다음 명령어 주소

② 명령어 인출 후 자동적으로 1 또는 명령어 길이(바이트 수)만큼 증가
③ 분기(branch) 명령어 실행 시 그 목적지 주소로 바뀐다.

(2) 명령어 레지스터(Instruction Register : IR)

최근 인출 명령어 저장


(3) 누산기(Accumulator : AC)

① 데이터를 일시적으로 저장
② CPU가 한 번에 처리할 수 있는 비트 수(Word) 같다.

(4) 기억장치 주소 레지스터(Memory Address Register : MAR)

PC 주소가 주 버스로 출력되기 전에 일시적으로 저장

(5) 기억장치 버퍼 레지스터(Memory Buffer Register : MBR)

기억장치에 쓰여질, 읽혀진 데이터를 일시적으로 저장




레지스터의 크기

PC와 MAR의 크기는 같다.
MBR과 주기억장치 1워드의 크기는 같다.

각 명령어 사이의 역할
① 인출 사이클 : 명령어 인출 후 해독
② 간접 사이클 : 데이터의 유효주소 계산
③ 실행 사이클 : 데이터(OPERAND) 인출 후 실행
④ 인터럽트 사이클 : 인터럽트 처리를 위한 프로그램 상태정보 저장





06 마이크로 오퍼레이션

① 각 명령은 명령 사이클에 의해 수행
② 명령 사이클은 명령어 인출 사이클과 실행 사이클로 구성
③ 마이크로 오퍼레이션은 각 사이클에서 실제 수행
   프로그램 수행의 기본 단위



프로그램 실행의 계층 구조
① 프로그램은 여러 명령어 사이클(instruction cycle)을 수행
② 명령어 사이클은 인출 사이클(fetch cycle), 간접 사이클(indirect cycle), 실행 사이클(execute cycle), 인터럽트 사이클(interrupt cycle)로 구성
③ 각 사이클들은 마이크로 오퍼레이션으로 구성


1. 인출 사이클(fetch cycle)

기억장치의 지정된 위치에서 명령어 읽어오기



t₀
MAR ← PC
PC 내용을 MAR로 보낸다. (CPU 내부 버스)

t₁
MBR ← M[MAR], PC ← PC + 1
주소가 지정하는 명령어가 MBR에 적재 (데이터 버스)
PC의 내용에 1을 더하여 다음 명령어 주소를 가리킨다.

t₂
IR ← MBR
MBR의 명령어가 IR로 이동


2. 실행 사이클(execute cycle)

명령어를 실행

① 데이터 이동 : CPU와 기억장치 또는 CPU와 I/O 장치 사이에 데이터 이동 (LOAD)

t₀
MAR ← IR(addr)
IR의 오퍼랜드(주소)를 MAR로 보낸다.

t₁
MBR ← M[MAR]
주소의 데이터 인출, MBR로 보낸다.

t₂
AC ← MBR
MBR의 데이터를 AC에 적재






② 데이터 처리 : 데이터에 대해 산술 또는 논리연산 수행 (ADD)

t₀
MAR ← IR(addr)
IR의 오퍼랜드(주소)를 MAR로 보낸다.

t₁
MBR ← M[MAR]
주소의 데이터를 인출, MBR로 보낸다.

t₂
AC ← AC + MBR
데이터와 AC의 내용을 더하고 결과를 다시 AC에 저장

③ 데이터 저장 : 연산 결과 데이터 혹은 읽은 데이터를 기억장치에 저장 (STORE)

t₀
MAR ← IR(addr)
데이터를 저장할 기억장치 주소를 MAR로 보낸다.

t₁
MBR ← AC
저장할 데이터를 MBR로 보낸다.

t₂
M[MAR] ← MBR
MBR의 내용을 MAR이 지정하는 기억 장소에 저장

④ 제어 : 프로그램의 실행 순서 결정

t₀
PC ← IR(addr)
분기할 목적지의 주소가 PC로 적재

3. 간접 사이클(indirect cycle)

① 간접 주소 사용 시, 실행 사이클이 시작되기 전에 그 유효주소를 기억장치로부터 읽어와 IR의 오퍼랜드에 적재

② 인출 사이클과 실행 사이클 사이에 위치

t₀
MAR ← IR(addr)
명령어의 오퍼랜드를 MAR로 보낸다.

t₁
MBR ← M[MAR]
MAR이 가리키는 기억장치의 내용(데이터의 실제 주소)을 MBR로 보낸다.

t₂
IR(addr) ← MBR
데이터의 실제 주소를 명령어의 오퍼랜드에 넣는다.



인터럽트 사이클(interrupt cycle)

① CPU는 한 명령어의 실행 사이클 종료
다음 명령어를 위한 인출 사이클 시작 전에 인터럽트 요구 신호가 있는지 검사
② 요구가 있으면 현재 명령어 실행을 끝내고, 다음 명령어의 주소(PC)를 스택에 저장
③ 인터럽트 서비스 루틴을 호출하기 위해 루틴의 시작주소를 PC에 적재
   시작주소는 인터럽트 요구 장치로부터 전송되거나 미리 정해진 값으로 결정


인터럽트 사이클

t₀
MBR ← PC
주프로그램에서 수행될 다음 명령어의 주소를 MBR로 전송

t₁
MAR ← SP, PC ← ISR(인터럽트 서비스루틴)의 시작 주소
SP(stack pointer)의 내용을 MAR로 전송
PC의 내용은 인터럽트 서비스루틴의 시작주소로 변경

t₂
M[MAR] ← MBR
MBR에 저장되어 있던 원래 PC의 값(복귀주소)을 스택에 저장

인터럽트 사이클

① MBR ← PC : 리턴 번지를 MBR에 저장
② PC ← 0 : PC를 0으로 설정
③ MAR ← PC : MAR을 0으로 설정
④ PC ← M : ISR(인터럽트 서비스 루틴)이 있는 주소로 설정
⑤ M[MAR] ← MBR : 리턴 번지를 스택에 저장
⑥ IEN ← 0 : IEN(interrupt enable)을 0으로 설정
⑦ R ← 0 또는 F ← 0 : FETCH 사이클로 진행


마이크로 오퍼레이션 사이클 타임

CPU 클록: 모든 플립플롭(레지스터 포함)들이 클록 펄스에 동기화되어 동작
        마이크로오퍼레이션은 이 주기 이내에 수행

(1) 동기 고정식

① 마이크로 오퍼레이션 사이클 타임 중에서 수행시간이 가장 긴 것
    CPU의 Clock 주기를 정하는 방식
② 마이크로 오퍼레이션 사이클 타임이 모두 같으므로 제어기를 구현하기 쉽다.
③ 마이크로 오퍼레이션 사이클 타임이 현저한 차이가 날 때 시간 낭비


(2) 동기 가변식

① 사이클 타임이 현저한 차이가 날 때 수행시간이 유사한 군 별로 다른 사이클 타임 (서로 정수배)

② 차이가 날 때 동기 고정식보다 시간 낭비를 줄인다.
③ 제어기 복잡



(3) 비동기식
① 원하는 만큼의 cycle time을 각각 할당
② CPU 시간 낭비는 없으나 복잡해서 미사용







07 시스템 버스

① 중앙처리장치와 시스템 내의 다른 요소들 사이에 정보 교환

② CPU 내부 버스는 제어장치, 연산장치, 레지스터를 연결하는 배선(wire)의 집합
데이터 신호, 주소 신호, 제어 신호 전송



데이터 버스 대역폭
① 클록 주파수 : 20MHz
　1초에 20M개의 클록 전송

② 버스 클록 주기 : 50nsec
　클록 1개의 시간은 클록 주파수의 역수

③ 데이터 버스 폭 : 64비트일 경우
　클록 1개는 64bit(8Byte)를 전송

④ 버스 대역폭은 Byte × 20M/1sec로 계산되어 160(Mbyte/sec)

1. 데이터 버스

① 장치들 사이에 데이터를 전송
② 양방향 전송
③ 폭은 중앙처리장치와 주기억장치 사이에 한 번에 전송되는 비트 수


2. 주소 버스

① 데이터의 쓰기, 읽기를 할 때, 해당 주기억장치 장소를 주소로 전송
② 단방향 전송
③ 비트 수는 중앙처리장치가 접근할 수 있는 기억장치의 주소 수 결정
   기억장소의 수 결정

3. 제어 버스

① 중앙처리장치와 주기억장치 및 입출력장치 사이에 제어신호를 전송하는 선들의 집합
② 제어 버스의 비트 수는 CPU 또는 시스템 구성에 따라 달라진다.
③ 기억장치 읽기/쓰기 신호와 I/O 읽기/쓰기 신호가 있다.





08 마이크로프로세서의 분류

CISC: 복잡한 명령어 집합 사용
RISC: 간단한 명령어 집합 사용


1. CISC(Complexed Instruction Set Computer)
① Load, Store, Register와 다양한 메모리 명령 제공
② 주기억장치 참조 방식에 따라 다양한 명령어
③ 명령어 길이는 가변
④ 마이크로 프로그래밍 제어방식 사용
⑤ 명령어가 복잡해서 속도 향상에 한계
⑥ 전력 소모가 많다.

2. RISC(Reduced Instruction Set Computer)

① 필수적인 명령어만 제공
② 한정된 주소지정 방식 사용
③ 모든 명령은 1클록으로 실행
④ 모든 명령은 1워드 길이로 명령어의 길이는 고정
⑤ 연산은 레지스터 사이에서만 수행, 메모리 참조는 Load/Store 명령만 사용
⑥ Hard-Wired Control 방식 사용
⑦ 레지스터를 많이 사용, 처리속도가 빠르고 처리율이 높다.
⑧ 자주 사용되지 않는 명령들이 사용될 경우 느리다.
⑨ 프로세서 기능이 단순 => 전력 소모가 적다.
⑩ 파이프라이닝에 효율적


기억장치 속도 순서

레지스터 > L1캐시 > L2캐시 > 주기억장치 > 보조기억장치

접근 방법에 따른 기억장치 유형
1. 순차적 접근

데이터 저장 순서에 따라 기억장치에 순차적으로 접근
접근 시간은 원하는 데이터가 저장된 위치에 따라 결정
(자기 테이프)

2. 직접 접근
어떻게 분류되고 어느 위치에 있는지에 상관없이 언제든지 호출
호출할 때 데이터 저장 위치나 접근 시간에 구애받지 않는다.

임의 접근과 비슷하나 임의 접근은 주기억 장치, 직접 접근은 보조 기억 장치


3. 임의 접근
접근 시간이 이전의 접근 순서와 무관하게 항상 일정
(RAM, ROM)

01 주기억장치

입력장치에서 온 초기정보, 처리과정의 중간정보, 처리 후의 최종정보를 기억

컴퓨터의 명령에 따라 유효하게 사용될 수 있도록 배열
용량에 따른 번지수

1. 기억장치 계층 구조

① 상위로 갈수록 용량은 작아지고 속도, 가격은 높아진다.


임의 접근 기억장치(Random Access Memory : RAM)

전원 공급이 중단되면 모든 데이터가 지워지는 휘발성


(1) 동적 RAM(DRAM)

① 충전기 캐패시터에 전하 저장(2진 데이터)
② 캐패시터의 전하는 방전되므로 재충전 제어회로 탑재
③ 저렴해서 메모리로 사용
④ 전력 소모가 적고 가격이 낮다.

(2) 정적 RAM(SRAM)
① 플립플롭 기억소자의 임의 접근 기억장치, 전원 공급이 있는 한 기억
② 재충전 제어회로 불필요
③ 집적도가 낮고 가격이 높다.
④ 빨라서 캐시 메모리

읽기 전용 기억장치(Read Only Memory : ROM)
① 명령, 데이터를 읽기만 가능
② 전원 공급이 중단되도 저장
③ 쓰기가 없어서 RAM보다 간단한 구조
④ 플립플롭 대신 OR 연결로 기억장치 배열 형성


ROM에 저장되는 내용

시스템 초기화 프로그램 및 진단 프로그램
그림(BIOS-POST)
자주 사용되는 함수들을 위한 서브루틴
제어 장치의 마이크로프로그램



(2) 종류

1) mask ROM

ROM 제작 시, 저장 데이터에 맞게 회로를 구성해 내용 변경 불가능

2) PROM(Programmable ROM)
① 사용자가 PROM writer로 기록 가능(1회만)
② 1회 변경 후, 변경, 삭제 X

3) EPROM(Erasable PROM)

① 여러 번 변경, 삭제
② UVEPROM(Ultra Violet Erasable PROM)과 EEPROM(Electrically Erasable PROM)
③ EEPROM: 비휘발성, 읽기와 쓰기 모두 가능
④ EEPROM: 데이터를 갱신 횟수 제한
.

4) 플래시 메모리(flash memory)

① 데이터를 보존하는 롬과 입출력이 자유로운 램의 장점 보유
② EEPROM처럼 전기적으로 삭제
③ EEPROM처럼 갱신 횟수 제한
④ 소비전력이 작고, 전원이 꺼져도 비휘발성, 하드디스크 대용
⑤ 저장용량이 큰 NAND형과 빠른 NOR형



SSD(Solid State Drive)

HDD와 달리 자기디스크가 아닌 반도체 메모리 내장
기계 구동장치가 필요없어 열, 소음 X
외부 충격에 강하다.


낸드플래시 메모리에 자료를 읽고 쓰는 방식
HDD보다 빠르다. 대용량 SSD 개발로 HDD 대체


SLC : 한 개의 셀/한 개의 비트저장
MLC : 한 개의 셀/두 개의 비트저장
TLC : 한 개의 셀/세 개의 비트저장



주기억장치 용량과 레지스터 간의 크기 관계

① 주기억장치의 용량은 주소의 개수와 주소 1개의 크기를 곱해 구한다.
② 주소의 개수는 MAR(memory address register)의 크기 관련
③ 주기억장치 주소 1개의 크기인 워드 길이는 MBR(memory buffer register) 크기



자기디스크
① 디스크팩 : 디스크에 자화 물질을 입혀서 만든 다수의 여러 장
② 액세스암 : Read/Write Header가 붙어있는 암
③ R/W 헤드 : 읽고 쓰는 자기 헤드
④ 트랙 : 디스크의 중심원으로 나눈 것
⑤ 섹터 : 트랙을 구역으로 나눈 것
⑥ 실린더 : 액세스암이 한번 이동되어 만날 수 있는 트랙의 집합
⑦ 사용면수 : 디스크 장수 × 2 - 2
　(맨 위, 맨 아래면)

2. 접근 시간

Access Time = Seek Time + Search Time + Transmission Time

① Seek Time : 헤드가 해당 트랙을 찾는데 걸리는 시간
② Search Time : 해당 트랙 내에서 해당 섹터를 찾는데 걸리는 시간
③ Transmission Time : 찾은 데이터를 이동시키는 데 걸리는 시간

주기억장치 용량과 레지스터와의 관계

① 주기억장치의 주소는 512개 이상 => 직접 주소방식에서 주소 관련 PC와 MAR은 10비트 이상

② 주기억장치의 한 주소내의 크기가 16비트 => 워드는 16비트, MBR과 AC(누산기)의 크기도 16비트

DRAM 확장

소용량 DRAM 칩으로 대용량 DRAM 칩 구성: 워드 길이, 개수 확장

1. 워드 길이 확장(병렬)

① 주소버스, 제어버스에 공통 신호 사용, 여러 워드를 순차적으로 연결 => 워드 길이 확장(워드용량 유지)

② 4개의 1K×8비트 RAM 칩들을 병렬로 연결하면 워드의 길이가 4배 확장
    => 1K×32비트의 기억장치 모듈을 설계 가능


워드 개수의 확장(직렬)

① 기억장치 칩들의 선택 신호를 제어버스로 공통으로 연결
   => 각 기억장치 칩의 선택을 통해 주소 확장
   사용할 수 있는 워드의 개수 확장



② 4개의 1K×8비트 RAM 칩들을 직렬 연결
   => 주소가 4배 확장되어 4K×8비트의 기억장치 모듈 설계 가능


③ 4K×8비트 기억장치 모듈에서 각 RAM에 지정되는 주소 영역을 나타낸 것

④ 2×4 디코더의 입력 비트 값이 주소 비트의 상위 두 비트




02 캐시 메모리

① CPU와 주기억장치의 속도 차이 보완
CPU 칩과 인접한 곳이나 칩 내부
고속의 반도체 기억장치 칩들 사용 => 주기억장치 접근 시간보다 매우 짧다.
주기억장치 용량보다 매우 적다.

캐시 사용 방식의 속도
연관 사상 > 집합 연관 사상 > 직접 사상

2. 캐시 기억장치의 동작 원리

① CPU가 기억장치 참조 시, 주기억장치대신 캐시 먼저 조사


② 캐시에서 찾으면 적중(hit), 못 찾으면 실패(miss)

③ 실패인 경우, 주기억장치에서 인출해야 하므로 CPU의 처리 시간이 길어진다.
④ CPU가 한 번 이상 접근했던 부분들이 캐시에 복사되어 있는 상태
⑤ 캐시는 중앙처리장치 명령어와 필요한 정보 저장, 즉시 제공

처리 시간 감소 (참조 지역성)


3. 주기억장치와 캐시 기억장치 사이에서의 평균 기억장치 접근 시간

T_average = H_hit ratio × T_cache + (1-H_hit ratio) × (T_main + T_cache)

보충학습 — 평균 기억장치 접근 시간 구하기

T_cache = 50ns, T_main = 500ns, 적중률 90%





보충학습
평균 기억장치 접근 시간 구하기

T_cache = 50ns, T_main = 500ns, 적중률 90%

1. 캐시 실패 시 캐시 기억장치 접근시간을 포함하는 경우
= 0.9 × 50ns + 0.1 × (500ns + 50ns) = 100ns

2. 캐시 실패 시 캐시 기억장치 접근시간을 포함하지 않는 경우
= 0.9 × 50ns + 0.1 × 500ns = 95ns


주기억장치에서 캐시로 데이터를 복사하는 방법

1. 직접 사상(direct mapping)

① 용량이 작은 RAM을 캐시 기억장치로 사용 (가장 간단)
② 주기억장치의 블록이 특정 라인에만 적재
   => 캐시 적중 여부는 그 블록이 적재될 수 있는 라인만 검사
③ 사상 방식이 간단, 저렴
④ 주기억장치 블록이 적재될 수 있는 라인이 하나
   => 프로그램이 동일 라인에 적재되는 두 블록들을 반복적으로 액세스하면 캐시 실패율 증가




직접 사상

캐시 블록번호 = 메모리 블록 번호 mod 캐시 블록개수
캐시 블록이 8개인 경우, 캐시 블록번호는 메모리 블록번호를 8로 나눈 나머지 값

메모리의 블록 주소 5비트 중에서 하위 3비트를 추출하는 것
상위 2비트는 몫에 해당하므로 캐시 블록 번호와 무관

직접 사상은 모듈로 연산의 결과인 하위 3비트를 사용하여 메모리 블록을 캐시 블록으로 사상

캐시 블록의 위치는 메모리 블록 번호의 마지막 3비트 정보만 내포

① 직접 사상(direct mapping) : 메모리 블록을 정해진 하나의 캐시 블록에만 사상

② 완전 연관 사상(fully-associative mapping) : 메모리 블록을 어떤 캐시 블록에도 사상

③ 집합 연관 사상(set-associative mapping) : 직접 사상과 완전 연관 사상을 절충, 메모리 블록을 정해진 블록의 집합 내 어디에도 사상





2. 완전-연관 사상(fully-associative mapping)

① 주기억장치 블록이 캐시의 어느 라인에도 적재 가능 => 직접 사상의 단점 보완
② 적중 검사가 모든 라인에 대해서 이루어져야 하므로 검사 시간이 길어진다.
③ 캐시 슬롯의 태그를 병렬 검색: 복잡하고 비용이 높은 회로 필요


보충학습

완전 연관 사상
메모리 블록이 어느 캐시 블록에도 사상 가능
캐시 블록을 정하는 인덱스 필드가 없다.
메모리 블록 번호가 0100, 0100, 1000, 1100
이 캐시 메모리의 어느 블록에도 사상될 수 있음을 보여준다.
캐시 블록 번호는 태그와 무관
메모리 블록의 정보 미포함
캐시 블록이 어느 메모리 블록에 대응하는지 식별하기 위해 메모리 블록 번호 5비트를 모두 캐시 태그로 사용
메모리 블록 번호가 1000번이고 캐시 블록 번호가 100에 적재되면, 캐시 블록 번호 100에 대응하는 태그는 01100




연관 사상에서의 캐시 교체방식

① 최소 최근 사용(LRU: least recently used) 방식
: 높은 적중률, 비싸다. (모든 블록에 대해 최근 참조 정보 포함)

② 무작위(random) 방식
: 임의의 캐시 블록을 선택하여 교체 => 캐시 메모리 공간 검사
효율성 보장 X, 저렴하고 간단

③ 선입 선출(FIFO first-in-first-out) 방식
: 먼저 저장된 블록을 먼저 삭제
무작위 방식보다 효율성 보장 X, 저렴


3. 집합-연관 사상(set-associative mapping)

① 직접 사상과 연관 사상을 조합
② 캐시는 n개의 집합으로 나누어지고, 각 집합은 k개의 슬롯으로 구성
③ 주기억장치 블록은 정해진 집합에 적재
그 집합 내에서는 연관 사상방식으로 어느 슬롯에도 적재 가능


보충학습

집합-연관 사상
캐시 집합 번호 = 메모리 블록 번호 mod 캐시 집합의 개수
컴퓨터의 캐시 블록은 8개
2-방향 집합 연관 사상: 집합의 크기가 2개 블록이므로 캐시 집합은 4개
메모리 블록을 캐시 집합에 사상하려면 메모리 블록 번호를 4로 나눈 나머지 값을 사용
이는 메모리 블록 번호의 하위 2비트를 인덱스 필드로 사용하는 방식이다.
집합 연관 사상의 인덱스 필드는 하나의 집합을 색인하기 때문에 집합 번호(set number)라고도 한다.
캐시 블록 번호의 5비트 중 상위 3비트는 캐시 블록에 적재된 데이터가 어느 메모리 블록인지 식별하기 위한 태그




4. 캐시 기억장치 쓰기 정책

CPU가 프로그램을 수행하는 동안 결과를 캐시에 쓰는 경우
캐시, 주기억장치에 기록하는 시점에 따라 즉시 쓰기(write through), 나중 쓰기(write back)

(1) 즉시 쓰기(Write-Through)
① 모든 쓰기 동작이 캐시, 주기억장치에서 동시 발생
② 주기억장치, 캐시의 일관성 유지
③ 주기억장치 접근이 빈번하고 쓰기 시간이 길다.

(2) 나중 쓰기(Write-Back)
① 새로운 데이터가 캐시에서 갱신
② 다른 데이터로 교체될 경우 주기억장치에 새로운 데이터를 적용하고 교체
③ 주기억장치 접근 최소화 => 캐시, 주기억장치 간 일관성 X, 성능 향상

 


5. 캐시 기억장치의 종류

① 온칩(on-chip) 캐시: CPU 내부에 기억장치 포함
② 오프 칩(off-chip): 기억장치가 CPU 외부
③ 계층적 캐시(hierarchical cache): 온 칩 캐시를 1차 캐시(L1), 칩 외부에 더 큰 오프 칩 2차 캐시(L2)



보충학습

연관 기억장치(Associative Memory)
① 변위 사용, 기억 정보의 일부만으로 위치를 알아낸 후, 그 위치에서 다시 직접 접근
② CAM(Content Addressable Memory): 내용 주소화 메모리
③ 데이터 내용 기준: 동시에 병렬 접근, 한 번에 저장장치의 내용 검색, 원하는 결과의 위치 찾기
④ 각 셀이 저장장소뿐 아니라 외부인수, 자신의 내용을 비교하는 논리기능 보유
⑤ 검색은 빠르지만 비싸다.



다중 프로세서에서의 캐시 일관성 문제 해결

1. 스누핑 프로토콜
① 주소 버스를 항상 감시, 캐시 상의 메모리 접근이 있는지 감시
② 다른 캐시에서 쓰기 발생 시, 캐시 컨트롤러가 자신의 캐시 위에 있는 복사본을 같이 갱신 또는 무효화
③ 메모리 요청에 대해 다른 모든 노드에 브로드캐스트, 노드 수가 증가하면 더 많은 브로드캐스트

2. 디렉터리 기반 프로토콜
① 디렉터리 기반 일관성 구조: 디렉토리(캐시 블록의 공유 상태, 노드 기록)로 관리
② 특정 노드에만 요청 (어떤 노드가 복사본을 갖고 있는지 알고 있다.)
③ 브로드캐스트 불필요, 대역폭이 작아도 된다.

3. MESI 프로토콜
① 메모리의 4캐시 상태 정의
㉠ Modified : 블록이 캐시에서 수정된 상태
             캐시만 수정(메모리 미수정) => 캐시와 메모리는 다른 데이터 보유
             캐시 블록을 캐시에서 내보낼 때 메모리에 변경 내용 반영

㉡ Exclusive : 메모리와 데이터 일치, 다른 캐시에 복사본 X
        CPU가 캐시 내용을 변경하면 exclusive => modified

㉢ Shared : 블록이 캐시로 공유
             캐시, 메모리의 상태가 동일
             해당 블록을 캐시에서 내보낼 때 메모리에 쓰기 불필요
㉣ Invalid : 블록이 유효하지 않은 상태.
       블록의 내용을 캐시로 올리려면 메모리나 다른 캐시에서 갱신 내용 확인 필요



③ M, S 상태는 캐시에서 읽을 수 있다.
I 상태는 다른 캐시에서 그 메모리를 M 상태로 가지고 있는지 확인, 그에 따른 갱신 작업 필요




메모리 인터리빙(Memory Interleaving)

① 1번에 여러 워드 식별 => 기억장치 접근 효율 향상
② 기억장치 모듈 여러 개 보유
③ 각 모듈을 독립적으로 액세스 => 연속 배치된 여러 바이트들을 한 번에 주기억장치에서 꺼낸다.
④ bus 회선이 많으면 모든 모듈 병렬 접근


03 RAID(Redundant Array of Independent Disks)

1. RAID 개요

① 여러 디스크를 배열 구조로 연결 => 1개의 논리적 디스크 단위로 패키지화

② 여러 디스크가 중복 데이터를 나눠서 저장 => 성능 향상
③ 레벨에 따라 저장장치의 신뢰성, 성능 향상
④ 중대형 컴퓨터 시스템에서 사용 (대용량 저장)

2. RAID 시스템 레벨

(1) RAID 0 : 스트라이핑(Striping) 모드

① 스트라이핑만으로 구성(패리티, 미러링 X)

② 스트립: 일정 크기로 분할한 하나의 파일 조각
            다수의 논리적 디스크에 분산된 연속적인 조각들의 스트립

③ 오류 검증 X => 드라이브 장애 시, 데이터는 모두 손실
④ 다수 디스크에 병렬로 읽기 및 쓰기 => 성능 개선
⑤ 안정성은 중요하지 않지만 빠른 접근에 적합



(2) RAID 1 : 미러링(mirroring) 모드

① 동일한 내용을 갖는 RAID 볼륨을 추가적으로 구성
② 모든 데이터를 반사 디스크에 복사 => 오류 검사, 수정
③ 실시간 복사 가능(신뢰성, 비싸다.)
④ 읽기는 데이터 디스크, 반사 디스크 중 탐색시간이 짧은 디스크 사용
⑤ 쓰기는 모든 디스크 갱신 => 성능이 좋지 않다.

(3) RAID 2 : bit-interleaved with ECC 모드

① 데이터 디스크(비트 분산 저장)와 검사 디스크(해밍 코드)
② 1비트 오류 검출, 수정 가능, 2비트 오류는 검출만 가능
③ 데이터 디스크가 늘어나면 검사 디스크도 늘어나며, 비용이 높아 미사용



(4) RAID 3 : bit-interleaved striping with parity 모드

① 데이터 디스크(비트 분산 저장)와 1패리티 디스크
② RAID 4와 유사하나 분산 저장을 경제적으로 수행하기 위해 하드웨어적인 지원이 요구되며 효율적인 동작을 위해 동기 가능한(synchronized-spindle) 드라이브를 사용한다.

(5) RAID 4 : block-interleaved striping with parity 모드

① 데이터 디스크(블록 분산 저장)와 1패리티 디스크
② 읽을 때는 RAID 0 처럼 우수한 성능, 저장할 때는 매번 패리티 정보 갱신(시간 필요)
③ 패리티 디스크 병목 시, 전체 스트라이핑 성능 저하



(6) RAID 5 : block-interleaved striping with distributed parity 모드

① 모든 패리티 비트를 볼륨에 라운드 로빈 방식으로 분산 저장 => 패리티 볼륨의 병목 방지
② 데이터 디스크와 패리티 디스크의 구분 X
③ 용량과 비용을 중요시 하는 환경에 적합
④ 가장 많이 사용

(7) RAID 6 : block-interleaved striping with double distributed parity 모드

① 블록 데이터와 패리티를 분산하여 저장, 2개 패리티 사용(신뢰성)
② 블록 인터리브된 이중 분산 패리티 방식


01 입출력장치


2. 입출력장치의 동작
① 중앙처리장치 또는 주기억장치와 외부 입출력 매체 사이에 정보 전송
② 중앙처리장치 또는 주기억장치에 비해 매우 느리다.
③ 중앙처리장치 또는 주기억장치에 정보 처리하는 단위가 다르다.
④ 에러가 많다.
⑤ 각 동작의 자율성



1. 입출력 모듈

① 입출력 장치는 다양하므로 전송 데이터 길이, 전송 데이터 형식, 전송 속도가 서로 다르다. 이들을 제어
② 주변장치는 중앙처리장치, 주기억장치보다 느리기 때문에 직접 통신 불가
    입출력 모듈이 중간 위치에서 제어 => 적절한 속도로 통신




2. 입출력장치의 주소 지정

입출력 모듈에는 여러 입출력 장치 연결
각 장치를 구분하는 고유 번호, 주소

(1) 기억장치-사상 방식(memory-mapped)

① 입출력장치와 주기억장치는 하나의 주소 공간 공유
② 기억장치 주소 일부를 입출력장치 주소로 할당
③ 기억장치의 읽기와 쓰기 신호를 입출력장치의 읽기와 쓰기 신호로 사용
④ 동일한 신호, 명령어 사용 => 프로그래밍하기 쉽다.
⑤ 입출력장치가 기억장치 주소 사용 => 기억장치만의 주소 공간 감소


(2) 분리형 입출력 방식(isolated I/O mapped)

① 입출력장치의 주소를 기억장치 주소와 별도의 기억장치에 할당
② 입출력 제어용 별도 입출력 명령어 사용
③ 별도의 입출력장치에 대한 읽기 쓰기 신호 필요
④ 입출력 제어는 입출력장치 명령어만 사용가능 => 프로그래밍 복잡



입출력 데이터 전송

저속 입출력장치, 고속 중앙처리장치와 속도 차이 => 중앙처리장치는 동기화 X, 자체 시간 펄스로 독립적 동작


1. 스트로브 신호(strobe)

① 송신 측에서 전송 시, 전송을 수신 측에 알려주는 별도 신호 사용
② 송신 측에서 데이터를 데이터 버스에 실어 데이터 펄스 신호 활성화 => 그 신호를 수신 측에 출력장치에 보낸다.
   출력장치는 스트로브 신호, 데이터 버스의 데이터 수신
③ 수신 측은 스트로브 신호를 송신 측에 전달하여 전송 요청
   송신 측에서는 데이터 버스에 데이터를 보낸다.
④ 송신측은 수신측의 수신 여부를 알 수 없다.


2. 핸드셰이킹(handshaking)

① 송신, 수신 측 양쪽에서 서로 제어신호 보내기
   데이터 버스 외에 신호선 2개
② 송신, 수신 측이 동시에 동작
   한 쪽 장치가 잘못되면 데이터 미전송 (높은 신뢰성)
③ 송신장치는 모든 수신장치가 준비 되었는지 검사하고 전송, 수신 했는 지 확인



03 입출력 제어 기법

CPU가 직접 제어하는 입출력 제어 방식

가장 기본적인 방법
모든 명령을 CPU가 직접 수행(데이터 전송, 데이터 상태 검사)


(1) 프로그램 입출력 방식

① 중앙처리장치가 프로그램 수행 도중 입출력 명령을 만나면 해당 입출력 모듈에 명령을 실행
② 중앙처리장치는 입출력 시작 시, 종료때까지 계속 개입
③ 입출력 모듈이 데이터 수신, 송신 준비가 될 때까지 중앙처리장치가 기다려야 하는 단점


(2) 인터럽트-구동 입출력 방식

① 중앙처리장치에서 입출력 명령을 받은 입출력 모듈이 동작 수행 동안 중앙처리장치가 다른 프로그램 처리 가능
② 메모리 접근은 중앙처리장치가 담당

보충학습

인터럽트-구동 입출력 방식의 읽기 동작

① 중앙처리장치가 입출력 모듈로 읽기 명령을 보낸다.
② 입출력 모듈은 주변장치에서 데이터를 읽는다. 중앙처리장치는 다른 일 수행
③ 입출력 모듈이 중앙처리장치로 인터럽트 신호를 보낸다.
④ 중앙처리장치가 입력된 데이터 요구
⑤ 입출력 모듈이 중앙처리장치로 데이터 전송


직접 기억장치 액세스(DMA)를 이용한 입출력 제어 방식

① DMA(Direct Memory Access) 방식은 대용량 데이터를 이동 시, 효과적
② 기억장치, 입출력 모듈 간의 데이터 전송을 DMA 제어기가 처리, CPU는 미개입
③ 중앙처리장치는 DMA에 명령을 보낸 후, 다른 일을 할 수 있게 되며, DMA 제어기가 모든 입출력 동작 담당
④ DMA 제어기는 중앙처리장치를 거치지 않고 1단어씩 모든 데이터를 기억장치로 전송 (메모리 접근은 DMA가 담당)
⑤ 모든 전송이 완료되면 DMA는 인터럽트를 중앙처리장치에 보낸다.
⑥ 중앙처리장치는 전송의 시작과 마지막에만 입출력 동작에 관여



보충학습

사이클 스틸링(Cycle Stealing)

• 주기억장치에 접근할 때 DMA제어기는 CPU의 Bus Line으로 사이클 스틸링
• 사이클 스틸링은 DMA로부터 주기억장치로 데이터 전송요구 시에만, DMA가 버스 사용권을 일시적으로 CPU로부터 빼앗는 전송 방식

버스트 모드(Burst Mode)
주변기기가 입출력 시 데이터의 전송을 블록 단위 고속 처리. 한 블록 전송 도중 중단 X
입출력 자체를 사용하는 방식의 한 가지로, 한 번이라도 장치가 한 채널을 독점하여 고속 전송



채널(Channel)의 종류

① 셀렉터 채널(Selector Channel)
고속 입출력 장치에 접속하여 대용량 자료를 고속 전송

② 멀티플렉서 채널(Multiplexer Channel)
채널, 기억장치 간 전송속도는 입출력장치보다 빠르므로 1채널에 여러 저속 입출력장치 제어


③ 블록 멀티플렉서 채널(Block Multiplexer Channel)
저속, 고속 입출력장치 동시 통신
블록 단위 전송, 여러 입출력장치 제어






보충학습

DMA 처리 순서

① 중앙처리장치가 DMA로 다음을 포함한 명령 전송
－ 입출력장치 주소
－ 연산(읽기, 쓰기) 지정자
－ 데이터가 읽혀지거나 쓰여질 주기억장치 시작 주소
－ 전송 데이터 워드 수
② DMA 제어기는 중앙처리장치로 버스 요구 신호(BUS REQ) 전송
③ 중앙처리장치는 DMA 제어기로 버스 승인 신호(BUS GNT) 전송
④ 중앙처리장치 개입 없이 DMA 제어기가 주기억장치에 데이터를 읽거나 쓴다.
⑤ 전송할 데이터가 남아있으면, ②~④ 반복
⑥ 전송이 완료되면 중앙처리장치로 인터럽트(INTR) 신호 전송


채널에 의한 입출력

① 직접 입·출력장치와 기억장치 사이에서 자료를 주고받는 입출력 전용 장치(CPU 개입 X) => 데이터 처리의 고속성
② 가장 고성능 입·출력 방식. 채널 제어기는 자신의 채널 프로그램으로 여러 블록 입출력
③ 데이터 전송회로 보유, CPU와 독립하여 동작, 입출력 명령을 해독하여 실행
④ 채널의 기능
㉠ 입출력 명령 해독
㉡ 입출력 동작을 CPU와 독립적(비동기적)으로 수행
㉢ 각 입출력장치에 명령 지시
㉣ 명령의 실행 제어

03 명령어 파이프라이닝

1. 2단계 명령어 파이프라인

1. 인출(fetch), 실행(execute)
2. 인출, 실행 처리 시간이 동일해야 효율


2. 4단계 명령어 파이프라인

1. 명령어 인출(IF), 명령어 해독(ID), 오퍼랜드 인출(OF), 실행(EX)
2. 첫 번째 블록 주기를 제외하고 나머지 블록은 병렬 처리. 최대 4 명령어 단계 동시 처리

명령어 파이프라이닝

1. 1번에 1명령어만 실행하는 것이 아니라 1명령어 실행 도중 다른 명령어 실행 시작 => 동시에 여러 명령어를 중첩 실행
2. 1명령어를 여러 단계로 나누어 처리 => 1명령어의 특정 단계 처리 동안 다른 명령어의 다른 단계 처리
3. 처리 속도, 처리량 향상
4. 1명령어 처리 속도가 빨라지는 것은 아니다.



3. 파이프라인에 의한 속도 향상

1. 파이프라인 단계 수 K
2. 실행 명령어 수 N
3. 각 파이프라인 단계가 클록 주기를 T로 가정
4. 파이프라인 전체 명령어 실행 시간 S

S = (K + N - 1) * T

4. 이상적인 효과가 나올 수 없는 문제점

1. 각 단계의 클록 주기는 실제 가장 긴 시간
2. 오퍼랜드 인출이 필요없는 명령어도 모든 단계 통과
3. 1단계, OF단계가 동시에 기억장치 접근 시, 충돌 => 지연
4. 조건 분기 명령어 실행 => 미리 인출한 명령어들 무효화




04 파이프라인 해저드

1. 해저드의 의미

1. 선행, 후행 명령어 중첩 실행 => 파이프라인에 새로운 명령어 투입 시, 여러 원인으로 잘못된 결과
2. 명령어, 데이터가 준비되지 않아서 파이프라인을 멈춰야 하거나 새로운 명령어를 파이프라인에 투입한 경우 잘못된 결과 초래
3. 구조적 해저드, 명령어 해저드, 데이터 해저드

2. 해저드의 종류

(1) 구조적 해저드

1. 파이프라인에서 실행 중인 2개 이상의 명령어가 동일 하드웨어를 동시 요구 => 중지
2. 하드웨어 자원 부족 => 자원 해저드
3. 해결책: 충돌 자원을 추가 제공, 예약표
4. 충돌 자원 필요 명령어 사이에 파이프라인 버블, 즉 NOP(no-operation) 명령어 삽입


(2) 명령어 해저드

1. 실행할 명령어 미결정 => 파이프라인 중지
2. 분기 명령어로 발생 => 분기 해저드, 제어 해저드
3. 조건, 무조건 분기 같은 제어 명령어 실행 시, 다음 명령어를 파이프라인에 투입
   => 잘못된 결과 (분기 명령어 다음의 명령어의 주소를 인출 단계에서 알 수 없기 때문)





(3) 데이터 해저드

① 연산할 데이터 미준비 => 파이프라인 중지
② 선행 명령어의 데이터와 후행 명령어의 데이터 간 종속관계로 발생
③ 파이프라인 방식의 데이터 접근 순서가 순차 방식과 다르다.

① 하드웨어 추가 : 인출장치를 전용 하드웨어로 구현
     무조건 분기 명령어를 인식, 빠르게 분기 목표 주소 계산(추가 시간 불필요)
② NOP(No-Operation) 사용 : 파이프라인 스톨이 생기면 NOP 명령어 삽입

2. 명령어 해저드(제어 해저드) 해결 방법

① 명령어 재배치 : 명령어의 순서를 재배치하여 파이프라인 스톨 해결
② 명령어 재배치와 분기 선계산 : 명령어 재배치와 인출장치에 전용 하드웨어를 사용하는 것을 결합
                  하드웨어는 분기 주소 계산, 분기 명령어 인식, 다른 명령어 수행

③ 명령어 선인출 : 필요한 명령어를 미리 명령어 큐에 인출해 저장

④ 지연 분기 : 분기 명령어와 그 명령어의 순서를 바꾸어 실행(조건 분기 전 명령어의 실행 결과가 영향을 안주는 경우)

⑤ 분기 예측 : 조건 분기 명령어를 인출한 후, 다음 명령어 인출을 예측 => 명령어 종속성에 의한 잠재적인 시간 지연 감소

3. 데이터 해저드 해결 방법

① 데이터 종속성으로 명령어가 이전 명령어 결과를 사용한다면, 그때마다 정확한지 확인


② 어떤 명령어는 이전 명령어 완료까지 진행 X => 이런 데이터 종속성은 파이프라인 성능 감소

③ 데이터 전방전달(forwarding) : 결과 생성 파이프의 출력과 결과 사용 파이프의 입력을 연결하는 별도의 경로 추가

④ ALU에서 실행한 1결과를 다음 명령어 사이클에서 ALU 실행에 사용
⑤ 컴파일러 도움으로 명령어의 수행 결과를 즉시 다음 명령어의 오퍼랜드로 이용할 수 있도록 전달




05 슈퍼스칼라(superscalar) / 슈퍼파이프라인(superpipeline)

1. 슈퍼스칼라 개요

① 여러 파이프라인을 이용해서 독립적으로 명령어들을 실행할 수 있어, 명령어들은 프로그램 순서와 다르게 실행하는 것이 가능하다.

② 슈퍼스칼라의 기본 구성은 파이프라인으로 구현된 여러 개의 기능 유닛(function unit)이 명령어들의 병렬 처리를 지원한다.

③ 슈퍼스칼라 등급(degree)이 m이면, m개의 명령어를 병렬 처리한다는 것이다.

④ 슈퍼스칼라 프로세서의 구조는 두 명령어 사이에 데이터 의존성이 존재하지 않아 독립적으로 동시에 실행이 가능하다.

등급이 m인 k단계의 슈퍼스칼라 프로세서에서 N개의 명령어를 실행하는데 걸리는 전체 시간은 다음과 같다.

(k + ⌈N / m⌉ - 1) * T


2. 슈퍼파이프라인 개요

① 파이프라인에서 단계의 클록 주기를 절반 이하로 줄여서 명령어 실행 속도를 두 배 이상 높이는 방법이다.

② 슈퍼파이프라인의 등급(degree)이 m이면, 기능 유닛의 클록 사이클 시간은 기본 사이클의 1/m이 된다.

등급이 m인 k단계의 슈퍼파이프라인 구조에서 N개의 명령어를 실행하는데 걸리는 전체 시간은 다음과 같다.

(k + ⌈(N - 1) / m⌉) * T




VLIW(Very Long Instruction Word)

① VLIW 컴퓨터는 프로세서의 복잡성을
을 줄이고 명령수행을 더 빠르게 할
수 있도록 많은 작업을 할 수 있지만,
특별히 VLIW형 프로세서를 위해서
설계되고 제작된 새로운 컴파일러
들을 필요로 한다.

② VLIW 컴퓨터는 프로세서 수준으로
작업을 수행하기보다는 소프트웨어
컴파일러가 대부분의 작업을 수행
할 수 있도록 설계되었다. 컴파일 시
에 컴파일러는 프로그램 수행을 위
한 가장 최상의 방법을 결정하며, 이
결정은 사실상 프로그램 코드의 한
부분으로서 저장될 것이고 실제 명
령과 데이터 따라 프로세서에 보내
지게 된다.

③ VLIW는 최상의 프로세서를 얻기 위
해 Instruction-Level Parallelism(ILP)
이라는 것을 사용한다. 동시에 모든
작업을 할 수 있는 복합적인 명령체
계를 가지고, 명령어는 어떻게 하면
쉽게 수행될 수 있는지에 관한 정보
를 저장하게 된다. 따라서 프로세서
의 각기 다른 부분에서 병렬적으로
명령어를 수행한다.




06 MIMD

1. MIMD 개요

① 대부분의 다중프로세서 시스템과 다중컴퓨터 시스템(multiple-computer system)이 이 분류에 속한다.

② n개의 프로세서들이 서로 다른 명령어들과 데이터들을 처리한다.

③ 밀결합 시스템(tightly-coupled system)의 전형적인 구조는 기억장치가 모든 프로세서들에 의해 공통으로 사용되는 공유-기억장치 구조(shared-memory architecture)이다.

④ 소결합 시스템(loosely-coupled system)은 다중컴퓨터 시스템이라고도 불리며, 각 프로세서들이 자신의 지역 기억장치(local memory)를 가진 독립적인 컴퓨터 모듈로 구성되고, 프로세서들 간의 통신은 메시지 전송(message-passing) 방식에 의해 이루어진다.


2. 기억장치 액세스 모델에 따른 분류

(1) 균일 기억장치 액세스(UMA : Uniform Memory Access) 모델

① 모든 프로세서들이 상호연결망에 의해 접속된 기억장치들을 공유한다.

② 프로세서들은 기억장치의 어느 영역이든 액세스할 수 있으며, 그에 걸리는 시간이 모두 동일하다.


(2) 불균일 기억장치 액세스(NUMA : Non-uniform Memory Access) 모델

① 시스템 내 모든 기억장치들이 하나의 주소 공간을 형성하는 분산 공유-기억장치(distributed shared-memory) 형태로 구성되기 때문에, 프로세서들은 자신이 속한 UMA 모듈 내의 지역 공유-기억장치(LSM : Local Shared Memory)뿐 아니라 전역 공유-기억장치(GSM : Global Shared Memory) 및 다른 UMA 모듈의 LSM들도 직접 액세스할 수 있다.




② 기억장치 액세스 시간은 어느 위치의 기억장치를 액세스하는지에 따라 달라진다.


(3) 무-원격 기억장치 액세스(NORMA : No-Remote Memory Access) 모델

① 프로세서가 원격 기억장치(다른 노드의 기억장치)는 직접 액세스할 수 없는 구조이다.

② 프로세서와 기억장치로 구성되는 노드들이 메시지 전송 방식을 지원하는 상호 연결망에 의해 서로 접속된다.


MPP(Massively Parallel
Processing)
분산 메모리 병렬 컴퓨터의 일종으로
수천 개의 고성능 컴퓨터를 연결한 초
병렬 처리 구조를 말한다.
무공유 구조(shared nothing architecture)
기반이다.
각 노드는 처리율을 높이고 지연시간을
낮추기 위해 맞춤식 네트워크를 통해
고속으로 통신한다.





07 암달의 법칙(Amdhal’s law)

1. 암달의 법칙 정의

① 초기의 IBM 컴퓨터 설계자인 진 암달(Gene Amdhal)이 제안한 암달의 법칙은 시스템의 일부분을 개선하는 경우 전체 시스템에서 얻을 수 있는 최대 성능 향상을 구할 때 사용한다.
② 암달의 법칙은 주로 병렬화에 의한 시스템 성능 향상의 한계를 지적하는 데 사용된다.
③ 시스템 일부의 기능을 아무리 향상하더라도 성능이 향상되지 않는 부분에 의해 전체 시스템의 성능이 제한된다는 것이다.

2. 최대 성능 향상

암달의 법칙에 따르면, 어떤 시스템을 개선하여 전체 작업 중 p%의 부분에서 s배의 성능이 향상되었을 때 전체 시스템에서 최대 성능 향상은 다음과 같다.

보충학습

암달의 법칙 예

부동 소수점 연산의 수행 시간이 50%를 차지하는 프로그램이 있다.
1. 부동 소수점 연산을 위한 하드웨어를 2배 빠르게 만든다면 수행 시간이 얼마나 향상되는가?
시스템의 일부를 개선한 후의 전체 시스템 성능은 암달의 법칙을 사용하여 다음과 같이 나타낼 수 있다.

시스템의 전체 성능 향상 = 1 / ((1 - 0.5) + 0.5 / 2) ≅ 1.33

따라서 부동 소수점 연산을 위한 하드웨어를 2배 빠르게 개선한다면 프로그램은 이전보다 약 1.33배 빨라진다.

2. 이 프로그램을 2배 빠르게 수행하려면 부동 소수점 연산을 위한 하드웨어를 얼마나 개선해야 하는가?
위와 동일한 방법으로 암달의 법칙을 사용해본다.

2 = 1 / ((1 - 0.5) + 0.5 / s)

성능을 2배 향상하려면 위와 같은 등식을 만족해야 하므로 0.5 / s = 0, 즉 s = ∞가 되어야 한다.
따라서 부동 소수점 연산의 부하가 50%가 차지하는 경우, 부동 소수점 연산을 위한 하드웨어에 아무리 투자하더라도 전체 성능을 2배 향상할 수 없다.

구스타프슨의 법칙(Gustafson’s Law)
컴퓨터 과학에서 대용량 데이터 처리는 효과적으로 병렬화할 수 있다는 법칙이다.
암달의 법칙에 반대되는 개념이다.








01 운영체제 개요

1. 운영체제의 정의

① 사람을 대신하여 컴퓨터 시스템의 각종 자원을 보다 효율적으로 관리하고 운영하는 시스템 소프트웨어
② 사용자에게 최대의 편리성을 제공하도록 하기 위한 컴퓨터 하드웨어와 사용자간의 매개체 역할을 하는 시스템 프로그램


2. 운영체제의 목적

(1) 편리성 : 사용자에게 편리한 환경을 제공한다.

① 운영체제는 사용자가 프로그램을 효율적으로 실행할 수 있는 환경을 제공해야 한다.

② 사용자와 컴퓨터 시스템이 정보 및 명령을 상호 교환할 수 있는 인터페이스를 제공해야 한다.


(2) 효율성 : 시스템 성능 향상을 지원한다.

① 처리량 : 시스템의 생산성을 나타내는 것으로 단위시간당 처리하는 작업량이다.

② 응답시간 : 사용자가 시스템에 작업을 의뢰한 후 반응을 얻을 때까지 걸리는 시간이다.
시분할 시스템과 온라인 시스템에서는 응답시간(response time)이라고 하고 일괄처리 시스템에서는 반환시간(turn around time)이라 한다.

③ 신뢰도 : 하드웨어, 소프트웨어가 실패 없이 주어진 기능을 수행할 수 있는 능력이다.

④ 사용 가능도 : 사용자가 일정기간 동안 컴퓨터를 실제로 사용한 시간 비율이다.
고장과 오류가 발생해도 그 영향을 최소화하여 시스템 전체를 중단하지 않고 운영할 수 있어야 한다.


컴퓨터 시스템 4가지 구성요소

① 하드웨어
② 운영 체제(OS)
③ 응용 프로그램
④ 사용자


커널(kernel)

커널은 운영체제의 핵심으로 메모리에 상주하면서 운영체제의 다른 부분 또는 응용 프로그램 수행에 필요한 환경을 설정하는 소프트웨어이다. 응용 프로그램의 실행에 필요한 하드웨어 서비스를 제공하고 실행되는 프로세스를 스케줄링한다.




(3) 제어 서비스 향상

① 운영체제는 시스템을 확장하고 효율적으로 운영할 수 있도록 새로운 기능의 효과적인 개발을 허용해야 한다.
② 입출력장치의 동작을 관리 및 제어하거나 시스템 오류 예방 등으로 컴퓨터 자원을 여러 사용자에게 효율적으로 할당하고 관리할 수 있도록 제어 서비스를 발전해 나가야 한다.


3. 운영체제의 기능

(1) 자원 관리

1) 주기억장치 관리

① 주기억장치의 어느 부분을 사용하고, 누가 사용하는지 점검한다.
② 주기억장치에 저장할 프로세스를 결정한다.
③ 주기억장치를 할당하고 회수하는 방법을 결정한다.

2) 보조기억장치 관리

① 빈 여유 공간을 관리한다.
② 새로운 파일을 작성할 때 저장 장소를 할당한다.
③ 파일을 생성하고 삭제한다.

3) 프로세스 관리

① 프로세스와 스레드를 스케줄링한다.
② 사용자 프로세스와 시스템 프로세스를 생성하고 제거한다.
③ 프로세스를 중지하고 재수행한다.
④ 프로세스 동기화 방법을 제공한다.
⑤ 프로세스 통신 방법을 제공한다.
⑥ 교착상태를 방지하는 방법을 제공한다.

4) 주변장치(입출력장치) 관리

① 임시저장 시스템 기능을 제공한다.
② 일반 장치용 드라이버 인터페이스를 제공한다.
③ 특정 장치 드라이버를 제공한다.

5) 파일(데이터) 관리

① 파일을 생성하고 삭제한다.
② 디렉터리를 생성하고 삭제한다.
③ 보조기억장치에 있는 파일을 맵핑한다.
④ 안전한(비휘발성) 저장장치에 파일을 저장한다.








(2) 시스템 관리

1) 시스템 보호(사용자 권한 부여)

① 컴퓨터 자원에서 프로그램, 프로세스, 사용자의 접근을 제어하는 방법이다.
② 운영체제는 파일 사용 권한 부여, 데이터 암호화 등 서비스를 제공하여 데이터와 시스템을 보호한다.

2) 네트워킹(통신)

연결된 프로세서가 통신을 할 때 경로설정, 접속정책, 충돌, 보안 등의 문제를 고려한다.

3) 명령 해석기

사용자나 프로그램에서 대화형으로 입력한 명령어를 이해하고 실행하는 사용자와 운영체제의 인터페이스이다.

보충학습

운영체제 서비스

1. 부팅 서비스

① 운영체제를 메인 메모리에 적재하는 과정을 부팅(booting)이라 한다.
② 부트 로더는 부트스트랩 로더(bootstrap loader)의 줄인 말로, 하드디스크와 같은 보조기억장치에 저장된 운영체제를 메인 메모리에 적재하는 ROM에 고정시킨 소규모 프로그램이다.


2. 시스템 호출(system call)

① 시스템 호출은 실행 중인 프로그램과 운영체제 간의 인터페이스로, API(Application Programming Interface)라고도 한다.
② 사용자 프로그램은 시스템 호출을 하여 운영체제의 기능을 제공받는다.
③ 시스템 호출에는 핵심 커널 서비스와 통신, 새로운 프로세스의 생성과 실행, 하드웨어 관련 서비스 등이 있다.
④ 시스템과 상호작용하는 동작은 대개 사용자 수준 프로세서에서는 사용할 수 없으나, 시스템 호출을 하여 운영체제에 서비스를 요청할 수 있다.



02 운영체제의 유형별 특징

1. 다중프로그래밍 시스템(Multi-Programming System)

① 하나의 CPU로 여러 개의 사용자 프로그램이 마치 동시에 실행되는 것처럼 처리하는 방식으로 한 사용자가 프로그램이 입출력 장치 등을 필요로 하지 않는 동안 다른 사용자 프로그램이 그 시간에 CPU를 사용하여 효율을 극대화한다.
② 여러 작업을 준비 상태로 두기 위해 메모리에 보관해야 하고 일정 형태의 메모리 관리가 필요하고 준비 상태의 여러 작업 중 하나를 선택하기 위한 결정 방법(스케줄링)이 필요하다.


2. 시분할 시스템(Time Sharing System)

① 프로세서 스케줄링과 다중 프로그래밍을 사용하여 각 사용자에게 컴퓨터를 시간적으로 분할하여 사용할 수 있도록 한다.
② 여러 작업이 메모리에 저장되어 있는 경우 한 작업이 다른 작업의 데이터를 변경하는 것에 대한 제어가 필요하다.


3. 다중처리 시스템(Multi-Processing System)

① 마이크로프로세서 여러 개를 연결해 다중 프로세서를 만들 수 있다. 이 방법은 초고속 프로세서를 사용하지 않고도 대형 컴퓨터의 능력을 얻을 수 있다.
② 주/종 다중처리 시스템과 대칭적 구성 다중처리 시스템으로 구분된다.


운영체제의 구조

1. 단일 구조 운영체제

단일(monolithic) 구조 또는 모놀리식 커널식 커널 구조 운영체제는 초기에서 생겨난 가장 보편적인 형태이다.
운영체제의 모든 기능을 커널과 동일한 메모리 공간에 적재한 후 시스템 호출만으로 사용할 수 있는 작고 간단하면서 시스템 기능이 제한된 구조이다.
대표적인 예로는 도스와 초기 유닉스이다.

2. 마이크로 커널 구조 운영체제

커널에는 최소 기능만 포함시켜 크기를 대폭 줄이고 기타 기능은 사용자 공간으로 옮겨 사용자 영역에서 수행하는 서버 구현 방법이다.



4. 분산처리 시스템(Distributed Processing System)

① 시스템마다 운영체제와 메모리를 가지고 독립적으로 운영되며 필요할 때 통신하는 시스템이다.
② 자원 공유, 연산속도 향상, 신뢰성과 통신 등의 목적으로 여러 개의 물리적 프로세서에 연산을 분산시킬 수 있다.

일괄처리(batch)
데이터 처리에서 즉시성을 필요로 하지 않을 경우, 일정량 또는 일정 기간 데이터를 수집한 후 한꺼번에 처리하는 방식이다.

대화식(interactive)
인간의 대화와 유사한 사용자와 시스템 사이의 상호 작용을 위해 제공되는 시스템이다.

실시간(real-time)
실제로 컴퓨터에 관련된 일들이 발생하는 시간으로 실시간 조직이 되는 컴퓨터는 연산 속도가 매우 빨라서 실제로 프로세서나 통신이 진행되고 있을 때 그것에 대한 연산 결과가 곧바로 실제로 발생하고 있는 프로세서나 통신에 영향을 미칠 수 있어야 된다.

클라우드 컴퓨팅 기술
• IaaS(Infrastructure as a Service)
데이터 센터에 있는 서버, 스토리지, 네트워크 등 인프라나 자원을 가상화하여 인터넷으로 제공한다.
아마존의 EC2(Basic Cloud Computing), S3(Simple Storage Service)가 해당된다.

• PaaS(Platform as a Service)
응용 프로그램의 구축, 테스트 및 설치가 가능한 통합 개발 환경을 웹으로 제공한다.
구글, 다음, 네이버에서 제공하는 Open API가 PaaS의 일종이다.
구글 앱 엔진(Google App Engine)은 웹 서비스를 개발, 구축, 관리, 배포할 수 있는 플랫폼을 제공한다.

• SaaS(Software as a Service)
특정 소프트웨어를 인터넷으로 제공한다.
해당 소프트웨어와 관련된 클라우드에서 관리하고, 사용자는 웹 브라우저로 접속하여 소프트웨어를 사용한다. 온디맨드(on demand) 소프트웨어라 한다.



가상화(virtualization) 기술

① 가상화는 물리적 자원을 추상화하여 논리적 자원 형태로 표현하는 기술이다.
② 적용 대상에 따라 서버 가상화, 데스크톱 가상화, 스토리지 가상화, 네트워크 가상화, 소프트웨어 가상화로 구분된다.
③ 운영체제 관련된 가상화 핵심은 서버 가상화이다.

서버 가상화

① 물리적 서버 하나에 가상 서버를 여러 개 구성하는 방법이다.
② 서버 하나에서 각 응용 프로그램과 운영체제를 독립된 환경으로 사용할 수 있어 여러 응용체계가 시스템의 자원을 공유할 수 있다.

1. 베어메탈(bare-metal) 기반 가상화 : Type-1

① 호스트 운영체제를 설치 전에 가상화 솔루션을 탑재하여 가상의 CPU, 메모리, 디스크, 네트워크 카드 등을 생성한다.
② 장점 : 향상된 성능을 제공하고 실시간 운영체제를 지원할 수 있다.
③ 단점 : 운영체제 위에서 구동되지 않으므로 디바이스 드라이버, 하드웨어 플랫폼 드라이버 등을 포함해야 하고 설치와 구성이 어렵다.

(1) 전가상화(Full-Virtualization)

① 게스트 OS와 호스트 사이를 중재하는 가상 머신을 사용한다.
② 전체 가상화는 하드웨어 어플리케이션보다는 빠르지만 하이퍼바이저 중재 때문에 실제 하드웨어보다는 성능이 낮아진다.
③ 일반적인 응용 프로그램에서는 하이퍼바이저를 거치지 않고 바로 실행이 되지만 OS 레벨의 명령은 하이퍼바이저의 변환을 거쳐 하이퍼바이저를 통해 하드웨어로 전달된다.
④ Guest OS는 커널을 수정하지 않아도 된다.

(2) 반가상화(Para-Virtualization)

① 일반적인 명령은 하이퍼바이저를 거치지 않고 바로 실행이 되며, OS 명령의 경우 바이너리 전환(Binary Translation)이 발생하지 않는다.
② Guest OS의 커널이 하이퍼바이저에 맞게 수정해야 한다.


2. 호스트 기반 가상화 : Type-2

① 호스트 운영체제에서 가상 머신을 구동한다.
② 장점 : 사용자가 호스트 OS를 수정하지 않고 설치가 가능하다.
③ 단점 : 하이퍼바이저나 VMM을 사용하는 가상화에 비해 성능이 떨어질 수 있다.



01 프로세스

1. 프로세스의 정의

① 실행 중인 프로그램
② 디스크에 저장되어 있던 실행 가능한 프로그램이 메모리에 적재되어 운영체제의 제어를 받는 상태로 해당 프로그램의 사용하고 있는 메모리 영역이 존재한다.
③ 프로세스는 반드시 한 개의 PCB(Process Control Block : 프로세스 제어 블록)와 연결된다.

보충학습

프로세스

프로세스 용어는 1960년대 멀틱스(multics) 운영체제에서 처음 사용했는데, IBM 운영체제에서는 이를 작업(task)이라고 칭하기도 한다.
프로그램이 실행 중이라는 의미는 디스크에 있던 프로그램을 메모리에 적재하여 운영체제의 제어를 받는 상태가 되었다는 것이다.
① 실행 중인 프로그램
② 비동기적(asynchronous) 행위
③ 실행 중인 프로세서
④ 실행 중인 프로세서의 제어 축적
⑤ 운영체제에 들어있는 프로세스 제어 블록(PCB)과 연결
⑥ 프로세서에 할당하여 실행할 수 있는 개체
⑦ 디스패치(dispatch)가 가능한 대상



2. 프로세스의 일반적인 메모리 구조

① 프로그램은 컴파일한 코드와 초기화 전역변수, 문자열과 문자열 상수 등 정적 데이터를 포함하는 정적 개체이다.
② 프로세스는 프로그램 카운터나 레지스터처럼 현재 어떤 자원을 사용하는지 관련 정보가 들어있는 동적인 개체이다.

(1) 스택(stack)

① 데이터를 일시적으로 저장하는 영역이다.
② 지역변수, 호출한 함수의 반환 주소, 반환 값, 매개변수 등에 사용한다.
③ 함수를 호출할수록 커지고 반환하면 줄어든다.

(2) 힙(heap)

① 코드 영역과는 별도로 유지되는 자유영역이다.
② 동적으로 메모리를 할당하려고 프로그램 실행 중 시스템 호출을 사용했다가 해제하는 방법으로 활용된다.

(3) 데이터(data)

① 프로그램의 가상주소 공간이다.
② 전역변수나 정적변수를 저장하거나 할당하고 실행하기 전에 초기화한다.

(4) 코드(code)

① 실행 명령을 포함하는 메모리이거나 목적 파일에 있는 프로그램 영역이다.
② 프로그램을 시작할 때 프로세서가 디스크에서 읽어 실행하는 컴파일한 프로그램을 저장한다.

프로세스 주소 공간 구조

① 실행 스택(stack) : 호출된 프로시저(함수)의 복귀 주소와 지역 변수를 저장한다. 프로시저 호출 시 마다 증가하고 호출된 프로시저를 반환 시 마다 줄어든다.
② 실행 힙(heap) : 텍스트(코드) 영역과 별도로 유지되는 자유영역이다.
③ 데이터(정적변수) : 전역 또는 정적 변수를 저장하며, 읽고 쓰기가 가능하다.
④ 텍스트(코드) : 프로세서가 실행하는 코드를 저장한다.


02 프로세스 종류

1. 역할에 따른 분류

(1) 시스템(커널) 프로세스

① 모든 시스템 메모리와 프로세서의 명령형 액세스할 수 있는 프로세서이다.
② 프로세스 실행 순서를 제어하거나 다른 사용자 및 커널(운영체제) 영역을 침범하지 못하게 감시하고, 사용자 프로세스를 생성하는 기능을 한다.

(2) 사용자 프로세스

사용자 코드를 수행하는 프로세스이다.


2. 병행 수행 방법에 따른 분류

(1) 독립 프로세스

다른 프로세스에 영향을 주지 않거나 다른 프로세스의 영향을 받지 않으면서 수행하는 병행 프로세스이다.

(2) 협력 프로세스

다른 프로세스에 영향을 주거나 다른 프로세스에서 영향을 받는 병행 프로세스이다.




fork() 시스템 호출

코드, 데이터, 스택, 힙 등 현재 프로세스를 복사한 자식 프로세스를 만들고 리턴한다.
부모 프로세스는 fork()의 리턴 값으로 자식 프로세스의 PID를 받게 되고, 자식 프로세스는 fork() 리턴값으로 0을 받게 된다.


exec() 시스템 호출

호출하는 프로세스의 주소 공간에 새로운 응용프로그램의 코드, 데이터, 힙, 스택을 올리게 되어, 호출 프로세스의 모든 영역들이 사라진다. 하지만 호출 프로세스의 PID는 그대로 계승된다.





03 프로세스 상태

1. 프로세스 상태

① 생성 : 프로세스의 작업 공간이 메인 메모리에 생성되고 운영체제 내부에 프로세스의 실행정보를 관리하기 위한 프로세스 제어 블록(PCB)이 만들어지는 상태
② 준비 : 프로세서에게 할당되기를 기다리는 상태
③ 실행 : 프로세서를 점유하여 명령어들이 실행되는 상태
④ 대기 : 프로세서가 어떤 이벤트(입출력 종료와 같은 외부 신호)가 일어나기를 기다리는 상태
⑤ 완료 : 프로세스의 수행이 끝난 상태

2. 프로세스 상태 변환

① 준비 → 실행(디스패칭(dispatching)) : 준비 상태의 프로세스는 디스패처(dispatcher)에 의해 프로세서가 부여되면 실행상태가 된다.
② 실행 → 준비(time run out) : 어떤 프로세스가 프로세서를 계속 독점하는 방지하기 위해 운영체제는 인터럽트 클록을 두어서 지정된 시간 동안만 프로세스가 프로세서를 점유하도록 한다.
③ 실행 → 대기(block) : 실행상태의 프로세스가 지정된 시간 이전에 입출력 연산 등을 필요로 할 경우 그 프로세스는 스스로 프로세서를 양도하게 된다.
④ 대기 → 준비(wake up) : 입출력 작업이 끝났을 때, 대기 상태의 프로세스는 준비 상태로 변환한다.

프로세스의 종료

프로세스가 마지막 명령을 실행하면 종료하여 운영체제에 프로세스의 삭제를 요청한다.
일괄처리 환경에서는 인터럽트를 발생하거나 시스템 호출로 중단 명령을 전달하여 프로세스를 종료한다.
대화형 환경에서는 사용자가 로그오프(log-off)하거나 터미널을 닫으면 프로세스를 종료한다.
이외 오류로 프로세스를 종료할 수 있다.

04 프로세스 제어 블록(PCB : Process Control Block)

① 운영체제에 특정 프로세스에 대한 중요한 정보를 제공해 주는 데이터 블록이다.
② 프로세스를 생성할 때 만들어지며 주기억장치에 유지되며 운영체제 내에서 한 프로세스의 존재를 정의한다. 프로세스의 실행이 종료되면 같이 삭제된다.
③ 인터럽트 처리, 자원할당, 스케줄링 등을 수행하는 운영체제의 모든 모듈에 의해 판독되고 수정될 수 있다.

프로세스 식별자	각 프로세스의 고유 식별자
프로세스 상태	생성, 준비, 실행, 대기, 중단 등 상태 표시
프로그램 카운터	프로세스를 실행하는 다음 명령의 주소 표시
레지스터 저장 영역	누산기, 인덱스 레지스터, 스택 포인터, 범용 레지스터, 조건 코드 등의 정보
	컴퓨터 구조에 따라 수나 형태가 다르다.
	인터럽트가 발생하면 프로그램 카운터와 함께 저장한다.
프로세서 스케줄링 정보	프로세스의 우선순위, 스케줄링 큐의 포인터, 기타 스케줄 매개변수
계정 정보	프로세서 사용시간, 실제 사용시간, 사용 상한시간, 계정번호, 작업이나 프로세스 번호 등
입출력 상태 정보	특별한 입출력 요구 프로세스에 할당된 입출력장치, 열린 파일 리스트 등
메모리 관리 정보	운영체제가 사용하는 메모리 시스템에 따른 상한·하한 레지스터(경계 레지스터), 페이지 테이블이나 세그먼트 테이블 값

보충학습

프로세스 생성 시 필요한 세부 작업

1. 새로운 프로세스에 프로세스 식별자를 할당한다.
2. 프로세스의 모든 구성 요소를 포함할 수 있는 주소 공간과 프로세스 제어 블록 공간을 할당한다.
3. 프로세스 제어 블록을 초기화한다. 프로세스 상태, 프로그램 카운터 등 초기화, 자원 요청, 프로세스 제어 정보(우선순위) 등을 포함한다.
4. 해당 준비큐에 삽입한다.

05 문맥교환(Context Switching)

① 프로세서를 다른 프로세서로 전환하려면 이전의 프로세스 상태 레지스터 내용을 보관하고, 다른 프로세스의 레지스터를 적재하는 과정을 말한다.
② 프로세서가 ‘준비 → 실행’, ‘실행 → 준비’, ‘실행 → 대기’ 상태로 변환할 때 발생한다.
③ 문맥교환은 모두 과부하(overhead)가 발생한다.
④ 운영체제에서 문맥교환은 자주 발생하므로 가능한 효율적으로 구현되어야 하는데 이를 위해 스레드(thread)를 사용한다.


06 스레드(Thread)

1. 스레드의 개념

① 프로세스는 자원과 제어로 특성을 구분할 수 있는데 이 중 제어만 분리한 실행 단위를 스레드(thread)라 한다.
② 프로세스 하나는 스레드 한 개 이상으로 나눌 수 있다.
③ 스레드들은 프로세스의 직접 실행 정보를 제외한 나머지 프로세스 관리 정보를 공유한다.
   ① 프로그램 카운터(PC)와 스택 포인터(SP) 등을 비롯한 스레드 실행 환경 정보(문맥 정보), 지역 데이터, 스택을 독립적으로 갖는다.
   ② 코드, 전역 데이터, 힙을 다른 스레드와 공유한다.
④ 응용 프로그램에는 적어도 한 개 이상의 프로세스가 있고, 프로세스에는 한 개 이상의 스레드가 있다.
⑤ 같은 프로세스의 스레드들은 동일한 주소 공간을 공유한다.


2. 스레드의 이점

① 프로세스의 자원과 메모리 공유 가능 : 스레드들이 프로세스 자원 하나와 메모리를 공유하므로 응용 프로그램 하나가 동일한 주소 공간에서 스레드를 여러 개 실행하여 시스템 성능을 향상시킬 수 있다.
② 경제성 향상 : 프로세스를 생성하는 것보다 스레드를 생성하여 문맥 교환을 수행하면 오버헤드가 줄어든다.
③ 다중처리(멀티 프로세싱)로 성능과 효율 향상 : 각 스레드를 여러 프로세서에서 병렬로 실행하여 성능과 효율성을 높일 수 있다.

① 단일 스레드의 프로세스 모델에서는 프로세스의 표현을 하나의 스레드, 즉 레지스터와 스택으로 표현한다.
② 다중 스레드 프로세스 모델은 프로세스를 각각의 스레드와 공유의 레지스터, 스택으로 표현한다.
③ 프로세스의 모든 스레드들은 그 프로세스의 자원과 상태를 공유하게 되고 또한 같은 주소 공간에 존재하며 동일한 데이터에 접근한다.

스레드의 상태 변화

스레드도 프로세스처럼 준비, 실행, 대기, 종료 상태가 있다.


단일 스레드와 다중 스레드

1. 단일 스레드
프로세스 하나에 스레드 한 개를 실행하는 전통적인 방법으로 아직 스레드 용어가 탄생하기 전이라 개념이 불확실하다. 도스가 대표적인 예이다.

2. 다중 스레드
① 동일 프로세스의 스레드는 자원을 공유하므로 자원 생성과 관리의 중복성을 최소화하여 실행 능력을 향상시킬 수 있다.
② 각 스레드는 커널이 개입하지 않고도 독립적으로 실행할 수 있어 서버에서 많은 요청을 효과적으로 처리할 수 있다.
③ 프로세스보다 스레드를 생성하는 것이 더 빠르고, 동일한 프로세스에 있는 스레드 간의 교환이나 종료도 더 빠르다.
④ 프로그램을 변경하지 않고 스레드를 병렬로 처리하여 효율을 극대화할 수 있다.
⑤ 스레드별로 실행 환경 정보가 따로 있지만 서로 많이 공유하므로, 프로세스보다 동일한 프로세스의 스레드에 프로세서를 할당하거나 스레드 간의 문맥 교환이 훨씬 경제적이다.


3. 커널 레벨 스레드와 사용자 레벨 스레드

(1) 커널 레벨 스레드

① TCB(Thread Control Block)가 커널에 의해 커널 공간에 만들어지고 커널에 의해 스케줄되는 스레드이다.
② 커널 레벨 스레드는 시스템 호출을 통해서만 만들어진다.
③ 시스템 호출을 통해야 하므로 속도가 느리다.

(2) 사용자 레벨 스레드

① 스레드 라이브러리에 의해, 사용자 공간에 생성되고 관리되고 스케줄되는 스레드이다.
② 상대적으로 스레드 생성 속도가 빠르다.

(3) 멀티스레드 구현

1) 1 : 1 매핑

① 사용자 레벨 스레드 하나당 커널에 의해 스케줄 가능한 엔터티, 즉 TCB 하나를 연계시킨다.
② 사용자 레벨 스레드들이 여러 개의 CPU 코어에서 동시에 실행되므로 멀티스레드 응용프로그램에게 높은 병행성을 제공한다.
③ 사용자 레벨 스레드 중 하나가 시스템 호출 중 블록 상태가 되어도, 응용프로그램 내 다른 사용자 레벨 스레드는 여전히 스케줄링 가능하므로 응용프로그램 전체가 중단되는 일은 없다.
④ 운영체제의 비용 부담이 큰 단점이 있다.

2) n : 1 매핑

① 하나의 응용프로그램(프로세스)에 속한 모든 사용자 스레드를 하나의 커널 스레드로 매핑한다.
② 단일 코어 CPU에서 멀티스레드 응용프로그램이 실행되는 속도가 전반적으로 빠르다.
③ 스레드가 생성되고, 스케줄링되고, 동기화되는 등 모든 동작이 커널에 진입하는 과정없이 스레드 라이브러리에 의해 사용자 공간에서 이루어지기 때문이다.
④ 응용프로그램에 속한 사용자 스레드 중 하나에게만 CPU 코어가 할당되므로, 멀티스레드의 병렬성을 얻을 수 없다.
⑤ 응용프로그램 내 한 사용자 스레드가 시스템 호출을 시행하여 입출력을 기다리는 등의 이유로 블록 상태가 되면, 나머지 사용자 스레드 모두 실행시킬 수 없어 응용프로그램의 실행이 중단되는 문제점이 있다.


01 병행 프로세스

1. 병행 프로세스

① 프로세서 하나는 한 번에 프로세스 하나만 실행할 수 있다.
② 하지만 운영체제가 프로세서를 빠르게 전환하여 프로세서 시간을 나눠 마치 프로세스 여러 개를 동시에 실행하는 것처럼 보이게 하는 것을 병행 프로세서라 한다.


2. 병행 프로세스의 해결 과제

① 공유 자원을 상호 배타적으로 사용해야 한다. 프린터, 통신망 등은 한순간에 프로세스 하나만 사용해야 한다.
② 병행 프로세스 간에는 협력이나 동기화가 되어야 한다.
③ 두 프로세스 사이에서는 데이터를 교환할 수 있도록 통신이 되어야 한다.
④ 프로세스는 동시에 수행하는 다른 프로세스의 실행 속도와 관계없이 항상 일정한 실행 결과를 보장하도록 결정성(determinacy)을 확보해야 한다.
⑤ 교착상태를 해결하고 병행 프로세스들의 병렬 처리 능력을 극대화해야 한다.
⑥ 병행 프로세스를 수행하는 과정에서 발생하는 상호배제, 즉 어떤 프로세스가 작업을 실행 중일 때 나머지 프로세스는 그것과 관련된 작업을 수행할 수 없도록 보장해야 한다.


병행 프로세스의 자원 공유 해결하기 위한 조건

① 공유 자원을 배타적으로 사용한다.
② 병행 프로세스들 사이에는 동기화가 이루어져야 한다.
③ 두 프로세스 사이에는 데이터 교환을 위한 통신이 이루어져야 한다.
④ 프로세스들은 동시에 수행되는 다른 프로세스들의 실행 속도와 관계없이 항상 일정한 실행 결과가 보장되어야 한다.
⑤ 교착상태를 해결해야 하며 병행 프로세스들의 병렬 처리 능력을 극대화한다.
⑥ 병행 프로세스를 수행하는 과정에서의 상호배제를 보장한다.


02 상호배제와 동기화

1. 임계영역(Critical Section)

① 둘 이상의 프로세스들이 동시에 공유할 수 없는 자원을 임계자원이라 하며, 프로그램에서 이 자원을 이용하는 부분을 ‘임계영역’이라고 한다.
② 프로세스가 공유 데이터를 액세스 하는 동안 그 프로세스는 임계영역 내에 있다고 한다. 프로세스들이 공유 데이터를 통해서 협력할 때 어떤 프로세스가 임계영역에 들어가면 다른 프로세스들은 모든 임계영역으로의 진입이 금지되어야 한다.
③ 임계영역에는 한 순간 반드시 단 하나의 프로그램만이 허용된다.
④ 임계영역 내부에서는 반드시 빠른 속도로 수행되어야 한다.
⑤ 프로세스는 임계영역 내에서 보류(block)되어서는 안 되며 무한루프에 빠지지 않아야 한다.

2. 세마포어(Semaphore)

① 다익스트라(Dijkstra)에 의해 제안된 것으로 상호배제의 해결을 위한 동기 도구이다.
② 세마포어는 플래그로 사용되는 음이 아닌 정수값을 갖는 변수이다.
③ 세마포어의 두 가지 동작 중 두는 감소(proberen)를 나타내며 V는 증가(verhogen)를 나타낸다.

P(S) : while S ≤ 0 do no-op;
        S := S - 1;

V(S) : S := S + 1;


임계영역 문제를 해결하기 위한 조건

① 상호배제 : 프로세스 i가 임계영역을 수행 중일 때 다른 어떤 프로세스도 임계영역에 수행영역에 수행할 수 없다.
② 진행 : 임계영역을 수행하는 프로세스가 없고 여러 프로세스들이 임계영역에 들어오려고 할 때 선택된 영역에서 처리하고 있는 프로세스 중 다음에 들어가려는 프로세스가 결정은 무한정 연기할 수 없다.
③ 제한된 대기 : 한 프로세스가 임계영역에 대한 요청 후부터 임계영역에 들어가기까지의 기간 내에 다른 프로세스가 임계영역을 수행할 수 있는 횟수에는 제한이 있어야 한다.

상호배제 방법

① 데커의 알고리즘(Dekker’s algorithm)
두 프로세스가 서로 통신하기 위해 공유 메모리를 사용하여 충돌 없이 자원을 공유할 수 있도록 한다.

② TestAndSet 명령어 : 기계를 비교 하나가 다른 내용을 검사, 수정하는 특별한 하드웨어 명령어(TestAndSet)를 사용한다.

③ 세마포어(Semaphore) : 세마포어 변수 값이 true일 때 프로세스 상태를 확인하는 동기화 도구이다.

④ 모니터(Monitor) : 공유 자원의 이 접근 및 예약을 관리하는 병행 프로그래밍 구조이다.


모니터(monitor)

1. 공유 데이터, 임계영역이 코딩된 프로시저, 초기화 코드로 구성된 모듈이다. 이 모듈에는 데이터 정의와 프로시저의 독점적 제어가 모두 포함되어 있다.
2. 초기화 코드는 모니터를 생성할 때만 사용하고, 공유 데이터의 변수는 모니터 내부에 있는 프로시저로만 접근할 수 있다.
3. 프로세스들은 모니터의 프로시저를 호출, 실행하여 모니터 안에 진입한 후, 원하는 공유 데이터에 접근할 수 있다.
4. 항상 한 번에 프로세스 하나만 모니터에 진입할 수 있도록 제한하여 상호배제를 실현한다.

모니터(monitor)

① 세마포어와 비슷한 역할을 하지만 제어가 쉽다.
② 모니터 안에서 정의된 프로시저는 모니터 안에서 지역적으로 정의된 변수들과 형식적인 매개변수들만 접근할 수 있다.
③ 모니터의 지역 변수들은 지역 프로시저에 의해서만 접근된다.
④ 모니터 구조는 한 순간에 하나의 프로세스만 모니터 안에서 활동하도록 보장한다.


01 교착상태(deadlock) 정의

① 다중 프로그래밍 시스템에서 결코 일어나지 않을 사건을 기다리고 있는 프로세스를 ‘교착상태’에 빠졌다고 한다.
② 임의의 프로세스 집합에서 그 집합 내의 각각의 프로세스가 그 집합 내의 다른 프로세스에 의해서만 발생될 사건(event)을 서로 기다리는 상태를 말한다.

정상적인 프로세스의 자원 이용 순서

자원 요청 → 자원 사용 → 자원 해제






02 자원할당 그래프

① 프로세스(P1)로부터 자원(R2)으로의 연결선은 P1 → R2로 표현되며, 프로세스가 자원을 요청하는 것으로 현재 이 자원이 자기를 기다리고 있는 상태이다.
② 자원(R1)로부터 프로세스(P1)의 연결선은 R1 → P1로 표현되며, 자원이 프로세스에 할당된 것을 의미한다.
③ 자원할당 그래프에서 사이클이 존재한다면 프로세스와 자원이 교착상태에 있음을 나타냅니다.

보충학습

교착상태 필요조건

① 상호배제 : 한 번에 한 프로세스만이 그 자원을 사용할 수 있다. 만일 다른 프로세스가 그 자원을 요청한다면 요청한 프로세스는 그 자원이 해제될 때까지 기다려야 한다.
② 점유와 대기 : 적어도 하나의 자원을 보유하고 현재 다른 프로세스에 할당된 자원을 얻기 위해 기다리는 프로세스가 있어야 한다.
③ 비선점 : 자원을 강제로 빼앗을 수 없고 그 자원을 점유하고 있는 프로세스가 끝나야 그 자원이 해제될 수 있다.
④ 순환대기 : 프로세스와 자원들이 원형을 이루며, 각 프로세스는 자신에게 할당된 자원을 가지면서, 상대방 프로세스의 자원을 요청하는 상황이다.




03 교착상태 처리 기법

1. 교착상태 예방

상호배제를 제외한 세 가지의 필요조건 중 하나를 부정함으로써 교착상태의 발생 가능성을 제거한다.

(1) 점유와 대기조건의 부정

각 프로세스는 한 번에 자기가 필요한 모든 자원을 요구해야 하며 만족되지 않으면 작업의 진행을 할 수 없다.

(2) 비선점 조건의 부정

만일 어떤 자원을 갖고 있는 프로세스가 더 이상 요구가 허용되지 않으면 원래 점유한 자원을 반납하고 필요할 때 다시 그 자원이나 다른 자원을 요구해야 한다.

(3) 순환 대기 조건의 부정

모든 프로세스에 각 자원 유형별로 할당 순서를 부여한 후 순서에 따라 자원을 요구할 수 있도록 한다.


2. 교착상태의 회피

① 은행가 알고리즘은 프로세스가 어떤 자원을 요청하고 이 자원을 할당했을 때 교착상태가 발생할 수 있다면 자원을 할당하지 않는다.
② 운영체제가 현재 모든 사용자에게 그들 모두의 작업이 일정 기간 내에 끝나도록 해줄 수 있으면 현재 시스템의 상태는 ‘안정’하다고 하며 그렇지 않으면 현재 시스템의 상태가 ‘불안정’하다고 한다.
③ 안정상태는 교착상태가 아니며 교착상태는 불안정상태다. 그러나 모든 불안정 상태가 교착상태인 것은 아니다.

시스템의 상태

은행가 알고리즘은 자원의 할당 허용 여부를 결정하기 전에 미리 결정된 모든 자원의 최대 가능한 할당량을 시뮬레이션하여 안전 여부를 검사한다. 그런 다음 대기 중인 다른 모든 활동의 교착상태 가능성을 조사하여 안정 상태 여부를 검사·확인한다.
은행가 알고리즘은 프로세스가 자원을 요청할 때마다 운영체제로 실행하여, 자원 요청을 승인하는 것이 불안정한 상태에서 시스템을 계속하게 할 수 있다고 판단하면 이 요청을 연기하거나 거부하여 교착상태를 예방한다.
따라서 각 프로세스에 자원을 어떻게 할당할 것인지 정보가 필요하므로 각 프로세스가 요청하는 자원 종류의 최대 수를 알아야 한다.


3. 교착상태 탐지

① 시스템이 교착상태 예방 알고리즘을 사용하지 않는다면, 교착상태가 발생할 수 있다.
② 교착상태가 발생했는지를 파악하기 위해 시스템의 상태를 검사하는 교착상태 탐지 알고리즘을 수행한다.
③ 교착상태를 파악하기 위한 교착상태 탐지 알고리즘의 수행 시기를 결정하기는 어렵다.
④ 교착상태 탐지 알고리즘을 자주 실행하면 시스템의 성능은 떨어진다.


4. 교착상태 회복

(1) 프로세스 중지

① 교착상태 프로세스들을 모두 중지한다.
② 교착상태가 해결될 때까지 한 프로세스씩 중지한다.
③ 종료할 프로세스를 우선순위에 따라 선택한다.

(2) 자원선점

① 희생자의 선택 : 비용을 최소화하기 위해 선점의 순서를 결정한다.
② 복귀 : 프로세스를 중지하여 완전히 복귀시키고 재시작한다.
③ 기아 : 동일한 프로세스가 항상 희생자로 선택되기 쉽다.




01 스케줄러의 종류

1. 작업 스케줄러(Job Scheduler) : 장기 스케줄러

① 디스크 공간에 제출된 프로세스들을 선택하여 주기억장치로 적재한다.
② CPU 위주의 연산과 I/O 위주의 연산을 적절히 혼용하여 스케줄링한다.

2. 프로세스 스케줄러(Process Scheduler) : 단기 스케줄러

실행 준비가 되어 있는 프로세스 중에서 하나를 선택하여 CPU를 할당한다.

보충학습

스케줄링 방법별 분류

① 선점 스케줄링

㉠ 한 프로세스가 CPU를 차지하고 있을 때 다른 프로세스가 현재 프로세스를 중지시키고 다시 CPU를 차지할 수 있다.
㉡ 높은 우선순위를 가진 프로세스들이 빠른 처리를 요구하는 대화형 시스템에서 유용하다.
㉢ 인터럽트와 문맥교환에 따른 오버헤드가 발생한다.

② 비선점 스케줄링

㉠ 한 프로세스가 CPU를 할당받으면 CPU는 그 프로세스로부터 빠져 나올 수 없다.
㉡ 응답시간을 쉽게 예측할 수 있다.
㉢ 짧은 작업이 긴 작업을 기다리는 경우가 종종 발생한다.




비선점 스케줄링 종류
FCFS, SJF, HRN

선점 스케줄링 종류
RR, SRT, MLQ, MFQ

02 프로세스 스케줄링 알고리즘

1. FCFS 스케줄링 - 비선점

① 가장 간단한 기법이다.
② 준비큐에 도착한 순서에 따라 CPU를 할당받는다.

프로세스        실행시간

P1             24
P2             3
P3             3


P1                         P2   P3
0                          24   27   30

• 평균 대기시간 : (0(P1) + 24(P2) + 27(P3)) / 3 = 17
• 평균 반환시간 : (24(P1) + 27(P2) + 30(P3)) / 3 = 27


2. Round Robin 스케줄링 - 선점

① FCFS에 의해서 프로세스들이 내보내어 지며 각 프로세스는 같은 크기의 CPU 시간(Time Slice)을 할당한다.

보충학습

Time Slice의 크기

Time Slice가 너무 크면 FCFS와 동일해 진다.
Time Slice가 너무 작으면 많은 문맥교환으로 CPU 유휴시간이 증가된다.


프로세스        도착시간        실행시간

P1             0              8
P2             1              4
P3             2              9
P4             3              5

프로세스가 CPU를 사용할 수 있는 Time Slice는 4로 한다.


3. SJF 스케줄링 - 비선점

기다리고 있는 작업 중에서 수행시간이 가장 짧다고 판정된 것을 먼저 수행한다.

4. SRT 스케줄링 - 선점

SJF와 마찬가지로 새로 도착한 프로세스를 포함하여 처리가 완료되는데 가장 짧은 시간이 소요된다고 판단되는 프로세스를 먼저 수행한다.


5. 다단계 큐 알고리즘 - 선점

① 각 작업들이 서로 다른 묶음으로 분류될 수 있을 때 사용된다.

② 일반적으로 작업을 전면작업(대화형, foreground task)과 후면작업(일괄처리형, background task)으로 분류한다면 이 두 작업은 각각 요구 반응 시간이 다르므로 서로 다르게 스케줄링되어야 한다.

③ 준비상태 큐를 여러 단계 종류로 분할해둔다.

④ 기억장치의 크기나 프로세스의 형태에 따라 어느 한 큐에 지정된다. 이후 작업은 다른 큐로 이동할 수 없다.

⑤ 각 큐는 자신만의 독자적인 스케줄링 알고리즘을 갖고 있다.


6. 다단계 피드백 큐 알고리즘 - 선점

① CPU 사용시간에 따라 입출력 위주와 CPU 위주로 구분하여 특성에 따라 서로 다른 Time-Slice를 부여한다.

② 프로세스가 보다 하위단계의 큐로 옮겨 갈수록 주어진 할당시간을 점차 크게 설정한다.

③ 입출력 장치를 효과적으로 이용하기 위해 입출력 위주의 작업들에 우선권을 준다.


7. HRN 스케줄링 - 비선점

① SJF의 약점이었던 긴 작업과 짧은 작업의 지나친 불평등을 어느 정도 보완한 기법이다.

② 서비스 받을 시간이 분모에 있으므로 짧은 작업이 우선순위가 높아지는 요인이 되고 대기시간이 분자에 있으므로 긴 작업도 대기시간이 긴 경우에는 우선순위가 높아진다.


우선순위 스케줄링
(priority scheduling)

① 준비 큐에 도착한 프로세스들의 우선순위를 비교하여 높은 프로세스에 프로세서를 할당한다.
② 우선순위는 내부적 또는 외부적으로 정의할 수 있다.
③ 우선순위 스케줄링은 선점 또는 비선점이 가능하다.
④ 높은 우선순위 프로세스가 프로세서를 많이 사용하면 우선순위가 낮은 프로세스는 무한정 연기되는 기아가 발생할 수 있다.




01 메모리 관리 정책

1. 반입(Fetch) 정책

① 페이지를 메인메모리로 가져올 시기를 결정하는 정책
② 요구반입 : 실행중인 프로그램에 의해 어떤 프로그램이나 자료가 참조될 때 그것을 주기억장치로 옮긴다.
③ 예상반입 : 현 프로그램 수행 중에 앞으로 요구될 가능성이 큰 자료 또는 프로그램을 예상하여 주기억장치로 미리 옮긴다.

2. 배치(Placement) 정책

① 새로 반입된 자료나 프로그램을 주기억장치의 어디에 위치시킬 것인가를 결정하는 정책
② 최초 적합(First Fit)
㉠ 사용가능공간 리스트에서 충분히 큰 첫 번째 공간에 할당한다.
㉡ 속도가 빠를 수 있지만 공간 활용률은 떨어진다.


③ 최적 적합(Best Fit)

㉠ 충분히 큰 사용가능 공간 중 가장 작은 크기의 사용 공간을 할당한다.
㉡ 리스트가 정렬되어 있지 않다면 전체 리스트를 검색해야 한다.
㉢ 사용가능 공간 이용률은 향상될 수 있으나 속도가 느리다.


④ 최악 적합(Worst Fit) : 가장 큰 사용공간에 할당한다.


3. 교체(Replacement) 정책

새로 들어온 프로그램들이 들어갈 장소를 마련하기 위해서 어떤 프로그램이나 자료를 주기억장치로부터 제거할 것인가를 결정하는 정책으로 가상기억장치에서 이용된다.


중첩(Overlay) 기법

① 프로그램을 실행할 때 주의 주소 공간은 그 프로그램을 수행하기 전에 실제 메모리에 적재되어야 하므로, 프로그램이 자기 자신을 메모리 크기 이상으로 적재할 수는 없다.
② 한 프로세스에 할당된 메모리보다 큰 프로그램은 중첩 기법을 사용하여 해결한다.


스와핑(Swapping) 기법

① 사용자 기억장치의 현재 내용이 보조기억장치에서 기억장치로 나가고 사용자의 내용이 기억장치에 읽혀오는 것을 swap이라고 한다.
② 실행에 관한 프로세스를 보조기억장치로 보내거나 다른 프로그램을 주기억장치로 가져오는 과정으로 불러와 실행한다.


절대 적재

① 주기억장치가 여러 개의 고정된 부분으로 나누어져 있고 하나의 작업은 할당된 파티션에 의해 한번에 적재되어야 하므로 실행상황이다.
② 한 작업이 실행 준비가 되어 있어도 지정된 자신의 분할이 이미 차 있다면, 다른 분할이 이용가능하더라도 기다려야 한다.

1. 고정분할 기억장치 할당

① 다중 프로그래밍을 지원하기 위한 간단한 방법은 메모리를 여러 개의 고정된 크기로 분할(정적분할)하는 것이다.
② 각 분할은 하나의 프로세스를 포함했고 각각의 크기로 분할된 작업 큐에는 해당 크기 내의 작업들이 지정된 분할에서만 실행될 수 있다.

2. 가변분할 기억장치 할당

① 가장 합리적인 분할의 크기를 결정하여 각 작업에게 주기억장치를 할당하는 기법으로, 고정된 분할의 경계를 없애고 각 작업에 필요한 만큼의 기억장치를 할당한다.
② 가변분할 할당은 내부 단편화는 절대 발생하지 않는다.
③ 가변분할 할당은 외부 단편화 문제가 발생한다.
④ 프로세스들이 메모리에서 제거되고 새로운 프로세스가 적재될 때 사용가능 기억 공간에 일부 적재되고 나머지 공간은 작은 조각으로 나누어진다.
⑤ 이런 작은 단편화 공간을 모아서 하나의 큰 가용 공간을 만드는 것을 쓰레기수집(Garbage Collection)이라고 한다.

통합(Coalescing)

하나의 작업이 끝났을 때 그 기억장소가 비어있는 다른 기억장소와 인접되어 있는지를 검사하여 하나의 공백으로 합하는 과정이다.


재배치 적재

① 모든 작업을 하나의 큐에 넣어서 어느 분배에서도 실행 가능하도록 하기 위한 기법이다.
② 절대 적재기법보다 주기억장치의 낭비를 줄이지만 문맥제어의 부담은 커진다.

압축(Compaction)

① 메모리 내용들을 적절히 움직여서 모든 사용가능 메모리를 하나의 큰 가용공간으로 만든다.
② 압축하는 동안 시스템은 모든 일을 멈추어야 한다.
③ 메모리 테이블을 관리하고 유지해야 하므로 오버헤드가 발생한다.

01 가상메모리의 개념

1. 가상 메모리

① 프로그래머나 사용자들이 디스크의 커다란 메모리 공간을 가상메모리로 인식하고 이를 이용하여 메모리의 부족함 없이 다중 프로그래밍 환경을 실현하는 기법이다.
② 사용자와 직접 주소를 물리적으로 분리하여 주기억장치 공간을 초과한 프로세스에 주소를 지정해서 주기억장치를 제한 없이 사용할 수 있도록 한다.
③ 프로그램 전체를 동시에 실행하지 않으므로 요구한 메모리 전체가 아닌 일부만 적재해도 실행이 가능하다.
④ 중첩을 고려하여 프로그래밍할 필요가 없으므로 프로그래밍이 쉽다.
⑤ 프로세서의 이용률과 처리율을 향상시킬 수 있다.
⑥ 응답시간이나 반환시간은 향상되지 않는다.

2. 동적 주소 변환(DAT : Dynamic Address Translation) 기법

① 가상 메모리를 이용하여 메모리 공간 문제를 해결하기 위해서는 실행 중인 프로세스가 참조하는 주소와 주기억장치에서 사용하는 물리적 주소를 분리해야 한다.
② 가상주소(논리적 주소, 프로그램 주소)를 물리적 주소로 변환하는 과정을 매핑(mapping)이라 한다.
③ 동적 주소 변환(DAT, Dynamic Address Translation)은 인위적 연속성을 제공한다.
④ 인위적 연속성이란 가상 주소에서 연속적이라고 주기억장치에서도 연속적일 필요가 없다는 의미이다.
⑤ 동적 주소 변환기법은 가상메모리의 어느 부분이 현재 실제 메모리 어디에 위치하는지를 나타내는 대응표(mapping table)를 유지해야 한다.


블록을 작게 설계하면
관리할 블록의 개수가 많아진다.
블록사상표의 크기가 커진다.
페이지 fault, 교체가 자주 일어난다.
CPU 유휴시간이 길어진다.
1개의 블록이동시간은 짧다.
디스크로부터 블록이동이 자주 발생한다.
필요한 부분만 가져올 수 있다.

블록을 크게 설계하면
관리할 블록의 개수가 적어진다.
블록사상표의 크기가 작아진다.
페이지 fault, 교체가 덜 일어난다.
CPU 유휴시간이 덜 발생한다.
1개의 블록이동시간은 길다.
디스크로부터 블록이동이 덜 발생한다.
필요치 않은 부분도 함께 온다.




3. 블록(가상메모리의 이동단위) 사상

① 고정길이 블록은 페이지(page), 가변길이 블록은 세그먼트(segment)이다.
② 페이지를 이용한 기법을 페이징(paging), 세그먼트를 이용한 기법을 세그멘테이션(segmentation)이라 한다.
③ 페이지 폴트(Page Fault)는 프로세스에서 원하는 페이지가 주기억장치 내에 존재하지 않는 경우를 말하며 페이지 교체로 이어진다.

심화학습

페이징(paging)

1. 페이지 시스템의 하드웨어 구조와 원리
① 논리적 주소는 페이지 번호와 변위(offset)로 구성된다.
② 페이지 번호를 이용하여 페이지 테이블의 위치에 저장된 값을 얻는다.
③ 는 메모리의 페이지 기준 주소로, 메인 메모리의 프레임 번호이다.
④ 기준 주소에 변위를 더하면 메인 메모리의 물리적 주소가 된다.
⑤ 페이지 테이블(페이지 매핑 테이블)을 이용하여 논리적 주소를 물리적 주소로 변환한다.
⑥ 페이지 테이블은 페이지의 논리적 주소인 페이지 번호와 이에 대응하는 물리적 주소인 페이지 프레임 주소를 포함한다.
⑦ 페이지 테이블은 별도의 레지스터로 구성하거나 메인 메모리에 배치하기도 한다.


역방향 페이지 테이블
(IPT, Inverted Page Table)

페이지 테이블에서 물리 페이지 번호를 포함한 엔트리만을 유용하게 저장하여 번호를 제외한 나머지 모든 페이지 번호를 기준으로 주소 변환 테이블을 생성한다.

이와 같은 주소 변환 테이블을 이용하는 것을 역방향 페이지 테이블 방식이라 한다.
역방향 페이지 테이블 방식의 경우, 주소 변환을 위한 테이블의 크기가 가상 주소 공간의 논리적 구간만큼 크기가 일정하다.
가상 주소에서 추출한 가상 페이지 번호를 역방향 페이지 테이블의 모든 엔트리와 비교하여 하나를 발견하는 시간이 걸린다.

이런 문제점을 줄이기 위해 해시 함수(hash function)를 사용한다.

변환 색인 버퍼
(TLB, Translation Lookaside Buffer)

페이지 테이블 중 최근에 참조된 주요 변환 정보를 캐시에 저장함으로써 주소 변환을 위한 메모리 접근을 줄이기 위해 사용한다.


세그멘테이션(segmentation)

1. 세그먼테이션 개요

① 세그먼트는 프로세스 관점을 지원하여 메모리를 크기가 서로 다른 세그먼트로 나눈다.
② 프로그램을 구성하는 서브루틴, 프로시저, 함수나 모듈 등으로 세그먼트를 구성한다.
③ 각 세그먼트는 연관된 기능을 수행하는 하나의 프로그램으로 생각하며, 메모리의 연속된 위치에서 구성하되 서로 인접할 필요는 없다.
④ 프로세스에 따라 세그먼트의 크기가 다르므로 메모리를 크기가 일정한 페이지 프레임으로 나누지 않고 동적 분할 방법으로 할당한다.

보충학습

세그먼테이션 예

0~4까지 번호를 갖는 세그먼트 5개가 있다.
세그먼트2는 4300번지에서 시작하며 길이가 400바이트이다.
세그먼트2에서 250바이트를 접근할 때는 4353번지로 매핑된다.
세그먼트 3, 250위도 접근 시에는 3450번지로 매핑된다.

2. 세그먼트 공유

① 페이징 시스템은 페이지 테이블의 공유 항목을 표시해야 하지만, 세그먼트는 공유한다고 선언만 하면 된다.
② 2개 이상의 다른 프로세스의 세그먼트 테이블에 있는 항목은 동일한 메모리 주소를 지정하면 공유할 수 있다.



보충학습

페이징 기법

① 외부 단편화가 발생하지 않는다.
② 페이지의 크기를 작게 설계함으로써 내부 단편화를 줄일 수 있다.
③ 페이지 사이즈로 비용이 증가하고 수행속도가 감소한다.
④ 페이지는 프로그램에 상응하는 논리적 의미를 갖지 못한다.

보충학습

세그먼테이션 기법

① 기억장치가 할당을 최초, 최적, 최악 적합 기법을 사용하여 해결하는 동적 기억장치 할당 방법을 사용(외부적 단편화가 발생한다).
② 세그먼트 공유와 보호측면에서 세그먼트는 페이징시스템보다 수행방법이 쉽고 명확하다.





02 페이지 교체정책(Replacement Strategy)

페이지 부재가 발생하면, 운영체제가 들어올 페이지에 대한 공간을 만들어주기 위해 주기억장치로부터 제거할 페이지를 선택한다.

1. FIFO(First In First Out)

① 각 페이지가 주기억장치로 들어올 때마다 그 시간을 기억하고 있다가 페이지가 교체될 필요가 있을 때, 가장 먼저 주기억장치에 들어온 페이지와 교체시킨다.
② Belady's 모순 : 어떤 프로세스에게 할당된 페이지 프레임의 수가 증가하면 페이지 부재의 수가 감소해야 하나, 페이지 프레임의 수가 증가될 때 현실적으로 페이지 부재가 더 증가하는 경우가 있다.

2. LRU(Least Recently Used) 교체 알고리즘

① 미래의 예측을 과거의 데이터로 해결하려는 통계적 개념으로 메모리의 지역성을 이용한다.
② 최근에 가장 적게 쓰인 페이지(가장 오랫동안 사용되지 않은 페이지)를 교체한다.
③ 각 페이지들이 참조될 때마다 그때의 시간을 테이블에 기억시키는 막대한 오버헤드를 초래하게 된다.

최적 페이지 교체(OPT)

모든 페이지 알고리즘 중에서 페이지 부재 비율이 가장 낮다.
앞으로 가장 오랫동안 사용하지 않을 페이지를 교체 대상으로 선택한다.
현실적으로 구현하기는 어렵다.




보충학습

스택을 이용한 LRU 알고리즘

• 스택을 이용한 LRU 기법은 페이지 사용 시간을 이용한 간단한 기법과 달리 페이지가 참조될 때마다 페이지 번호는 스택의 top에 위치하는 것이다.
• 가장 최근에 사용한 페이지가 스택의 top에 위치하게 된다. 교체될 페이지는 bottom에 있다.
• 페이지 폴트가 발생할 경우 가장 최근에 사용된 페이지가 교체되고 지금 사용한 페이지는 top에 위치하며 나머지 페이지는 bottom 쪽으로 이동한다.

• 페이지 5 요구하면 페이지 폴트가 발생하여 가장 오래전에 사용된 1과 교체된다.
• 최근에 사용한 페이지가 5가 되므로 5는 스택의 top에, 나머지 페이지들은 bottom 쪽으로 이동한다.

3. LFU(Least Frequently Used) 교체 알고리즘

① 각 페이지마다 참조 횟수에 대한 계수기를 가지고 그 값이 가장 작은 페이지가 교체된다.
② 어떤 프로세스의 초기 단계에서 한 페이지가 많이 사용되고 이후에 사용되지 않을 경우 큰 계수를 가지고 있기 때문에 더 이상 사용되지 않아도 메모리에 남아 있다.
③ 바로 불러온 페이지가 교체될 수도 있다.

4. NUR(Not Used Recently) 교체 알고리즘

① 최근에 쓰이지 않는 페이지는 가까운 미래에도 쓰이지 않을 가능성이 많기 때문에 교체대상으로 선택된다.
② 각 페이지 당 필드가 두 개의 하드웨어 비트(참조비트, 변경비트)를 가지고 그 값으로 교체할 페이지를 선택한다.
③ 가장 사용되지 않은 P1이 교체대상이 되며, P4는 자주 사용하므로 교체되지 않는다.




2차 기회(Second Chance) 교체 알고리즘

① 기본적인 알고리즘은 FIFO 알고리즘으로 운용되나 비슷한 성능을 가지지만 고부하가 적은 알고리즘이다.
② 각 프레임의 사용여부를 나타내는 참조비트를 추가하여 페이지가 메모리에 있을 때 '1'로 설정하며, 처음 적재되었을 때 '1'로 설정한다.
③ 페이지를 교체할 시에 참조비트가 '0'인 페이지를 찾아 교체하며, 참조비트가 '1'인 프레임을 이용할 때 참조비트가 '1'인 페이지를 '0'으로 변경시킨다.
④ 그 페이지에 마지막 기록을 지고 다음에 이 검사를 대기할 때까지 교체되지 않는다.
⑤ 다음 순환 시 새로운 0을 만나면 그 프레임을 교체한다.


03 적재 정책

1. 지역성(Locality)

① 실행 중인 프로세스에 의해 나타나는 특성으로 프로세스들은 기억장치 내의 정보를 균일하게 액세스하는 것이 아니라 어느 한 순간에 특정부분을 집중적으로 참조한다.
② 지역성은 캐시 메모리, 연관 기억장치의 성립 이유가 되고 Working Set을 뒷받침한다.
③ 시간지역성은 처음에 참조된 기억장소가 가까운 미래에도 계속 참조될 가능성이 높다는 것을 의미한다.(Looping, Subroutine, Stack, Counting과 Totaling에 사용되는 변수)
④ 공간지역성은 일단 하나의 기억장소가 참조되면 그 근처의 기억장소가 계속 참조되는 경향을 의미한다.(배열, 순차적 코드 실행, 프로그래머들이 관련된 변수들을 근처에 선언하는 경향)


시간 지역성

① 특정 자원을 상대적으로 짧은 시간 안에 재사용한다는 것을 의미한다.
② 한 순간 한 지점에서 특정 메모리 위치를 참조할 때 동일한 위치에서 가까운 미래에 다시 참조할 가능성이 높다.
③ 순환(loop), 서브 프로그램, 스택, 계산이나 합계에 사용하는 변수

공간 지역성

① 프로세서가 주기억장치의 어떤 위치를 참조하면 그 근처를 이용하여도 계속 참조할 가능성이 높다는 것이다.
② 상대적으로 가까운 위치에서 데이터 요소를 사용하는 것을 의미한다.
③ 데이터 정렬과 1차원 배열의 요소, 연속적인 코드 실행
④ 배열의 범위에서 순차적 코드의 실행, 근처의 관련 변수 선언 등








2. 스래싱(Thrashing)

① 너무 자주 페이지 교체가 일어나는 경우를 말하는 것으로 어떤 프로세서가 프로그램 수행에 소요되는 시간보다 페이지 교체에 소요되는 시간이 더 큰 경우를 말한다.
② 다중 프로그래밍의 정도가 점점 더 커지면 스래싱 현상이 자주 일어나게 되고 프로세서의 이용률은 급격히 감소하게 된다.
③ 프로세서의 이용률을 높이고 스레싱을 중단하려면 다중 프로그래밍의 정도를 낮춰야만 한다.
④ 스래싱 현상을 방지하려면 각 프로세스에 필요한 프레임을 제공할 수 있어야 한다.
⑤ 지역성을 이용하여 현재 지역 크기보다 적은 페이지 프레임을 할당하면 페이지 부재가 발생하는 원인이 될 수 있다.
⑥ 프로세서가 요구하는 최소한의 수보다 페이지 프레임의 수가 적으면 적을수록 페이지 부재율이 증가한다. 그러면 더 많은 페이지 부재가 일어나고, 프로세서의 효율은 떨어진다.




① 빈 프레임이 있을 때 : 페이지 부재 비율이 상한 값을 초과하면 현재 프로세스에 프레임을 할당한다. 페이지 부재 비율이 하한 값 이하로 떨어지면 현재 프로세스의 프레임을 제거한다.

② 빈 프레임이 없을 때 : 페이지 부재 비율이 상한 값을 초과하면 희생시킬 프로세스를 선택하고, 그 프로세스의 실행을 일시 중단한다. 현재 프로세스의 페이지 부재 비율이 하한 값 이하로 떨어지면 현재 프로세스의 프레임을 제거한다.

③ 페이지 부재 비율이 상한 값을 넘으면 프로세스에 다른 프레임을 더 할당하고, 하한 값보다 낮으면 프레임을 회수한다.

3. 페이지 부재 비율(PFF, Page Fault Frequency)

① 스래싱을 예방하는 직접적인 액세스 방법으로, 페이지 환경에서 프로세스의 실행을 측정하는 기준이 된다.

② 페이지 부재 비율이 높다는 것은 프로세스에 더 많은 프레임이 필요하다는 의미이고, 페이지 부재 비율이 낮다는 것은 프로세스에 프레임이 너무 많다는 의미이다.

③ 페이지 부재 비율이 증가하고 유효 프레임이 없으면 어떤 프로세스를 골라서 중지해야 한다.

④ 프로세스를 중지하면 페이지 부재 비율이 높은 프로세스들에 프로세스에 할당된 프레임을 분배한다.

⑤ 스래싱은 페이지 부재에서 발생하므로 페이지 부재 비율을 조절하는 것이 필요하다.



01 탐색시간(Seek Time) 최적화 기법 – 트랙을 찾는 데 걸리는 시간

1. FCFS(First Come First Service) 스케줄링

① 가장 간단한 형태로, 먼저 도착한 요청이 우선적으로 서비스 받는다.
② 근본적인 공평성이 보장되고 프로그램밍이 편리하다.
③ 헤드 이동거리에 비해 전체적인 처리율이 낮다.

보충학습

FCFS(First Come First Service) 스케줄링의 헤드 이동 순서
대기큐 : 98, 183, 37, 122, 14, 124, 65, 67
현재 헤드 위치 : 53

53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67

전체 헤드 이동거리는 640


2. SSTF(Shortest Seek Time First) 스케줄링

① 탐색거리가 가장 짧은 요청이 먼저 서비스를 받는 기법으로 현재 헤드 위치에서 최소의 탐색시간을 요하는 디스크 요청을 고르며 먼저 처리해 나간다.
② 안쪽이나 바깥쪽의 트랙이 가운데 있는 트랙보다 훨씬 서비스를 덜 받는 기아현상이 발생할 수 있다.
③ FCFS보다 처리량이 많고 평균 응답시간이 짧으나 응답시간의 편차가 발생한다.


④ 일괄처리 시스템에 유용하고 응답시간의 편차가 크기 때문에 대화형 시스템에는 부적합하다.

보충학습

SSTF(Shortest Seek Time First) 스케줄링의 헤드 이동 순서

대기큐 : 98, 183, 37, 122, 14, 124, 65, 67
현재 헤드 위치 : 53

53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183

전체 헤드 이동거리는 236


3. SCAN 스케줄링(엘리베이터 알고리즘)

① 요청 큐의 동적 특성을 반영하여, 요청된 트랙으로 입출력 헤드가 디스크의 한 끝에서 다른 끝으로, 또한 다른 한쪽 끝에 도달했을 때는 역방향으로 이동하면서 요청된 트랙에 대한 처리를 해나간다.
② 헤드는 디스크의 한 끝과 끝 사이를 계속해서 왕복한다.
③ SSTF에서 발생하는 차별대우를 많이 없애고 낮은 편차를 가지므로 대화형 작업에 적합하다.

보충학습

SCAN 스케줄링의 헤드 이동 순서

대기큐 : 98, 183, 37, 122, 14, 124, 65, 67
현재 헤드 위치 : 53

53 → 37 → 14 → 0 → 65 → 67 → 98 → 122 → 124 → 183

전체 헤드 이동거리는 236




4. C-SCAN(Circular-SCAN) 스케줄링

① SCAN에서의 불공평한 대기시간을 좀 더 균등하게 하려 변형을 가한 스케줄링이다.
② 한쪽 방향으로 헤드를 이동해 가면서 요청을 처리하지만 한쪽 끝에 도착하면 반대 방향으로 헤드를 처리하지 않고 이동한다.
③ 헤드는 항상 바깥쪽 실린더에서 안쪽 실린더로 이동하면서 가장 짧은 탐색 시간을 갖는 요청을 서비스한다.
④ 큐 내의 트랙을 처리하고 있는 도중 새롭게 요청된 트랙은 다음 번 이동 때 처리한다.

보충학습

C-SCAN(Circular-SCAN) 스케줄링의 헤드 이동 순서

대기큐 : 98, 183, 37, 122, 14, 124, 65, 67
현재 헤드 위치 : 53

53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 → 0 → 14 → 37

전체 헤드 이동거리는 382

N-Step SCAN 스케줄링

헤드가 특정 방향으로 진행이 시작될 때 대기중인 입출력 요구를 서비스한다는 것만 제외하면 SCAN과 같다. 진행 도중 도착한 요구는 한데 모아 다음 번에 대량으로 진행해 최적의 서비스를 위해 정렬된다. 각각의 진행에서 먼저 N개의 요구가 서비스된다.


5. LOOK 스케줄링

① SCAN이나 C-SCAN은 헤드를 디스크의 끝에서 끝으로 이동한다는 원리지만 실제로 이런 방식으로는 구현되지 않는다.
② 헤드는 한 방향으로 요청에 따르는 거리만큼 이동하고, 현재 방향에서 더 이상의 요청이 없다면 헤드의 이동 방향이 바뀌는 방식을 사용한다.
③ SCAN은 LOOK, C-SCAN은 C-LOOK이라 한다.



02 회전지연시간(Rotational Delay Time) 최적화 기법 - 섹터를 찾는 데 걸리는 시간

1. 예상번호 기법

헤드는 C-SCAN처럼 움직이는데 예외로 모든 실린더는 그 실린더에 요청과 상관없이 전체 트랙이 한 바퀴 회전할 동안에 서비스한다.

2. SLTF 스케줄링(섹터 큐잉 : Sector Queueing)

① 여러 섹터에 대한 많은 요구들 중 가장 짧은 회전지연시간을 갖는 요청에게 먼저 서비스한다.
② 고정헤드 디스크, 자기 드럼을 위한 스케줄링 기법이다.








01 파일

파일 시스템은 운영체제의 가장 일반적인 서비스로 정보 저장의 논리적인 관점과
저장 장치의 물리적인 특성을 고려하여 논리적 저장 단위, 파일을 정의하고 실제적인
메모리 장소에 저장시킨다.

1. 파일의 구성요소

(1) 항목(field)
① 바이트의 모임으로 데이터 파일을 구성하는 기본적인 구성요소이다.
② 의미있는 데이터의 가장 작은 단위이다.

(2) 레코드(record)
① 파일을 구성하는 요소는 레코드이며, 레코드를 구성하는 요소는 항목이다.
② 레코드는 고정 길이 또는 가변 길이로 구성되며 필요에 따라 파일을 구성하는
   레코드들은 몇 개가 모여 하나의 블록을 만든다.


ISAM(Indexed Sequential
Access Method)

레코드를 순서대로 처리할 수도 있고
특정 항목을 인덱스로 하여 순서에 관계없이
개별 레코드를 처리할 수도 있다.
인덱스 영역, 데이터 영역, 오버플로우
영역으로 나누어 관리한다.
레코드를 새로 삽입하면 데이터 영역에
기록되고 그 레코드의 위치 정보는 인덱스에 기록된다.

VSAM
(Virtual Storage Access Method)

동적 인덱스 방법을 이용한 인덱스된
순차 파일의 구성 방식으로 IBM이 지원하는 파일이다.


2. 파일의 구조에 따른 분류

파일을 구성하는 레코드들이 보조기억장치에 배치되는 방식을 말한다.

(1) 히프 파일
다음 레코드는 실제로 현재의 레코드 바로 뒤에 저장되어 있다.

(2) 기순차 파일
① 다음 레코드는 삽입할 위치를 찾은 후 저장한다.
② 삽입할 공간을 확보하기 위해 레코드들의 이동이 발생한다.

(3) 인덱스 파일
① 레코드는 각 레코드의 키에 따라서 논리적 순서대로 배열되어 있다.
② 시스템은 레코드의 실제 주소가 저장된 인덱스(index)를 관리한다.




(4) 직접 파일

① 레코드가 물리적 주소를 통해 직접 액세스된다.
② 파일 내의 레코드들이 어떤 일정한 순서를 유지할 필요가 없다.

심화학습

1. 히프 파일(비순서 파일)
① 일반적으로 레코드들이 삽입된 순서대로 파일에 저장된다.
② 레코드들의 순서는 없다.
③ 원하는 레코드를 찾기 위해서는 모든 레코드들을 순차적으로 접근해야 한다.

2. 순차 파일(순차 파일)
① 레코드들이 하나 이상의 필드 값(탐색키)에 따라 순서대로 저장된다.
② 탐색키는 순차 파일을 정렬하는데 사용되는 필드이다.
③ 원하는 레코드를 검색하는 경우에는 인덱스(Index)를 이용하여 순차탐색보다 탐색 시간을 줄일 수 있다.
④ 삽입 연산은 삽입하려는 레코드의 순서를 고려해야 하므로 시간이 많이 걸릴 수 있다.

3. 인덱스 파일
① 인덱스 파일을 통해서 인덱스의 레코드를 접근할 수 있는 정보를 얻는다.
② 인덱스는 데이터 파일과는 별도의 파일에 저장된다.
③ 인덱스는 파일 내의 특정 레코드들을 빠르게 찾을 수 있도록 도와주는 데이터 구조이며 인덱스를 통해 검색을 수행하면 증가시간이 향상된다.



02 디렉터리 시스템

• 운영체제는 디스크같은 보조기억장치에 저장된 파일을 관리하기 위해 디렉터리라는 논리적 저장장치를 유지하고 관리한다.
• 한 개의 파일 디렉터리 항목은 물리적 속성을 제공하기 위해 장치 디렉터리에 대한 포인터를 두거나 그 정보를 복사하여 가질 수도 있다.

1. 디렉터리 구조

(1) 1단계 디렉터리

① 가장 간단한 디렉터리 구조로 모든 파일이 같은 디렉터리에 있어 단순하다.
② 모든 파일이 각각 고유한 이름을 가져야 한다.

(2) 2단계 디렉터리

① 각 사용자에 따른 디렉터리를 만들어 사용하도록 한다.
② 각 사용자는 자신의 사용자 파일 디렉터리(UFD : User File Directory)를 갖고, 각 UFD는 유사한 구조를 가지면서 오직 한 사용자의 파일만 나타낸다.

2단계 디렉터리

장치 디렉터리
각 실제 장치에 저장되고 이러한 장치에 있는 모든 파일들을 나타낸다.
파일의 위치, 파일의 크기와 할당 과정 등을 나타낸다.

파일 디렉터리
모든 파일들의 논리적 구성으로 이름, 파일 유형, 소유자, 계정정보 등을 나타낸다.

(3) 트리구조 디렉터리

하나의 루트 디렉터리를 가지고 있으며 시스템 내의 모든 파일은 유일한 경로명을 갖는다.

비순환 그래프 디렉터리

트리구조 디렉터리에서는 파일 또는 디렉터리의 공유를 할 수 없다. 비순환 그래프는 디렉터리들이 공유 서로 디렉터리와 파일을 갖도록 한다. 같은 파일이나 서로 디렉터리는 2개의 서로 다른 디렉터리에 있을 수 있다.
그래프를 검색하여 어떤 파일에 대한 더 이상 존재하지 않은 삭제를 설정하는 알고리즘이 비교적 단순하다.

일반 그래프 디렉터리

비순환 그래프 구조는 순환이 없다. 트리구조의 디렉터리에 링크를 추가하여 순환을 허용한 단순한 그래프 구조를 생성한다.



03 디스크 할당 방법

1. 디스크의 빈 공간 관리

(1) 비트 벡터

① 빈 공간 리스트는 비트맵(bit map) 또는 비트벡터(bit vector)로 구현될 수 있다.
② 블록이 비어있으면 0, 블록이 할당되어 있으면 1이다.

(2) 연결 리스트

① 모든 빈 디스크 블록들을 함께 연결시킨다.
② 첫 번째 빈 블록 안에 다음의 빈 디스크 블록의 포인터를 갖고 있다.


2. 연속 할당(Contiguous Allocation)

① 파일들이 디스크의 연속적인 주소들의 집합에 할당되는 방식이다.
② 파일에 접근할 때 필요한 디스크 탐색의 횟수는 최소화할 수 있다.
③ 새로운 파일을 위한 빈 공간을 찾는 것은 어렵다.
④ 전체 디스크 공간이 요구량을 만족하여도, 연속된 공간이 아니면 외부 단편화가 발생한다.
⑤ 주기적인 압축이 필요하다.

3. 연결 할당(Linked Allocation)

① 각 파일들이 디스크 블록들의 리스트에 연결되는데, 디스크 블록들은 디스크 전체에 분산되어 있다.
② 디렉터리는 파일의 첫 번째와 마지막 블록의 포인터를 가지고 있다.
③ 외부 단편화가 발생하지 않는다.
④ 직접 액세스 기능을 지원할 수 없다.
⑤ 포인터를 위한 기억공간이 필요하다.


4. 인덱스 할당

① 연결 할당은 연속 할당의 외부 단편화를 해결했으나 직접 액세스를 지원할 수 없고 블록들의 포인터가 디스크 전체에 분산되어 있다.
② 인덱스 할당은 모든 포인터들을 하나의 장소, 즉 인덱스 블록으로 관리하여 직접 액세스를 지원한다.




1. 유닉스의 특징

① 대화식 시스템
② 다중사용자 시스템
③ 다중 작업용 시스템
④ 높은 이식성과 확장성 제공
⑤ 계층적 트리 파일 시스템

2. 유닉스의 구성요소

① 커널 : 프로세스 관리, 메모리 관리, 파일 시스템 관리, 장치 관리 등 컴퓨터의 모든 자원을 관리하고 제어하는 기능을 수행한다.
② 셸 : 사용자와 커널 사이의 중간자 역할을 담당하는 프로그램으로 사용자가 입력한 명령을 해석하여 커널에 넘겨준다.
   본 셸(bourne shell), C 셸, 콘 셸(korn shell), 배시 셸(bash shell) 등이 다양하다.

3. 유닉스의 파일 시스템

유닉스는 디렉터리 파일, 일반 파일, 장치 파일이 있다.
이 모든 파일은 하나의 트리 구조를 가지며 계층적으로 관리한다.

4. 디스크 블록 구조

① 부트 블록 : 파일 시스템에 유닉스 커널을 적재시키는 프로그램을 포함한다.
② 슈퍼 블록 : 파일 시스템을 관리하는 정보를 저장한다.
③ I-노드 블록 : 파일 관리에 필요한 정보를 저장한다.
④ 데이터 블록 : 일반 파일이나 디렉터리 파일의 내용이 들어 있다.


01 데이터 통신 시스템의 구성 요소

• DTE(Data Terminal Equipment) : 데이터 중단 장치 - 터미널, 컴퓨터 등을 총칭
• DCE(Data Circuit-End Equipment) : 데이터 회선 종단 장치, 신호변환장치

데이터 통신 시스템

1. 단말장치(terminal)

① 통신 회선을 통해 컴퓨터 시스템에 접속되어 여러 가지 형식의 데이터를 입출력하는 장치 또는 장치의 집합이다.
② 입/출력 기능과 전송 제어 기능이 있다.

2. 데이터 전송장치

(1) 신호변환장치

정보 기기에서 사용하는 부호를 전송로에 전송되는 신호에 적합하도록 변환하며 수신 측에서는 전송된 신호를 기기에 적합하도록 복원하는 장치이다.
