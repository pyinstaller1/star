


취약한 인증
사용자 본인인지 확인하는 인증 과정이 부적절
취약한 패스워드 등으로 발생

부적절한 인가
인증된 사용자가 어떤 자원을 사용할 권한이 있는지 확인 X
허용되지 않은 자원에 접근 가능




리버스 텔넷
웹 서버 권한 획득 후 원격 쉘 획득
서버에서 역으로 텔넷처럼 명령어 입력
대응책: 내외부 방향 방화벽



CSRF(Cross Site Request Forgery)
로그인된 사용자가 자신도 모르게 공격 수행
로그인 세션 인증 악용 => 수정, 삭제, 등록, 송금
게시물 열람 => CSRF 스크립트 실행

CSRF는 악성 스크립트를 서버에 요청
(XSS는 악성 스크립트가 클라이언트에서 실행)
웹사이트가 사용자의 웹 브라우저를 신뢰하는 것을 이용
대응책 : 요청 내에 세션, 사용자별 토큰 추가
             => 정상 요청인지 서버가 판별



디렉터리 리스팅 : 서버의 디렉터리 내 파일 목록 노출
               중요 파일 노출
백업 파일 : 삭제하지 않은 백업 파일 노출
             내부 로직, DB 접속 정보
주석 관리 미흡 : 웹 페이지의 주석이 사용자에게 노출





버퍼 오버플로
버퍼에 할당된 크기보다 큰 데이터를 입력
인접 메모리 영역 침범
RET(Return Address) 덮어쓰기
프로그램 흐름을 변경할 수 있음

스택 버퍼 오버플로
스택 영역을 넘침 (지역변수, 함수)
RET 덮어쓰기
원하는 코드의 주소로 흐름 변경
셸코드 실행 가능

SetUID
실행 시 파일 소유자의 권한으로 실행
관리자 소유 SetUID 프로그램 공격 시 관리자 권한 획득 가능

방어
스택가드: RET 앞에 Canary 저장
           함수 종료 시 Canary 변조 여부 검사
           변조되면 실행 거부
스택쉴드 : RET를 별도 영역에 저장 (Global RET 스택)
            종료 시 RET 비교 => 다르면 프로그램 종료
ASLR : 스택, 라이브러리의 주소를 난수화
        공격자가 주소 추측 어려움
Non-Executable 스택 : 스택에서 코드 실행 X
취약 함수를 피한다. (strcpy, strcat)














포맷 스트링 공격
printf() 에서 사용자 입력을 %포맷 문자열로 처리
% 악용 => RET 위치 찾기
데이터의 불명확한 정의


레이스 컨디션 공격
프로그램의 임시 파일 공격 (root 소유자, SetUID 사용)
심볼릭 링크를 미리 생성
프로그램이 원래 링크 대신 심볼릭 링크의 임시 파일에 쓴다.
